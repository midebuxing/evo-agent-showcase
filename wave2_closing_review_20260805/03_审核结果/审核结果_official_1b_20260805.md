### 归因：**错在方向上，必须修**

记录 §四第 3 条与尾巴 2 写：row 1 翻 0 是"本池无 fsp<0.75 的片段…**这是池相关不是结构性质**：

**实测是反的——`fsp < 0.75` 结构上不可达，换任何池都不会翻。**

推导（三步都可查）：

1. `_compute_fsp_true = clip(1.20 − 0.30·max_severity − 0.10·age_norm, 0, 2)`
   （`generator_sampling.py:112-119`）；
2. `age_norm = clip(age_years/50, 0, 1)`（`generator_base.py:373-375`）⇒ ≤ 1；
   `max_severity` 取自 `candidate_scores` 的 max，其分量要么是 sigmoid 输出（(0,1)，
   `generator_defect.py:28-59`）、要么是 placeholder `0.3+0.6·rand`（≤0.9，`generator.py:900-901`）
   ⇒ < 1；
3. ⇒ fsp > 1.20 − 0.30 − 0.10 = **0.80** > **0.75** = `_RISK_BUILDING_SAFETY_FSP_THRESHOLD`
   （`generator.py:2584`）。

实测佐证（同池 50 栋）：片段级 fsp **n=342，min 0.8308 / max 1.1084，<0.75 者 0 条**；
楼级 fsp **min 0.8308 / max 0.9633，<0.75 者 0 条**。

**三条后果**：

- (a) 记录 §四第 3 条与 §六尾巴 2 的"池相关"表述**作废**；
- (b) 这条错误预期**已经写进随单落库的脚本注释**——
  `verify_rng_isolation_pairing.py:121-122`「`sidecar.entries` … 红了是**通道发作不是锚坏**」
  在当前 fsp 公式下永远不会发生。留着它，下一个人会去"找一个含 fsp<0.75 片段的池"，找不到；
- (c) allowed-change 里 `buildings.derived_outcomes` 与 `repair_assessment.writeback`
  不是"本池恰好没变"，是**结构上不可能变**（它们的唯一 fsp 通道是 row 1）。
  脚本 `[注意]` 节要求"要解释"，正确的解释是这一条，不是记录写的那一条。

**顺带查实的新债（1b 之前就有，1b 未引入也未修）**：0.75 这个阈值是 **spec 锚定值**
（`generator.py:2578-2584` 注释引 spec 06 §11 row 1 ＋ spec 11 inventory §5.1
`RISK_BUILDING_SAFETY_EMERGENCY_V1 thresholds={... fsp:0.75 ...}`），

## 一、结论（先行）

**不违背。** 形态 C 不是对 §3.2 的绕开或违背，而是落在 spec 自己划给「行政一次性事件」的 §3.1 形状里；对行政事件打聚合标记才是错用（把它虚报成「碎片读数的派生聚合」）。三条主判据见 §五，一条承重边界见 §四5。

## 二、spec 原文核查：§3.2 的射程只罩「部位进度槽的派生聚合读数」

1. **§1 根因段（草案 L20-22）**：「任命/提名/知会/递件这类**行政一次性事件**在现实里就是楼级事实，按 fragment 独立抽 4 次本身是建模走样；而**部位工程进度**按部位采样是对的，错在楼级读数没有定义。」——spec 开篇就把两类存在明确分家：行政事件＝楼级原生；部位进度＝碎片原生＋楼级需**派生**。
2. **§3.1（L37-52）**：行政一次性槽 → W0 楼级采样，一栋一抽落一条楼级行。通篇**没有任何聚合标记要求**。
3. **§3.2（L77-95）**：标题即「**部位进度槽** → 保 fragment 采样 + 检索层**聚合派生**楼级读数」；表格只列 4 个部位进度槽；其载体与作用域规则的小节标题明写「**聚合事实**的载体与作用域规则（一审修正④⑤）」（L89）——标记（`{"aggregation":"building"}`）与碎片作用域排除（L92-95）这两条规则按字面只约束**派生聚合事实**，不约束楼级原生事实。
4. **二审约束性解释（状态行 L3）**：「『不动闭包验证器』按二审的约束性解释＝不改判定权与真假规则、**允许 §92-95 授权的聚合事实作用域过滤**」——spec 授权的验证器侧改动只有「聚合事实」那一行过滤。形态 C 对 validator **零改动**，连这唯一的授权面都不碰。
5. **射程外声明（诚实边界）**：粒度语义 spec 的管制对象是流程布尔槽；期限 duration 数值事实本不在其字面射程内。故本复核回答的是「设计意图」层面的论证——而意图层面同样不违背（§三）。

## 三、设计意图还原：标记的语义是「派生读数不得冒充部位原值」，不是「楼级事实碎片不可见」

- **validator docstring（`closure/validator.py:1403-1407`）原文**：「楼级聚合读数（qualifiers.aggregation=='building'，spec 草案·流程槽粒度语义 §3.2）**排除**——部位承载卡必须读本部位原值，聚合读数只暴露给楼级作用域；**普通楼级事实（无该标记）照旧可见**。」
  ——排除的理由句（「部位承载卡必须读本部位原值」）与放行句（「普通楼级事实照旧可见」）写在**同一段**：设计明确保留了一个「无标记楼级事实、双作用域可见」的合法类。形态 C 正是这个类。
- **代码行为（`validator.py:1410-1414`）**：`_fragment_index` 收录条件是 `_fact_frag(f) in (None, fid)` **且** `aggregation != "building"`。楼级事实（无 fragment 归属）默认进碎片索引，唯一变量就是那个标记——E1 墙①的对照臂（A3/C2 带标记 0 条脱离 vs A4/C3 去标记立刻 8/8 satisfied，唯一差异＝标记）与代码逐行一致。
- 所以 §3.2 的意图是**定向防御一个具体危险**：派生聚合读数若进碎片作用域，部位承载卡会拿「全楼汇总」当「本部位原值」——那是拿别人的读数冒充自己的证据。行政事件事实**不存在可被冒充的部位原值**（它根本没有碎片级本体），防御对象与其无关。

## 四、「聚合读数」与「楼级原生行政事件」是否同类——不同类，且世界侧有四个不打标记的先例

**不同类，逐维对照：**

| 维度 | 聚合读数（§3.2） | 楼级原生行政事件（§3.1／形态 C） |
|---|---|---|
| 来源 | 检索/生成侧从碎片读数**派生**（all_true/any_true） | 事件本身，楼级采样一次 |
| 认识论身份 | 多个部位量测的汇总 | 整栋一次的行政动作（任命/递件/呈交） |
| 碎片作用域绑定的危险 | 冒充部位原值（真实） | 无部位原值可冒充（不存在） |
| 标记语义 | 需要标记自证「我是派生读数」 | 打标记＝虚报「我是碎片读数的聚合」，是错用 |

**世界侧不打标记的楼级原生事实先例（四个，含一个同业务域）：**

1. **§3.1 行政槽发射分支（`worldgen/sidecar.py:505-535`）**：`granularity=="building"` 槽一栋一抽，`qualifiers` 只带 `carrier_domain`＋`granularity:"building"`，**无 aggregation 标记**，`refs=[building_world_id]`（即 `fragment_id=None`）。注册表（`registry.py:3098-3145`）13 个行政槽全标 `granularity: "building"`（注释直引本 spec「行政一次性事件楼级采样」）。**这就是 spec §3.1 的落地形状本身**——形态 C 与之同构。
2. **reporting 三根轴行（`sidecar.py:470-503`）**：注释原文「语义是**楼级**（呈交/送达/签署是整栋楼流程的事件，不随 fragment 变），故只发楼级行、不逐 fragment 展开」，qualifiers 带 `granularity:"building"`、**无 aggregation 标记**。与期限锚**同一业务域**（§2.1.3 呈交类行政事件），是最贴身的先例。
3. **检索层两处同形状先例**（不在 W0 世界侧，属同一事实供应链）：报告字段组契约行（`fact_retriever.py:1283-1284`）注释明写「无 aggregation 标记（章节契约在 fragment 作用域也须可见——identify 卡 fragment-scoped，带 aggregation=building 会被作用域排除）」；类目成员楼级广播行（`fact_retriever.py:1361-1367`）＝「carrier_type=building、**不带 aggregation 标记**、不带 fragment 戳……须对所有 fragment 作用域可见」。——「楼级＋无标记＋碎片可见」已是被多次显式采用的设计形状。
4. **意图声明（`sidecar.py:1148-1149`，`_emit_scope_declaration_rows` docstring）**：「楼级主行（granularity=building，**勿打 aggregation 标记——两作用域皆可见是本意**）」。

5. **⚠️ 对照先例＝风险边界（必须给实施卡点破）**：同一函数体（`sidecar.py:1181-1184`）后来**确实补打了**标记，原因注释：「无限定符触发器在 fragment 作用域撞 19 条楼级行判歧义」。这划出了「何时才需要标记」的边界：**同楼同槽多行＋无限定符消费者**。形态 C 的碰撞策略（决议一.2：同（楼,锚）唯一、0 条→诚实 miss、>1 条→报错禁 `facts[0]`）在结构上恰好排除了这一歧义成因——**故逐（楼,锚）唯一性断言不只是碰撞策略，是形态 C 合法性的承重前置**；建议实施卡把「发射后碎片作用域消费者无歧义」写进验收断言。另注意该 docstring 与代码现状不一致（docstring 说不打、代码打了），引用时以「docstring 记意图、代码记多行槽的例外」理解，别拿它当单向证据。

**附带佐证（不作为主论据）**：聚合标记不是单纯的「作用域过滤位」，闭包层还有绑定它的消费语义——S3 甲′待裁守卫（`obligation_deriver.py:2485` 起）专盯带标记的读数：「未登记绑定不得依赖 `aggregation=building` 读数产实判」，防的正是「派生读数未经裁定就产实判」。期限绑定走 `evaluate_deadline` 而非精确合同路径，未必触发；但这说明标记在下游绑定的语义比「一行过滤」多，给非聚合事实打标记是把它拖进不针对它的守卫射程——进一步支持「打标记才是风险侧」。

## 结论

**不违背。**

形态 C 属 spec §3.1「行政一次性事件＝楼级原生事实」的既定形状：`aggregation` 标记的设计语义是「派生聚合读数防止冒充部位原值」，行政事件没有部位原值可冒充，打标记才是错用；validator 对「无标记楼级事实」明文照旧放行，形态 C 零改动落在设计内路径；世界侧 §3.1 行政槽与 reporting 轴积行均为不打标记的楼级原生先例。唯一承重条件：逐（楼,锚）唯一性断言必须落地（多行＋无限定符消费者才是需要标记的场景，`scope.component.inspection_included` 后补标记即此例）。

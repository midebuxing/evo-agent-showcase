## 一、阶段声明：这是**实验室阶段**的研究管线，不是产品

**你评审的对象是一条研究管线的可信度与准备度，不是一个待上线的系统。**

- 没有生产流量、没有外部用户、没有发布窗口。**不需要**灰度 / 金丝雀发布 / 回滚编排 /
  多租户隔离 / SLA / 运维手册这一类部署语义——历史上有一轮外部设计因为没说清阶段，
  产出了约 600 行实验室阶段无场景的部署代码，全被删掉。请主动跳过这些维度。
- 「批」＝一次离线跑批（当前规模 30 栋楼），产物落在本机目录里，可以随时重跑、随时删。
- 「换池」＝把世界生成的随机种子池换一版重新生成全部合成楼宇数据，是本管线里
  **成本最高、最不可逆的一次操作**——换池之后，此前所有锚在旧池上的数字、真值、
  断言、验收表，都要重新对账或作废。**本次审核的核心就是「换池前的准备够不够」。**

## 二、项目原则（先讲原则，再看材料——凡与原则冲突的方案一律作废重来）

这些是本项目长期累积的硬约束，评审时请把它们当成给定条件，并在你的结论里
**显式标注**你的每条建议与哪几条原则相关、是否相容：

1. **判定权红线**：合规判定（`allow_stop` / `closure_status` / `satisfaction_status`）
   只由确定性闭包验证器产出，唯一权威；大模型 / 编排层 / 策略层一律不得改写。
   `allow_stop = open==0 且 blocked==0 且 schema/forbidden 校验过`。
2. **blind 红线**：agent 运行时绝不看参考真值（W2）。真值只服务旁路阅卷，
   agent 运行时不得引入阅卷模块。喂真值给 agent ＝ 抄答案。
3. **「判合规」不是本系统的活**——最终判决是使用本系统的专业人员做的。
   系统的验收标准是：**无故 unknown 归零；有故 unknown 必须说清为什么；适用条款不漏。**
   请不要用「判定准确率」这一类指标框架来评价本管线。
4. **不发明规范**：法规原文没有的数值/时限/映射，一律不许为了让机制跑通而发明。
   宁可诚实落「不知道」，也不许造出一条看起来确定的判定。
   （本项目 2026-07-27 出过一次事故：期限绑定的早返回不看时间锚点，把 15 个不同锚点
   塌缩成同一条事实，**凭空判出 135 条期限合规结论**。当日修复动作的实质不是
   「让期限变得可判」，而是「把 135 条捏造判定换成诚实的说不知道」。这是本波次
   期限锚案全部设计取舍的背景。）
5. **法规效力只认中文正文**：规则卡里的英文引文与规范化文本是**译文、无效力证据力**，
   不得作为规范依据。中文效力标记：須＝必须 / 應＝应当 / 可、可能需要＝可以；
   注意「無須/不須」不是强制，「不得」是禁止（另一个极，不在强度轴上）。
6. **改权威数据必须全链同步**：规则卡带指纹，卡改了而派生索引/授权表/身份目录不重建，
   系统会**静默丢弃该卡授权**且全链不报错。
7. **跑批期间仓库零改动**：批一开跑，代码状态锚就冻结；作用域内任何字节变动都让
   「重算 == 清单」失效。
8. **诊断轴 ≠ 消费者轴**：「让我更清楚系统哪里不行」和「让使用者更好用」是两件事，
   本项目长期跑偏在前者。评审时如果你要提改进建议，请标明它落在哪一轴。
9. **数字纪律**：任何数字必须带口径（哪个批、哪个池、按什么单位计）。
   本项目多次因为「同一个数字两套口径」下过错结论，故台账里保留了大量
   带删除线的作废数——**那是有意的防错设计，不是没清理**。

## 五、请你回答的三问（这是本次审核的全部要求）

### 问一：**换池前还有什么没想到的风险？**

这是最重要的一问。换池不可逆、成本最高，一旦换了才发现某件事该在换池前做，
代价是再换一次池 ＋ 全部数字重新对账。请你独立扫一遍，特别关注：

- 本柜各案的「遗留尾巴」里，**哪几条其实是换池的硬前置**，而我们当成了「换池后再说」？
  （已知的自我怀疑：#23 词表扩建**至今未开工**；KG 重灌押后；
  `check_batch_acceptance` 门限随分母漂移未核；全池 50 栋逐字节配对未做；
  1b 的下游判定位移未验。）
- 各案之间的**交互**有没有被漏掉？——七个案子在同一批里落地，
  两两之间的相互影响是否都被显式验证过？（例：期限锚新增条目与 #29 改轴
  「互不移位」这一条，底稿要求实测坐实，**实施记录明写本次未做**。）
- 有没有**在换池那一刻才会第一次显形**的缺陷？本柜里已经出现过两次这种形状
  （乙12：冻结批不注入所以什么都没坏，换池批必然注入；
  真值双池：同 seed 标签两个池，跨池评分整族反号）。**第三次在哪？**
- 有没有哪一处「现状安全」的结论，其实**只在某个特定口径下成立**？

### 问二：**预注册期望表的口径有没有漏洞？**

「预注册期望表」＝换池批开跑**之前**写死的一组期望数字，换池批跑完拿真实数字与它对账，
用来防止「跑完了再解释数字」这种事后合理化。当前这套表分散在几处
（`02_实施记录/实施记录_换池捆绑_20260805.md` §三.3 与 §六.3 是主表；
期限锚案 §三、#25 案的 A5 分布断言、#29 案的记账闸各有一部分），
**它们并不统一在同一节里，也不是同一个口径。** 请评估：

- **口径混用的风险**：冻结批注入口径 vs 换池批重生成口径是两张不同的表，
  当前规矩是「旧表原地标沿革，不许把上界换成实测值原位改」——这条够不够？
- **上界口径能不能承重**：多处数字标注为「上界口径 / 占位分布，不得当结论引用」，
  因为 satisfied/violated 的拆分由**已授权但未标定**的分布决定。
  那么换池批对账时，**到底哪些数字算「对上了」，哪些结构上不可能对上**？
- **性质断言 vs 条数断言**：当前裁定是「不变量部分用性质断言（不锚条数），
  条数部分作为预注册值取当批数」。这个两分法有没有漏洞——
  会不会出现「性质断言全绿、条数全错」而没人报警的情形？
- **基数漂移**：本柜已经有一条预注册期望在实施当天就因基数变化被订正
  （27→8/10 实为 0→0）。**如何在换池批开跑前系统性地发现同类基数漂移**，
  而不是撞上了才改？

### 问三：**「停止认证」的标准该怎么设？**

背景：本项目有一条规矩——凡要宣称「被阻塞、只能停下」，必须先把阻塞清单
（每条附「我试过什么」）交第三方逐条认证，判定「真是外部阻塞」的才算数；
判「没试 / 可绕」的当场回去做。历史实证：一次连报十余个「阻塞」，绝大多数是自造的。

现在要把这条规矩用在**更大的一层**：换池 + 重立 baseline 之后，
**凭什么可以宣告「这个阶段做完了、可以停」？** 请你给出一套判据，要求：

- **可测**——不能是「感觉够了」。参照本项目现行的验收标准形态
  （无故 unknown 归零 / 有故 unknown 说清为什么 / 适用条款不漏），
  以及「消费者优雅可用」这个更高的收官标准（一键跑批、产物完整可信、
  阅卷可信、数字可引，**有坑即未收官**）。
- **区分「做完了」与「做不下去了」**——这两种停止的判据不应该是同一套。
- **防「宣告漂移」**——本项目历史上多次出现「管线通了就宣告完成」，
  以及「脚注承认某项缺失、标题仍写过门」这种形状。你的判据要能挡住它们。
- 明确说出：**哪些欠账可以带着进收官，哪些必须清零。**

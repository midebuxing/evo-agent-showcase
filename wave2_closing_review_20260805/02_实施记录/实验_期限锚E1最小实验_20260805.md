## 一、三态结论

> **E1 成立**（A 臂 0 条脱离）——**但它给出的机制只覆盖了四堵墙里的一堵，且不是最硬的那堵。**

1. **E1 的可操作结论坐实**：凡带 `qualifiers.aggregation == "building"` 标记的行，
   对碎片作用域的 #7/#8 义务**一条都救不回**。
   **全批 30 栋实测**（A3 臂，锚名槽 ＋ 聚合标记 ＋ 载体伪装 `sidecar_entry`）：
   **107 / 107 仍 `missing_time_anchor`，脱离 = 0**；
   单栋另测的两种楼级形态（真实 `pack_builder` 载体形 A2、量表通道 C2）同样 0 条。
   ⇒ 商议结果里的决策点 5①（"走楼级救不了这 107 条"）**不必作废**。
2. **E1 的机制描述对 #7（14 条）成立、对 #8（93 条）不成立**。
   #8 的 93 条**不是"绑不上"**——它们**已经绑上了一条事实**
   （`evidence_fact_ids` 非空、`observed_value_json = "true"`），
   `missing_time_anchor` 来自 `obligation_deriver.py:2108-2109` 的**第二处判据**
   （"observed True unusable"），不是 `fact is None` 那处。
3. **实验额外查出两堵 E1 与底稿都没点名的墙**，其中一堵比 E1 更硬（见 §四）。

## 四、机制：四堵墙，按遇到的先后

**墙①（E1 说的那堵）——`_fragment_index` 排除 `aggregation=="building"`。**
`validator.py:1409-1414` 属实。**干净证据在 #7 上**：#7 的锚名不在别名表、世界侧零事实，
故墙②墙③都不适用；A3（载体伪装 `sidecar_entry`，槽通道与量表通道都该命中）
与 C2（量表通道）两臂对 #7 **0 条脱离**（A3 全批 0/14，C2 单栋 0/8），
而只把 `aggregation` 标记去掉（A4 / C3）立刻 **8/8 satisfied**、
换成碎片级（C1）**全批 14/14 脱离** ⇒ 墙①独立成立、且**唯一变量就是那个标记**。
（#8 上墙①与墙③同时生效，A3 的 0 条是过定的，分不出是哪一堵——所以不拿 #8 当墙①的证据。）
**但 A4/C3 反过来证明：把标记去掉，同一行楼级事实碎片作用域立刻看得见并绑得上**
（#7 8/8 satisfied）⇒ **挡路的是 `aggregation` 标记，不是"楼级"本身**。
E1 写的"两个选项都不成立"，这里要修正为：存在**不改 `_fragment_index` 的第三条路**
（楼级发射但不打聚合标记）。代价与底稿担心的一样——该行对每个碎片各判一次。

**墙②——`_bind_deadline_fact` 从不读 `provenance.time_anchor_key`。**
它按 `canonical_slot(锚名)` / `canonical_measure(锚名)` 查（`obligation_deriver.py:2178-2199`）。
A1 与 B1 两臂用的正是底稿设想的供给形状（新起一个 `duration.*` 槽名 ＋ 填 `time_anchor_key`），
**楼级碎片级都 0 条脱离**。
⇒ **底稿 §4.2「给新槽填 `time_anchor_key`」这条路，在当前绑定实现下无论走哪个作用域都无效**——
这比 E1 的适用面更广，且 E1 没点名。可行的供给形状只有两种：
①事实的 `slot_id` 归一后＝锚名（走第 1+2 级，另需 `carrier_type=="sidecar_entry"`）；
②事实的 `measure_key` 归一后＝锚名（走第 3 级，无载体过滤）——即 C 组用的量表通道。

**墙③（最硬，全批 156 条，跨作用域）——锚名经别名表指向一个世界侧布尔闸槽。**
`_bind_deadline_fact` 第 1+2 级是 `if facts: return facts[0]`，**不看值类型**。
`slot_aliases` 全表 15 条真桥里，**只有 `repair.prescribed.completed` 与 `repair.prescribed.started`
两个键与期限锚名撞上**，别名目标 `procedure.repair.prescribed.*` 在世界侧各有
8 条碎片 `sidecar_entry` ＋ 1 条楼级聚合行，**全是 boolean 闸状态**。
⇒ 归一后必然命中布尔行 → `return facts[0]` → **第 3 级量表通道永不可达**。
实测佐证：C1（量表通道·碎片级）对 #7 全中、对 #8 **0 条**；D4 对楼级的 `repair.prescribed.started` 同样 0 条。
⇒ **#8 的 93 条 ＋ `repair.prescribed.started` 的 63 条 ＝ 156 条（603 条期限义务的 25.9%），
在不改 `_bind_deadline_fact` 的前提下，任何供给侧动作都救不回。**
> 反讽点：**有别名反而是害**。其余 13 个锚点因为不在别名表里，槽通道空转、
> 第 3 级量表通道畅通，反而是可被供给救回的（#7 与 D5 实测坐实）。

**墙③附加（根因已钉到卡）——`repair.prescribed.completed` 这个键在同一张卡里还兼着触发槽。**
卡 `rc.mbis.reporting.ri_procedural_notifications.ri.submit.s2_1_3_r.c01`：
`trigger_conditions.items[0]` 是 `slot_ref sr01 == true`，而 `slot_role_map` 里
`sr01.slot_id = "repair.prescribed.completed"`、`roles=["trigger"]`；
同卡 `workflow_operands.deadlines[0].time_anchor_key` 也是这个键。
⇒ **一键两用**：触发器要它是 `true`（布尔），期限要它是已历时长（数值）。
往该槽塞 numeric 会同时砸掉触发器——A4/B2/B3 三臂 #8 全部
`open/missing_time_anchor → blocked/missing_rule_edge`（`trigger_state=blocked`，
notes `trigger aggregate blocked`）。**同槽混供两种值类型是净恶化，不是修复。**
（`repair.prescribed.started` 的三张卡没有这层 in-card 撞名，只有别名撞名。）

**墙④（供给侧之外）——卡侧 `offset_value` 缺失。**
卡包 32 条带 `time_anchor_key` 的期限条目里，`investigation.detailed.commencement`（3 条，`relation=before`）
与 `repair.prescribed.started`（3 条，`relation=before`）的 `offset_value` 为 `None`。
D1/D2/D3 实测：锚事实供上了、绑上了，判定落 `blocked / schema_contract_violation`。
⇒ **"脱离 `missing_time_anchor`" ≠ "产出确定判定"**，验收数字表若按前者写会高估。
（D5 用 `offset_value` 齐全的锚点做了正对照：5 天 → 4/4 satisfied，30 天 → 4/4 violated，
机制端到端是通的。）

## 五、副作用（对"隔离"与字节锚有直接含义）

往锚点槽注入一行会**改变义务集大小**，不是纯增量判定：
A2（真实楼级聚合形）净 +10 条（14 增 4 减，全落楼级作用域，涉 `s5_3_1` / `s5_3_3` / `s5_4_2` 等卡）；
A4 净 +15 条（17 增 2 减，全落碎片作用域）。
**C 组（量表通道，新槽名承值）三臂全部 0 增 0 减**——
⇒ 若要供给，**量表通道是唯一不扰动义务集的形状**。

## 六、对商议结果的影响

| 商议结果的表述 | 本实验裁定 |
|---|---|
| 决策点 5①「走楼级救不了 107 条」 | **维持**（三种楼级聚合形态全批 0 条脱离） |

| 底稿 §4.2「给新槽填 `time_anchor_key`」 | **整条无效**（墙②，A1/B1 双作用域 0 条），与作用域选择无关 |

## 七、诚实边界

- 全部结论来自**同一批**（`wave1_closing_seed401_20260804`，池 `gen_seed_401`）。
  换池后锚点作用域分布可能变，但四堵墙都是**代码级**判据，与池无关。
- 注入的是**合成事实**，不是真实世界生成器产物。它证明的是
  "闭包这一侧对这种形状的行会怎么反应"，**不证明**世界生成器有能力产出这种形状
  （`sidecar.py` 的楼级发射器现只有 `_emit_scope_declaration_rows` 一条、且写死单槽，
  商议结果 E4 已核实，本实验未动这一层）。
- D 组只在单栋（0041）跑，未做全批；D 组结论（楼级作用域吃楼级行、`offset_value` 缺失落
  `schema_contract_violation`）的机制均可在代码里直读，但**数字只对这一栋**。
- 未测：多行 sidecar 的 `facts[0]` 取序问题。B2（尾插）与 B3（首插）本想测这个，
  但两臂 #8 都因触发器塌陷落到 `blocked`，**取序未被观测到** ⇒ 这条潜伏项仍未验。
- 全批臂只跑了 base / A3 / C1 三臂（30 栋，覆盖全部 107 条）；
  A1 / A2 / A4 / B1 / B2 / B3 与 C2 / C3 / D 组只在 0041 单栋跑。
  各臂的判据都是代码级、与栋无关，但**数字只对所跑范围**。
- 本实验**不改变任何仓库文件**；批产物只读。

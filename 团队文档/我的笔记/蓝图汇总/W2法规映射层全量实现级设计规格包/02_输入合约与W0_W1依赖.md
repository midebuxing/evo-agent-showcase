# W2 输入合约与 W0 / W1 依赖

W2 法规映射层消费三类输入：**W1 输出**（`WorldBundle` + `SidecarRuntimeBundle`，事实层）+ **W0 资源**（注册表 / canonical_slot universe / sidecar 边界契约，资源层）+ **rule_card v2 bundle**（法规元数据层）。W2 不生成事实、不修改 W0 资源、不修改 rule_card 数据；W2 是三类输入的**只读消费方**。

本章列出 W2 各主入口函数 + 子函数消费的输入清单 + 入口路径 + 字段契约 cross-ref。

## 1. 总入口

```text
W2 输入 = (W1 输出, W0 资源, rule_card v2 bundle)
     │
     ├──→ 编译路径（rule_card → projection contract / spec）
     │      │
     │      ▼
     │   compile_projection_contract(bundle_dir) → ProjectionContract.v1.json
     │   compile_projection_specs(bundle_dir, contract) → ProjectionSpecs.v1.json
     │   load_runtime_mapping(bundle_dir) → runtime_mapping dict
     │
     ├──→ 阈值加载路径
     │      │
     │      ▼
     │   load_all_thresholds(batches_dir) → List[Threshold]
     │   （从 reviewed_batches/batch_*/rule_cards*.jsonl flatten）
     │
     └──→ 评估路径（per-world / batch）
            │
            ▼
        build_normative_projections_for_world(world, registries, sidecar_runtime_bundle)
            → List[NormativeProjection]
            │
            ▼
        execute_projection_batch_v2(
            building_worlds_path,
            normative_projection_path,
            sidecar_runtime_path,
            output_dir,
        ) → {summary_path, results_path, samples_path}
```

四个主入口分工：

| 主入口 | 消费 | 产出 | 触发时机 |
|---|---|---|---|
| `compile_projection_contract` | rule_card v2 bundle | `ProjectionContract.v1.json`（slot / measure 分区 + alias 表 + result schema）| W2 启动前一次性编译 |
| `compile_projection_specs` | rule_card v2 bundle + contract | `ProjectionSpecs.v1.json`（family × card_specs 嵌套结构）| 同上 |
| `build_normative_projections_for_world` | `WorldBundle` + `RegistryBundle` + `SidecarRuntimeBundle` | `List[NormativeProjection]`（per-world per-fragment）| W1 输出一个 world bundle 后 |
| `execute_projection_batch_v2` | `building_worlds.json/parquet` + `normative_projection.json/parquet` + `sidecar_runtime.json/parquet` | `Summary.v2.json` + `Results.v2.parquet` + `Samples.v2.json` | batch 级聚合 |

主入口函数签名细节 + Reject / Repair 边界见 W2 规格 04 函数实施卡。

## 2. W2 消费 W1 输出

W1 输出经 `WorldBundle`（worldgen core，A 类 slot）+ `SidecarRuntimeBundle`（worldgen sidecar 派生层，B 类 slot）两个容器传给 W2；详见 W1 规格 04 函数实现规格卡 + W0 规格 09 §1.2 / §3 Projection consume contract。

### 2.1 `WorldBundle` — A 类 slot（worldgen core 事实层）

W1 worldgen core 9 段函数派生出的 13 类 world object 容器；W2 通过 `world.<field>` 直接访问。W2 消费的关键字段：

| 字段 | 含义 | 在 W2 哪用 | W0 字段合约 |
|---|---|---|---|
| `BuildingContext` | 单建筑顶层上下文（building_id / archetype / scope 系列 qualifier）| Per-building 聚合维度（v2 batch entry 按 building 分桶）| W0 规格 04 §1.1.1 |
| `ComponentNode[]` | 建筑构件节点列表（component_id / component_type / location_class / parent_ref 等）| 当前 W2 主循环不直接遍历 `world.components`；component_type 信息通过 `fragment.component_id → ComponentNode.component_type` 反查读到（spec 04 §7 reference-based contract），进 `_pick_projection_family_for_fragment` family 路由（structural_member → structural_components 等 override）| W0 规格 04 §1.1.2 |
| `LocationNode[]` | 建筑位置节点列表（location_id / location_class / coverage 关联）| 当前 W2 主循环不直接遍历 `world.locations`；location_class 信息通过 fragment 间接读到 | W0 规格 04 §1.1.3 |
| `FragmentContext[]` | 建筑片段五层因果起点（spec 04 §7 9 字段：fragment_id / fragment_template_id / component_id / location_id / fragment_role / fragment_area_m2 / fragment_length_m / in_scope / exclusion_reason）；component_type / material_system / exposure 等物理上下文按 spec 04 §7 reference-based contract 通过 `fragment.component_id → ComponentNode.X` / `fragment.location_id → LocationNode.X` 反查，非 fragment 自身字段 | **主消费**——`build_normative_projections_for_world` 按 `world.fragments` 主循环；每 fragment 构 `NormativeProjection`；读 `fragment.fragment_id` + 按 reference 反查 `fragment.component_id → ComponentNode.component_type` 等上游字段 | W0 规格 04 §1.1.4 |
| `CoverageRelation[]` | component ↔ coverage 类型关联（覆盖率 baseline 用）| 当前 W2 不直接消费 CoverageRelation 实例；coverage_status 派生靠 `world_core_ready` 简化判断 | W0 规格 04 §1.1.5 |
| `DriverState[]` | 五层因果第二层 driver state | W2 不直接消费 | W0 规格 04 §1.1.6 |
| `MechanismState[]` | 五层因果第三层（mechanism_family / fragment_id / parent_ref）| **主消费**——`mechanism_by_fragment[fragment_id] → MechanismState.mechanism_family` → `_pick_projection_family_for_fragment` family 路由 | W0 规格 04 §1.1.7 |
| `ConditionState[]` | 五层因果第四层（condition_class / severity_index / fragment_id 等）| **主消费**——`condition_by_fragment[fragment_id] → ConditionState.severity_index` → severity_band 派生 + applicability_score | W0 规格 04 §1.1.8 |
| `DrainageState[]` / `UBWState[]` / `FireSafetyState[]` / `RepairAssessmentState[]` | 子域 state（drainage / UBW / fire safety / repair-assessment）| 当前 W2 主循环不直接遍历这些 state 列表；相关事实通过 measurement / sidecar 的对应 slot 间接读到（如 drainage 子域走 DrainageState 派生公共健康风险，按 DEBT-012 closure 2026-05-12）| W0 规格 04 §1.1.9 / §1.1.10 / §1.1.11 / §1.1.12 |
| `MeasurementRecord[]` | 测量值层（measurement_id / slot_id / value_num / unit / target_ref / measurement_family 等）| **主消费**——`measurements_by_fragment[fragment_id]` → fragment_measurements → `find_thresholds_for_slot_any_family(slot_id)` 跨家族查阈值 → `build_threshold_evaluation` 构 ThresholdEval | W0 规格 04 §1.1.13 + §17 |

W2 端**不消费**的 `WorldBundle` 字段：

- W1 内部 distribution 参数（`recommended_mean` / `recommended_sigma` / `physical_bounds` / `typical_bounds` / `mean_semantics` / `distribution_source` 等）—— 这些是 W1 sampling 隐式参数，W2 拿到的只是已采样的 `value_num` 输出值（按 W0 规格 01 §1.1.1 Layer 2 evo-agent-blind 红线，W2 视作 W1 内部不可见）
- W1 derived flag 输入侧（formula / threshold 派生公式）—— 派生公式属 W0 / W1，W2 只读派生结果（如 `coverage.insufficient` 是否 True）

### 2.2 `SidecarRuntimeBundle` — B 类 slot（worldgen sidecar 派生层事实层）

W1 sidecar 派生层（按 W0 规格 09 §1.2 双路径派生 — marginal prevalence + conditional formula）输出的 B 类 slot 容器；按 W0 规格 09 §3 Projection consume contract 列 **5 桶**：

| 桶 | 含义 | W2 端消费 |
|---|---|---|
| `procedure_gate_state` | 程序状态桶（委任 / 提名 / 通知 / 认可 / 开始 / 完成 / 送交 / 最终检验等程序 gate） | **主消费**——sidecar 数值 slot 抽 numeric value（如 `duration.notification.deadline`）→ threshold lookup 跨家族查 |
| `supervision_runtime_state` | 监督运行时状态桶（监督团队 / 现场访问 / SP1 / SP2 / 见证等）| **主消费**——同上 |
| `artifact_requirement_state` | 工件证据要求桶（报告 / 表格 / 日志 / 相片 / 图则 / 证书 / 声明等）| **主消费**——同上 |
| `completion_runtime_state` | 完成阶段运行时状态桶（最终验收 / 完工证明 / 完工报告等） | **主消费**——同上 |
| `facts` | qualifier 通用桶（actor_role / location_class / component_type 等 enum）| **主消费**——按 spec 09 §1.2 修订 2026-05-09 双路径派生，conditional formula 输出的 numeric / categorical 值也进 facts 桶 |

**W2 端抽取规则**（详见 W2 规格 04 函数实施卡 §2.2 sidecar numeric 提取）：

- per-fragment 抽取：通过 sidecar record 的 `qualifiers.fragment_id` 关联到 W2 fragment 主循环；同一 fragment 多个 sidecar slot 全部进入 `threshold_inputs`
- unit / measurement_family 翻译：通过 `sidecar_measurement_registry` 查 slot_id → `{unit, measurement_family}` 元数据
- 数值过滤：sidecar slot value 必须 `isinstance(int, float)`；非数值 slot（bool / categorical）不进 threshold_inputs（5-bin 评估走 `not_numeric` 兜底）

**W2 端不修改**：sidecar bundle 一旦从 W1 sidecar 派生层产出就是 immutable；W2 不写回 / 不补丁 / 不重新派生 sidecar slot 值。如 sidecar 派生异常（spec 09 §1.2 / §6），W2 端按 fallback 路径输出 `unknown` + 对应 `unknown_reason_code`（详见 W2 规格 08）。

### 2.3 merge_key（W1 → W2 关联键）

按 W0 规格 09 §3 Projection consume contract：

```text
merge_key:
    - world_id
    - building_id
    - fragment_id
    - component_id
    - slot_id
```

`fragment_id` 是 W2 主循环维度；`slot_id` 是 measurement / sidecar slot 跨 worldgen core / sidecar 派生层的统一命名约定（详见 W2 规格 06 canonical_slot universe）。

## 3. W2 消费 W0 资源

W2 通过 `RegistryBundle` 容器消费 W0 资源；详见 W0 规格 02 资源域 + W0 规格 03 schema matrix + W0 规格 11 inventory。

### 3.1 W2 主消费 — `normative_projection_registry`

`normative_projection_registry` 是 W2 端**主要**消费的注册表（按 W0 规格 02 §2 资源域职责 + W0 规格 11 §4.4 inventory）。

**消费入口**：

- `_projection_registry_lookup(registries)` → `Dict[str, Dict[str, Any]]`（按 `projection_family` 字段索引 records）
- `build_normative_projections_for_world` 调用上述 lookup 拿 `projection_family_index`，per-fragment 通过 `projection_family_index[family_id]` 查 family 的 entry

**W2 端消费的字段**（按 W0 规格 11 §4.4 schema 11 字段声明）：

| 字段 | W2 端消费场景 |
|---|---|
| `projection_family` | family_id 主键；W2 family 路由依据 |
| `projection_registry_id` | 注册表 ID 写入 `NormativeProjection.projection_registry_id`；fallback `NP_UNKNOWN_<fragment>` |
| `applicability_predicates` | 判断 family 是否适用（W2 当前简化版按 mechanism_family + component_type 路由，未完全 evaluate predicate 表达式）|
| `required_world_core_slots` / `required_measurement_slots` / `required_qualifier_slots` / `required_sidecar_interfaces` | per-family required slot 清单，进 `NormativeProjection.required_*` 字段 |
| `conflict_group` | family 互斥与冲突回退分组（详见 W2 规格 07）|
| `rule_ids` | family 关联的 rule_card 清单，进 `ProjectionFamilyEval.rule_ids` |
| `basis_template_ids` | basis 模板（per-family 配置的 basis 来源清单）|
| `domain_buckets` | family 所属的 domain bucket 分组（如 `structural_external / coverage_sampling / assessment / drainage / fire_safety / technical_validation` 等）|

severity_band 派生公式（按 `regulation_projection_executor.py::build_normative_projections_for_world` 主循环 L988-L997 + W2 规格 00 §2 `severity_band` 术语）直接基于 `ConditionState.severity_index` 数值阶梯派生，**不**消费 `normative_projection_registry` 额外字段。

**W2 端不消费**的 `normative_projection_registry` 字段：W2 当前简化版用 mechanism_family + component_type 路由 family，未读取所有 predicate 表达式；这是 W2 当前实施现状的简化（spec 上 family 选择应基于完整 applicability_predicates 评估），不在本章 spec 范围内描述。

### 3.2 W2 必读 / 可读不强制 — sidecar 相关 registry

| registry | W2 端权限 | 消费入口 |
|---|---|---|
| `sidecar_measurement_registry` | **必读** | `build_normative_projections_for_world` 主循环内 `registries.registries` 找 `registry_id == "sidecar_measurement_registry"` → 抽 `slot_id → {unit, measurement_family}` 元数据，给 sidecar numeric slot 抽 numeric value 时翻译 unit / family |
| `sidecar_ownership_registry` | **可读不强制** | sidecar slot ownership map 主要在 W1 sidecar 派生层（worldgen 内）使用；W2 端通过已派生 `SidecarRuntimeBundle` 5 桶分流间接消费 ownership 信息（5 桶分流已隐含 ownership 路由），不直接 read registry |
| `sidecar_bool_slot_registry` | W2 不直接消费 | sidecar bool slot 由 W1 sidecar 派生层用，W2 拿到的是已派生 bool value |

### 3.3 W2 可读 — `technical_measurement_registry`

W2 端不消费 `technical_measurement_registry` 主体（W1 worldgen core 负责按 registry 采样 measurement value），但 W2 端可能间接通过以下场景查询：

- threshold_regime 评估需要查 measurement `slot_unit` / `measurement_family`：以 `MeasurementRecord.unit` / `MeasurementRecord.measurement_family` 与 W0 measurement contract 的一致性为准；W2 不猜测单位或 family。
- precision / bounds：W2 不消费（属 W1 sampling 层隐式参数，按 W0 规格 01 §1.1.1 Layer 2 evo-agent-blind 红线）

### 3.4 W2 不消费的 W0 注册表

按 W2 / W1 / W0 三层分工，以下注册表 W2 **不消费**：

| W0 registry | 不消费的原因 |
|---|---|
| `building_template_registry` / `component_type_registry` / `location_class_registry` / `fragment_template_registry` / `coverage_relation_registry` | W1 worldgen core Step 1 实例化 world core 用，W2 拿到的是已实例化 `BuildingContext` / `ComponentNode` / `FragmentContext` 输出 |
| `mechanism_library_registry` | W1 Step 2-5 mechanism / condition 派生用，W2 拿到的是已派生 `MechanismState` / `ConditionState` 输出 |
| `defect_condition_taxonomy_registry` / `material_system_registry` | 同上，W1 Step 2 用 |
| `sampling_plan_registry` | W1 Step 6 coverage / sampling 用 |
| `verification_test_registry` | W1 Step 7 technical validation 用 |
| `assessment_surrogate_registry` | W1 Step 8 FSP surrogate 用 |
| `risk_derivation_registry` / `repair_outcome_registry` | W1 Step 9 derive flags 用 |
| `latent_driver_registry` | W1 Step 1 latent driver 实例化用 |

W2 不消费这些注册表的根本原因：W2 是法规映射层，只读法规相关资源（projection_registry + sidecar 派生界面）和 W1 已输出的事实（WorldBundle + SidecarRuntimeBundle）。W1 内部 surrogate / formula / 派生函数对 W2 不可见。

## 4. W2 消费 rule_card v2 的契约（按 D-4 决策仅描述契约，不复写规格）

按 D-4 决策（用户 2026-05-13 拍板）：W2 spec **只描述 W2 端消费 rule_card v2 的契约**（哪些字段、哪些 cross-ref），**不复写 rule_card v2 数据规格本身**（rule_card 字段 schema / manifest schema / threshold 表达式语法 等属 rule_card 系统，由 rule_card v2 系统自身维护）。

### 4.2 W2 消费的顶层文件 — `manifest.json`

`manifest.json` 是 W2 消费 rule_card bundle 的**唯一入口**（按勘探报告 §10.1）；含顶层 4 字段：

| 字段 | 含义 |
|---|---|
| `bundle_id` | bundle 唯一标识 |
| `schema_version` | rule_card v2 schema 版本（当前 `2.1.0`）|
| `source_documents` | 法规原件清单（含 sha256 + canonical_file 路径）|
| `files` | sub-file 索引 dict — 13 个键 |

W2 端 `compile_projection_contract` / `compile_projection_specs` 通过 `load_rulecard_bundle(bundle_dir)` 解 manifest → 读 `files` dict → 按需加载各 sub-file。

### 4.3 W2 消费 rule_card 字段的契约

W2 端**实际消费**的 rule_card 字段清单（按勘探报告 §10.3 + 现役代码 `regulation_projection_contract.py` + `regulation_thresholds.py`）：

| 消费场景 | 消费的 rule_card 字段 | W2 端入口 |
|---|---|---|
| projection family applicability | `family_id` + `applicability.phase / subject / actors / building_scope / component_scope`（当前实施未消费 `applicability.regime` / `applicability.exclusions`）| `_compiled_card_spec`（L228 per-card 编译时读 applicability dict）|
| candidate trigger 评估 | `trigger_conditions`（`logic` + `items`，每 item 含 `condition_id / predicate_kind / slot_ref_id / operator / expected_value / measure_key / qualifiers`）| `_compiled_trigger_predicates`（L153）|
| slot 绑定 | `slot_role_map`（每项 `slot_ref_id / slot_id / qualifiers / roles / required`）| `_compiled_card_spec` 内读 slot_role_map；通过 `projection_runtime_mapping_v1.slot_aliases` 翻译 rule_card slot_id → W0 slot_id |
| threshold 加载 | `threshold_regimes`（每项 `threshold_regime_id / measure_key / operator / value / unit / qualifiers / time_anchor_key / source_quote_refs`）| `regulation_thresholds.py::load_all_thresholds`（L40，从 `reviewed_batches/batch_*/rule_cards*.jsonl` flatten）|
| basis 字段追溯 | `rule_card_id`（→ `ThresholdEval.rule_id` / `ReportBasisItem.rule_id`）+ `family_id`（→ `ReportBasisItem.family_id`）+ `source_quote_refs`（用作可追溯）| `build_threshold_evaluation` + `_compiled_thresholds`（L202）|
| evidence 完整性 | `evidence_requirements`（3 段 `for_matching / for_submission / for_completion`，每项 `evidence_requirement_id / kind / required / description / artifact_ids / slot_ref_ids / measure_keys / required_field_groups`）| `_collect_required_sidecar_interfaces`（L102）反推 sidecar 接口需求 |

### 4.4 W2 当前**不**消费的 rule_card 字段

- `obligation_graph`（rule_card 字段，描述义务节点 + 边）—— W2 当前停留在 single-card / single-fragment 评估，未消费 obligation chain（属未来 W2+ extension）
- `exceptions` / `definitions`（rule 内嵌例外 / 定义）—— W2 当前不消费
- `workflow_operands`（primary_actor / primary_action / recipients / artifacts / deadlines / audiences / method_keys_allowed 等）—— `_compiled_card_spec` 仅取 `deadlines` 部分作 trigger，未消费完整 workflow
- `provenance` / `version`（出处 / 版本元数据）—— W2 不消费
- `neighbor_families`（邻接 family 清单）—— 当前简化版 family 路由未消费 neighbor relation

### 4.5 W2 ↔ rule_card 翻译入口 — `projection_runtime_mapping_v1.json`

`projection_runtime_mapping_v1.json` **不在** rule_card bundle 的 `manifest.files` 13 文件清单内（按勘探报告 §10.2 备注），但 W2 必读。物理上放在 rule_card 目录下，但定位是给 projection executor 用的 alias / lookup 映射。

**顶层 schema**（7 字段，按物理 JSON 现状 + 勘探报告 §10.4.3 列的前 4 字段）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `version` | `str` | runtime mapping 版本（`regulation_projection.runtime_mapping.v1`）|
| `slot_aliases` | `dict[str, list[str]]` | W0 端 `slot_id` → rule_card 端 `slot_id` alias 列表 |
| `measure_aliases` | `dict[str, list[str]]` | W0 端 `measure_key` → rule_card 端 `measure_key` alias 列表 |

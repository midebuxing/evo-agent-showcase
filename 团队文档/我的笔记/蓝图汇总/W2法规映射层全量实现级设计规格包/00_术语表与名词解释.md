# W2 术语表与名词解释

## 1. 跟 W0 / W1 规格 00 的关系

W2 术语**继承** `W0新版全量实现级设计规格包/00_术语表与名词解释.md` + `W1实例生成流程全量实现级设计规格包/00_术语表与名词解释.md`，本表只补 W2 阶段独有 + W0 / W1 已列但 W2 端语义有特化的术语。

## 1.1 slot 术语约定（spec-wide）

按 memory `feedback_slot_terminology.md`：本 W2 spec 包中讨论 slot 涉及**两套独立 slot 系统**——

| slot 系统 | 来源 | 5 / 2 类分类 | 在 W2 哪用 |
|---|---|---|---|
| **W0 端 canonical slot**（来自 a4 + W0 规格 08） | a4 canonical slot universe + W0 规格 08 §1 | 5 类 `slot_class`：`world_truth_slot` / `measurement_slot` / `qualifier_slot` / `artifact_requirement` / `procedure_or_gate_requirement` | W2 spec 06 主体（canonical_slot universe + family coverage baseline） + W2 spec 09（`required_slots` 字段）|
| **rule_card v2 端 semantic_slot + measure**（来自 `semantic_slot_registry_v1.json` + `measure_registry_v1.json`） | rule_card v2 数据系统 | rule_card 端用 `semantic_domain` 分类，不用 5 类 `slot_class`；含 `slot_id` + `allowed_roles` + `semantic_meaning` 字段 | W2 spec 02 输入合约（消费契约层）|

**两套各自独立定义**，靠**命名一致 + `projection_runtime_mapping_v1.json` 中 `slot_aliases` / `measure_aliases` alias 表**衔接。spec 内出现 `slot` 字样**默认按 W0 端读**，如需指 rule_card 端会显式标 "rule_card semantic_slot"。

## 2. W2 独有术语 — projection 输出对象家族

### `NormativeProjection`

**定义**：法规映射层的参考真值输出对象；针对单个 fragment 由 projection executor 构造；包含 `projection_id` / `projection_registry_id` / `projection_family` / `world_id` / `projection_version` / `matched_families` / `selected_family` / `projection_status` / `required_slots` / `basis_items` / `unknown_reason_code` / `sidecar_join_status` / `severity_band` / `required_world_core_slots` / `required_measurement_slots` / `required_qualifier_slots` / `required_sidecar_interfaces` / `matched_component_refs` / `matched_measurement_ids` / `coverage_status` / `notes` 字段（详见 W2 规格 09；W0 04 §§18-21 只保留迁出 stub）。

**ID 前缀**：`NP-`（继承 W0 规格 00 §5.1 ID Prefix 表）；fragment 级 ID 形如 `NP-<fragment_id>-<index:02d>`。

**新版状态**：保留。

**易混点**：`NormativeProjection` 不是 `HiddenGold`（已砍）；不是 W0 静态资源层的输出终点；不是 evo-agent 的 verdict。它是 W2 的**主输出对象**，是 evo-agent 训练 / 评估的**参考真值**输入之一。

### `ProjectionFamilyEval`

**定义**：单个 regulation family 在某 fragment 上的适用性评估结果；含 `family_id` / `applicability_score` / `applicability_state` / `trigger_ids` / `rule_ids` / `slot_role_map` / `threshold_evaluations` / `verdict` 字段（详见 W2 规格 09）。

**新版状态**：保留。

**易混点**：family eval 是法规投影中的 family 适用性结果，不是 adjudication；`verdict` 取值 `pass` / `fail` / `unknown` / `not_applicable`，不是 agent 答案对错。

### expected_verdict

`expected_verdict` 是 W2 `NormativeProjection` 的 per-fragment reference truth。取值固定为：`pass` / `fail` / `unknown` / `not_applicable`。

它用于训练 / 评测 / 报告依据追溯，不是人类巡检员最终决定，也不等于 Closure Verifier 的最终输出。

### pending

`pending` 不属于当前数据生成层封口版输出 enum。任何 `ProjectionFamilyEval.verdict` 或 `NormativeProjection.expected_verdict` 都不得输出 `pending`。

### `ThresholdEval`

**定义**：单个数值阈值评估结果；含 `rule_id` / `slot_id` / `operator` / `threshold_value` / `observed_value` / `regime_tag` / `pass_bool` 字段（详见 W2 规格 09；threshold regime 见 W2 07）。

**关键不变量**：`regime_tag` 跟 `pass_bool` **是两套独立维度**——`regime_tag` 描述测量值相对阈值的位置（5-bin + `not_numeric`），`pass_bool` 描述测量值是否通过 operator 检验；同一 `near_below` 在 `<=` 是 pass、在 `>=` 是 fail。

**新版状态**：保留。

**易混点**：threshold eval 是法规投影用的数值判断，不是评分标签；不是 HiddenGold 副本。

### `ReportBasisItem`

**定义**：projection 说明 verdict 的依据项；按 `basis_kind` 分 5 个 kind（详见 W2 规格 09，本节列定义）：

| `basis_kind` | 来源 | 字段重点 |
|---|---|---|
| `threshold_compare` | a12 §12.1 | observed_value / threshold_value / operator / regime_tag / pass_bool / unit |
| `bool_assertion` | a12 §12.2 | observed_value（bool）/ expected_value / pass_bool / statement_code |
| `family_uncovered` | a12 §12.3 | family_id = `unknown` / rule_id = `None` / reason_code / candidate_known_families |
| `world_origin` | W0 规格 04 §21 新增 | 标记 basis 源自 worldgen core fact（非 rule_card threshold）|
| `measurement_origin` | W0 规格 04 §21 新增 | 标记 basis 源自 W0 measurement layer |

a12 §12 只列前 3 kind；后 2 kind（`world_origin` / `measurement_origin`）是 W0 规格 04 §21 在 a12 基础上扩展，用于支持 projection 端追溯到 W1 / W0 输入的不同来源层。

**新版状态**：保留。

**易混点**：basis item 可用于解释法规投影 verdict，**不应复制成 HiddenGold**；按 W2 端约束 `C025_BASIS_NONEMPTY`，`NormativeProjection.basis_items` 必须非空。

### `projection_status`

**定义**：projection 覆盖状态枚举；取值 `covered` / `uncovered` / `conflict`（继承 W0 规格 00 §4 / 详见 W2 规格 09）。

**新版状态**：保留。

**易混点**：不是 HiddenGold 的评分状态；跟 `coverage_status`（W0 规格 04 §18 `NormativeProjection.coverage_status`）取值不同——`coverage_status` 是 `world_core_ready` / `unsupported`，描述世界端核心 slot 是否到位；`projection_status` 是 family 维度的覆盖结果。

### `severity_band`

**定义**：fragment 级严重度的离散分箱；W2 规格 04 实施卡 + `regulation_projection_executor.py::build_normative_projections_for_world` 派生公式：

| `severity_index` | `severity_band` |
|---|---|
| ≥ 0.85 | `emergency` |
| ≥ 0.66 | `severe` |
| ≥ 0.33 | `moderate` |
| > 0 | `minor` |
| 否则 | `none` |

**新版状态**：保留。

**易混点**：severity_band 是 projection 端按 severity_index 派生的离散标签，不是 rule_card 端的 risk verdict；不是 evo-agent 训练 reward。

## 3. W2 独有术语 — threshold regime 5-bin

### `ThresholdRegime` / `regime_tag` / 5-bin

**定义**：测量值相对法规阈值的位置 6 枚举（5 数值档 + 1 非数值兜底）：

| `regime_tag` | 物理含义 |
|---|---|
| `far_below` | 测量值远低于阈值（差距超过 width）|
| `near_below` | 测量值略低于阈值（差距 ≤ width）|
| `exact_threshold` | 测量值精确等于阈值（在 `EPS_EXACT = 1e-9` 内 / rounding 后精确等 / integer 严格相等）|
| `near_above` | 测量值略高于阈值（差距 ≤ width）|
| `far_above` | 测量值远高于阈值（差距超过 width）|
| `not_numeric` | 非数值 operator（`in` / `not_in` / 用于 bool / enum 的 `==`）兜底 |

**width 公式**：按 measurement_family 路由（详见 W2 规格 09 §1.2 + 勘探报告 §9.1.2）；family 表 hit 优先（`geometry_length / width / depth` / `geometry_area` / `ratio` / `count` / `rate` / `stress` / `bool` / `enum`），fallback 按 `slot_unit` 推断（`mm / m / m2 / ratio / N_per_mm2 / count / count/25m2`），最终兜底 0。

**新版状态**：保留。

**易混点**：5-bin 描述测量值相对阈值的位置，**不代表 pass/fail**——pass/fail 由 operator 单独决定；`exact_threshold` 是数值意义上"精确等"不是 pass/fail 判断。

### `EPS_EXACT` / `_EXACT_THRESHOLD_EPSILON`

**定义**：浮点精度 epsilon，固定 `1e-9`；用于 `exact_threshold` 判定（`abs(observed - threshold) < 1e-9`）+ operator 求值（`<=` / `<` / `>=` / `>` / `==` / `!=` 比较时容忍精度）。

**新版状态**：保留。

## 4. W2 独有术语 — canonical slot universe

### `slot_class` 5 类

**定义**：a4 canonical slot universe 中 slot 的语义类别（继承 W0 规格 00 §4 Slot Class，本表补 W2 端语义）：

| `slot_class` | 含义 | 例 |
|---|---|---|
| `world_truth_slot` | slot 描述建筑 / 构件 / 缺陷 / 风险 / 修葺结果本身，应存在于 world truth | `defect.crack.exists` / `risk.building_safety.emergency` |
| `measurement_slot` | slot 描述比例 / 面积 / 数量 / 时间 / 应力 / 公式 / 采样率等测量值；**不应**伪装成 world truth | `ratio.covered_area.inspected` / `length.crack.width` / `count.core_sample.minimum` |
| `qualifier_slot` | slot 限定别的 slot / measure 的分类信息 | `qual.component_type` / `qual.location_class` / `qual.actor_role` |
| `artifact_requirement` | slot 描述法规要求存在的工件证据（报告 / 表格 / 日志 / 相片 / 图则 / 证书 / 声明）| `artifact.inspection_report.submitted` |
| `procedure_or_gate_requirement` | slot 描述程序状态（委任 / 提名 / 通知 / 认可 / 开始 / 完成 / 送交 / 最终检验）| `procedure.ri.appointment.completed` |

**注**：a4 原文写过两种命名 `procedure/gate requirement` 和 `procedure_or_gate_requirement`，W0 规格 08 §1 + W2 规格 06 统一为 `procedure_or_gate_requirement`。

**新版状态**：保留。

**易混点**：`artifact_requirement` / `procedure_or_gate_requirement` 是法规事实需求，但**不代表 W0 / W1 要生成 artifact / procedure truth**——这两类 truth 由 W1 sidecar 派生层生成进 `SidecarRuntimeBundle`（按 W0 规格 09 §1.2），W2 通过 sidecar join 消费。

### `family_id`

**定义**：regulation family 唯一标识；W2 端 16 个 baseline family（按 W0 规格 08 §5 + a4 §3）：

1. `mbis.scope.coverage_and_preinspection`
2. `mbis.procedure.ri_notifications_and_submissions`
3. `mbis.inspection.external_components`
4. `mbis.inspection.structural_components`
5. `mbis.inspection.fire_safety`
6. `mbis.inspection.drainage`
7. `mbis.inspection.ubw`
8. `mbis.investigation.gate_and_proposal`
9. `mbis.investigation.structural_assessment_fsp`
10. `mbis.repair.general_selection_and_classification`
11. `mbis.repair.external_structural_validation`
12. `mbis.repair.fire_safety_and_drainage`
13. `mbis.supervision.ri_minimum_and_site_controls`
14. `mbis.supervision.rc_controls`
15. `mbis.reporting.inspection_report`
16. `mbis.reporting.completion_report`

**新版状态**：保留。

**易混点**：W0 / W2 端 `family_id` 跟 **rule_card v2 端 `family_id` 命名规则不同**——rule_card 端含 actor / action_cluster 后缀（如 `mbis.reporting.inspection_report.ri.submit`）；W2 通过 `regulation_thresholds.py::_W0_FAMILY_TO_RULECARD_PREFIXES`（13 W0 family → rule_card prefix 列表）做衔接翻译。

### `applicability_predicate`

**定义**：`normative_projection_registry` 中判断某 family 是否适用的表达式集合；只读 world / measurement / qualifier / sidecar join，不反向生成 world（详见 W0 规格 00 §5.1）。

**新版状态**：保留。

### `conflict_group`

**定义**：互斥或竞争的 family 组，用于多 family 冲突回退（详见 W2 规格 07）；W2 端 4 个 named entities（按 W0 规格 07 §4.1）。

**新版状态**：保留。

## 5. W2 独有术语 — unknown / not_applicable / fallback

### `unknown_reason_code` 13 枚举

W2 unknown reason code 固定 13 条，权威见 `08_unknown策略.md`。不得用 14 条、16 条或任何 “第 14 条 sidecar_derivation_failed” 口径。

| code | 含义 |
|---|---|
| `no_known_family_match` | 没有 known family 适用 |
| `unsupported_material_system` | material 不被 binding 支持 |
| `unsupported_component_type` | component 不被 binding 支持 |
| `unsupported_damage_pattern` | condition_class 无 binding |
| `unsupported_location_context` | location 不被 binding 支持 |
| `projection_binding_incompatible` | required slots 存在但 unit / method 不兼容 |
| `binding_registry_gap` | registry schema 无法绑定 slot |
| `multi_family_conflict` | 多 family 同组竞争无法解 |
| `sidecar_only_fact_pattern` | sidecar 事实模式无法支撑 projection |
| `coverage_unimplemented_domain` | projection registry 未覆盖该 domain |
| `measurement_family_unimplemented` | measurement family 未实施 |
| `method_class_unimplemented` | test method 未实施 |
| `unit_incompatible` | measurement unit 跟 binding expected unit 不匹配 |

projection unknown 不是 episode 中“调查员不知道”的 unknown；旧 `sidecar_missing` 只作为废止术语保留。


### `not_applicable`

**定义**：某法规 family / slot / condition 对当前 world / component / fragment 不适用的语义（继承 W0 规格 00 §7 Not Applicable，本表补 W2 端语义）。详见 W0 规格 06 §16.4 + W2 规格 08。

**新版状态**：保留。

**易混点**：`not_applicable` 不是 `unknown`、不是 `pass`、不是 `fail`；不是"调查员不需要问"。

### `sidecar_derivation_failed`（已撤回，2026-05-13）

`sidecar_derivation_failed` 是已撤回的文字层副产物，不属于当前 unknown reason code，不属于 sidecar join status，不属于字段名或 basis kind。

sidecar 派生不可用时使用：

- `sidecar_join_status=partial` 或 `unavailable`
- 必要时 `unknown_reason_code=sidecar_only_fact_pattern`


## 6. W2 独有术语 — rule_card v2 消费契约

### `projection_runtime_mapping`

**定义**：rule_card v2 系统 → W2 端的运行时翻译契约文件 `projection_runtime_mapping_v1.json`；顶层含 `version` / `slot_aliases` / `measure_aliases` / `slot_targets` 4 字段（详见勘探报告 §10.4.3 + W2 规格 02）。

**关键字段**：

- `slot_aliases` (`dict[str, list[str]]`)：W0 端 `slot_id` → rule_card 端 `slot_id` alias 列表
- `measure_aliases` (`dict[str, list[str]]`)：W0 端 `measure_key` → rule_card 端 `measure_key` alias 列表
- `slot_targets` (`dict[str, object]`)：W0 端 slot 在 sidecar 端的 owning interface + lookup 规则（含 `owning_interfaces` / `owning_interface_mode` / `lookup_rule`）

**新版状态**：保留。

**易混点**：`projection_runtime_mapping_v1.json` **不在** rule_card bundle 的 `manifest.files` 13 文件清单内；W2 规格 02 输入合约**单独列**此文件作 W2 端 alias / 翻译契约的主入口。

### `slot_aliases` / `measure_aliases`

**定义**：W0 端 slot/measure → rule_card 端 slot/measure 的 alias 翻译表；由 `regulation_projection_contract.py::_slot_aliases` (L43) / `_measure_aliases` (L47) 加载使用。

**新版状态**：保留。

### `Threshold`（dataclass）/ `threshold_regimes`（rule_card 字段）

**定义**：

- rule_card v2 端 `threshold_regimes` 是 `rule_cards.json` 中每条 card 的字段，列阈值清单；每项含 `threshold_regime_id` / `measure_key` / `operator` / `value` / `unit` / `qualifiers` / `time_anchor_key` / `source_quote_refs`（详见勘探报告 §10.3）
- `Threshold` 是 W2 端 `regulation_thresholds.py::Threshold` dataclass，由 `load_all_thresholds` (L40) 把 rule_card `threshold_regimes` flatten 加载为 `List[Threshold]`

**新版状态**：保留。

**易混点**：rule_card 端 `threshold_regimes` 跟 `ThresholdRegime` / `regime_tag` 5-bin **完全是两套概念**——前者是 rule_card 数据中的阈值清单；后者是 W2 端测量值相对阈值的 5 档分箱标签。

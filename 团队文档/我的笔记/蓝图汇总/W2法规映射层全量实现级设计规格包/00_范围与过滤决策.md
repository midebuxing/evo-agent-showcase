# W2 范围与过滤决策

## 1. 本包覆盖范围

W2 是 `WorldGenerator` 三层链中的**法规映射层**，位于 W0 静态资源层之后、W1 实例生成流程层之后；W2 消费 W1 输出 + W0 资源 + rule_card v2 bundle，产出 `NormativeProjection` 参考真值。

W2 覆盖 5 大业务：

- **projection executor 主入口**：per-fragment 构造 `NormativeProjection`、batch 级聚合（v2 entry 读 building_worlds + normative_projection + sidecar_runtime → 汇总 verdict / family_status_breakdown / unknown_reason / severity_band / coverage_status / threshold_regime / threshold_pass）
- **canonical_slot universe 与 normative_projection_registry**：a4 的 5 类 `slot_class`（`world_truth_slot` / `measurement_slot` / `qualifier_slot` / `artifact_requirement` / `procedure_or_gate_requirement`）+ W0 core canonical slots + measurement canonical slots + sidecar-only canonical slots + 16 个 family 的 coverage baseline + `normative_projection_registry` 填表依据
- **threshold_regime 5-bin 分桶 + `ReportBasisItem`**：5-bin（`far_below` / `near_below` / `exact_threshold` / `near_above` / `far_above`，加 `not_numeric` 兜底）+ width 公式 + `ThresholdEval` 字段合约 + `ReportBasisItem` 5 个 kind（`threshold_compare` / `bool_assertion` / `family_uncovered` / `world_origin` / `measurement_origin`）+ `BASIS_NONEMPTY` 约束
- **unknown / not_applicable / sidecar 派生异常 fallback**：unknown 设计原则（`unknown` 不是兜底垃圾桶）+ `unknown_reason_code` 完整枚举 13 条（W0 规格 06 §16.3 + 封口版固定 13 条；2026-05-13 重审拍板撤回原计划新增的 `sidecar_derivation_failed` 第 14 条，sidecar 派生异常 fallback 沿用现有 13 条之一兜底——按业务语义最贴近的是 `sidecar_only_fact_pattern`；详见 W2 规格 08 §3）+ 条件到 `reason_code` 映射 + `not_applicable` 语义 + sidecar 派生异常 fallback 路径
- **coverage_control（采样侧）**：a8 §4 第五件 coverage-controlled rejection 在 W2 端的采样控制——按 5-bin regime / neighbor-family overlap / recoverable missing 过采（用户 D-1 决策 2026-05-13 归 W2）

W2 还定义：

- W2 端约束 `C023_UNKNOWN_NO_RULE_IDS` / `C024_KNOWN_SINGLE_CONFLICT_GROUP` / `C025_BASIS_NONEMPTY`
- family 互斥与冲突回退（4 个 `conflict_group` + 5 种竞争处理）
- W2 ↔ W1 / W2 ↔ rule_card v2 / W2 ↔ evo-agent 三条接口边界

## 4. 跟 W0 / W1 / rule_card v2 / evo-agent 的边界

W2 与上下游层的物理边界详见 `_拆分说明.md` §"跟 W0 / W1 包的关系"。本节列**本包内容编辑时**的过滤判据，按 §0 source 优先级（详见 `01_设计原则与本体边界.md` §0）：

### 4.1 W2 ↔ W0 静态资源层

- W0 规格 02 / 03 / 11 已定义 19 张 registry（含 `normative_projection_registry`）+ schema matrix：**W2 不重复**，cross-ref 引用即可
- W0 规格 04 §17-§22 已定义 `NormativeProjection` / `ProjectionFamilyEval` / `ThresholdEval` / `ReportBasisItem` 字段合约：**W2 规格 09 cross-ref**，不重写字段表
- W0 规格 05 §1 第 6-7 步 + §3.10 / W0 规格 06 §16.3-§16.5 / W0 规格 07 §2 C023-C025 + §3 + §4 + §5 / W0 规格 08 全文：**物理迁出**进 W2 各章节，W0 闭环后留 stub 引 W2
- W0 规格 09 sidecar 边界契约：**W2 引**（projection executor 可消费 sidecar join），W0 物理留存
- W0 规格 15 parquet schema：**W2 引**（`Results.v2.parquet` 由 W0 定义 schema），W0 物理留存

### 4.2 W2 ↔ W1 实例生成流程层

- W1 输出 `WorldBundle` + `SidecarRuntimeBundle`，是 W2 的主消费输入
- W1 严格 rule-blind：W1 不读 `normative_projection_registry`、不调法规 family、不消费 W2 任何输出
- W2 不能反向写回 W1 输出；W1 → W2 严格单向（继承 W0 规格 01 §2 边界表 + a8 §6 三层接口主设计）
- DEBT-030 §A 组耦合点：当前 `agent_v1/src/workflow_engine/worldgen/models.py` L403-L470 物理含 4 个 W2 端 dataclass（`ThresholdEval` / `ReportBasisItem` / `ProjectionFamilyEval` / `NormativeProjection`）+ `worldgen/validation.py` L44 import `regulation_projection_executor.execute_projection_batch_v2` —— 这是历史耦合，W2 spec 包闭环后才能拆迁；W2 spec 不正面描述此耦合，仅在 spec 10 禁止依赖章节点名 DEBT-030 §A 组作 forward-direction trace

### 4.3 W2 ↔ rule_card v2 系统

- rule_card v2 数据系统（`agent_v1/regulations/rulecard_v2/mbis_cop_2023/`）含 ~353 个 rule_card + manifest + 13 个 sub-file + `projection_runtime_mapping_v1.json`
- W2 通过 `compile_projection_contract` / `compile_projection_specs` 编译 rule_card bundle → projection contract / compiled spec；通过 `regulation_thresholds.py::load_all_thresholds` 加载 `reviewed_batches/batch_*/rule_cards_delta.jsonl` 真阈值
- 按 D-4 决策：**W2 spec 只描述消费契约**（哪些字段、哪些 cross-ref），**不复写 rule_card 数据规格**；rule_card v2 系统独立 spec 是否需立项暂不登记 DEBT，按勘探报告 §12.4 备忘清单 trace

### 4.4 W2 ↔ evo-agent 训练层

- W2 输出 `NormativeProjection` 是 evo-agent 训练 / 评估的**参考真值**输入之一
- evo-agent 不可调 W2 内部 family / threshold / projection_registry 配置参数；按 W0 规格 01 §1.1.1 Layer 2，W2 端 projection 输出不可被反推出"这个 projection 是按哪条 threshold 派生的"
- evo-agent 独立承接，W2 spec 不预先约束 evo-agent 内部逻辑；W2 端禁止依赖详见 W2 规格 10

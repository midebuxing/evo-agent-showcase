# W2 函数实现规格卡

> 跨包权威源与负向不变量见：`../_封口总则_字段权威源与负向不变量.md`。如本章与总则冲突，以总则和字段所属包权威章节为准。


本节是 `03_projection_executor函数总览.md` §2 的逐函数展开。§2 给出 W2 phase 1-4 主入口 + 6 个公开 helper 的总览（输入 / 输出 / 前置依赖），本节为每个**主入口和公开 helper**单独一张实施卡，补上 §2 没列的字段：边界条件、公式、Reject 条件（P0）、Repair 动作（P3）。

读者按需切换：要看跨 phase 顺序看 §2，要看单函数实施细节看本节。`compile_projection_contract` / `compile_projection_specs` 的输出 JSON schema cross-ref W0 规格 04 §17-§22；P0/P3 优先级体系 cross-ref W1 包 07 §1 + W0 规格 07 §2 C023-C025 约束。

**P0-P3 速查**（完整定义在 W1 包 `07_约束与四级修复.md` §1，W2 端 cross-ref）：

| 优先级 | 含义 | 触发时动作（W2 端） |
|---|---|---|
| **P0** | reject_or_resample | W2 阶段 P0 集中在 contract / spec 编译和 NormativeProjection 输出 schema 检查；reject 后 batch 停止 |
| **P1** | repair_world_truth_geometry_or_state | **不在 W2 阶段触发** — 属 W1 worldgen，W2 不修世界真相 |
| **P2** | repair_measurement_rounding_or_bounds | **不在 W2 阶段触发** — 属 W1 measurement，W2 不修测量值 |
| **P3** | projection_fallback_to_unknown_or_not_applicable | W2 主体 fallback 动作 — 清 rule_ids / 解决冲突 / 回退 unknown / not_applicable |

## 1. `compile_projection_contract`（W2 phase 1 主入口）

| 项 | 规格 |
|---|---|
| 输入 | rule_card v2 bundle 物理目录路径（默认走 `agent_v1/regulations/rulecard_v2/mbis_cop_2023/`）|
| 输出 | `ProjectionContract.v1.json` dict — 顶层含 `version` / `generated_at` / `rulecard_bundle_id` / `rulecard_schema_version` / `runtime_mapping_version` / `runtime_mapping_path` / `input_partitions`（4 类 `world / measurement / qualifier / sidecar`）/ `slot_partition_map`（每 slot_id → 4 类之一）/ `measure_partition_map`（每 measure_key → 4 类之一）/ `slot_alias_map` / `measure_alias_map` / `result_contract`（含 `applicability_states` / `verdicts` / `required_arrays` / `batch_breakdowns`）|

| Repair | 无（编译期 P0 reject 后 batch 直接停） — W2 阶段不修 rule_card 数据，按 D-4 决策修 rule_card 走 rule_card 系统自身工作流 |

**来源**：W0 规格 05 §3.10 + a12 §7.10 前半（HiddenGold 半段砍）+ 勘探报告 §10.1 manifest schema + §10.4.3 projection_runtime_mapping_v1.json 顶层字段。

## 3. `build_normative_projections_for_world`（W2 phase 3 主入口）

| 项 | 规格 |
|---|---|
| 输入 | `WorldBundle` 对象（W1 输出）+ `RegistryBundle`（含 `normative_projection_registry` / `sidecar_measurement_registry` / `sidecar_ownership_registry`）+ `SidecarRuntimeBundle`（W1 sidecar 派生层输出，含 5 桶）|
| 输出 | `List[NormativeProjection]`（per-fragment；每 fragment 一个 NormativeProjection；NormativeProjection 字段合约详见本包 `09_输出契约_NormativeProjection.md`）|
| 边界条件 | `WorldBundle` 主消费字段必须存在（`world.fragments` / `world.mechanisms` / `world.conditions` / `world.measurements`）+ `normative_projection_registry` 注册表必须含**16 个 baseline family**记录（按 W0 规格 08 §5 + a4 §3）+ `sidecar_measurement_registry` 必须可查 sidecar slot 的 `{unit, measurement_family}` 元数据 |
| 公式 | **per-fragment 主循环 5 步**：<br/>(1) lookup 准备：从 `world.mechanisms` / `world.conditions` / `world.measurements` 按 fragment_id 索引；<br/>(2) sidecar numeric 提取：5 桶按 `qualifiers.fragment_id` 关联 fragment + `sidecar_measurement_registry` 翻 unit/family（详见 §3.2 sidecar numeric 提取规则）；<br/>(3) candidate family 路由：调 `_pick_projection_family_for_fragment(mechanism_family, component_type, projection_family_index)` + `_build_candidate_families_for_fragment(...)` → candidate list（单 target / 多 component_type override，详见 §5）；<br/>(4) 跨家族 threshold 查：W0 measurement slot + sidecar numeric slot 都按 `find_thresholds_for_slot_any_family(slot_id)` 跨家族查，多阈值全 emit；<br/>(5) 调 H1 `evaluate_fragment_projection_candidates` → 返回 selected_family_ids / unknown_reason_code / threshold_evaluations / projection_status；<br/>**构造 NormativeProjection**：projection_id 形如 `NP-<fragment_id>-<index:02d>`；projection_registry_id 兜底 `NP_UNKNOWN_<fragment>`；severity_band 按 ConditionState.severity_index 派生（`>=0.85 emergency / >=0.66 severe / >=0.33 moderate / >0 minor / else none`）；matched_families 含 ProjectionFamilyEval × N（详见 `09_输出契约_NormativeProjection.md` §2 字段合约）|
| Reject (P0) | C025 `BASIS_NONEMPTY` — `NormativeProjection.basis_items` 为空 → reject projection（W0 规格 07 §2 P0） / `WorldBundle.fragments` 为空 / `normative_projection_registry` 注册表加载失败 / mechanism_family 不在 16 family baseline 内（属 spec ↔ spec 错位，按 spec 优先返回兜底 `NP_UNKNOWN_<fragment>` + unknown_reason_code `coverage_unimplemented_domain`）|
| Repair (P3) | P3 触发场景：(a) family conflict 无法解 → `selected_family=unknown` + `unknown_reason_code=multi_family_conflict`；(b) sidecar 派生失败 → `unknown_reason_code=sidecar_only_fact_pattern`（priority 13，扩义为"sidecar 不能支撑事实"；2026-05-13 重审撤回原 `sidecar_derivation_failed` 单独 reason_code 路径，详见本包 `08_unknown策略.md` §3）；(c) required slot 无 W0 或 sidecar 支持 → `not_applicable`；(d) 其他 13 priority 条件按 H4 `derive_unknown_reason_code` 路由 |

### 3.2 sidecar numeric 提取规则（H1 内部 phase 3 中段）

按 W0 规格 09 §1.2（2026-05-09 修订）+ §3 Projection consume contract：

- sidecar_runtime_bundle 提供时按 5 桶（`procedure_gate_state` / `supervision_runtime_state` / `artifact_requirement_state` / `completion_runtime_state` / `facts`）抽 numeric value
- 通过 `qualifiers.fragment_id` 关联 fragment 主循环
- 通过 `sidecar_measurement_registry` 查 `slot_id → {unit, measurement_family}` 元数据
- 数值过滤：sidecar slot value 必须是 `int` / `float`（非数值 slot 不进 threshold_inputs，5-bin 评估走 `not_numeric` 兜底）
- 收集为 `sidecar_numeric_by_fragment: Dict[fragment_id, List[Dict]]`

**来源**：W0 规格 05 §3.10 + a12 §7.10 前半 + a12 §13.3 projection compile logic 伪代码（HiddenGold 半段砍）+ a12 §13.1 派生顺序 + 勘探报告 §11.5 build_normative_projections_for_world 主 pipeline + W0 规格 09 §1.2 / §3。

## 4. `execute_projection_batch_v2`（W2 phase 4 主入口）

| 项 | 规格 |
|---|---|
| 输入 | `building_worlds_path: Path`（v2 building-centric JSON 或 parquet 目录）+ `normative_projection_path: Path`（per-fragment NormativeProjection v2 JSON / parquet）+ `sidecar_runtime_path: Path`（v2 sidecar_runtime JSON / parquet）+ `output_dir: Path` |
| 输出 | 三件套字典 — `{summary_path: Path, results_path: Path, samples_path: Path}` 对应 `RegulationProjectionSummary.v2.json` + `RegulationProjectionResults.v2.parquet` + `RegulationProjectionSamples.v2.json` |
| 边界条件 | 三类 v2 输入路径必须可读 + 输入文件 schema 版本必须是 v2（v1 不兼容，OLD execute_projection_batch 已删）+ output_dir 必须可写 |
| 公式 | **8 类 counter 聚合**（per-batch）：<br/>(1) `verdict_counter`（projection_status 作 verdict proxy — `covered / uncovered / conflict / unknown`）；<br/>(2) `family_hit_counter`（selected_family 出现频次）；<br/>(3) `family_status_breakdown`（family × projection_status 二维 dict）；<br/>(4) `unknown_reason_counter`（13 unknown_reason_code 计数）；<br/>(5) `severity_band_counter`（5 档 + unknown）；<br/>(6) `coverage_status_counter`（`world_core_ready` / `unsupported` / unknown）；<br/>(7) `threshold_regime_counter`（5-bin + not_numeric）；<br/>(8) `threshold_pass_counter`（pass / fail）<br/>+ sidecar join status counter（available / partial / unavailable） |
| Reject (P0) | 输入 schema 版本不一致 / parquet 写入失败 / 三类 v2 输入 building_id 不匹配（如 normative_projection 含 fragment 但 building_worlds 无对应 world_id）|
| Repair | 无（batch 聚合 P0 reject 后停 — 单 fragment 评估异常已在 phase 3 处理）|

**注**：phase 4 输出 parquet schema 由 W0 规格 15 定义（W2 不重写）；output_dir / 总体文件名按 v2 命名约定（`RegulationProjection<Summary/Results/Samples>.v2.<ext>`）。

**来源**：W0 规格 15 parquet schema + W0 规格 06 §16.3 batch level unknown_reason 聚合 + 勘探报告 §11.6 execute_projection_batch_v2 段。

## 5. `evaluate_fragment_projection_candidates`（H1，公开 helper）

| 项 | 规格 |
|---|---|
| 输入 | `fragment_id: str` + `candidate_families: List[Dict]`（每项含 `family_id` / `applicability_score` / `target_component_id` / `required_slots_present`）+ `conflict_group_id: Optional[str]`（来自 `normative_projection_registry.conflict_group`）+ `threshold_eval_inputs: List[Dict]`（每项含 `rule_id` / `slot_id` / `operator` / `threshold_value` / `observed_value` / `measurement_family` / `slot_unit` / `integer_compare`）+ `extra_unknown_context: Dict[str, bool]`（13 priority 条件位）|
| 输出 | dict — `{fragment_id: str, selected_family_ids: List[str], unknown_reason_code: Optional[str], threshold_evaluations: List[Dict], projection_status: str}` |
| 边界条件 | candidate_families 可空（空时直接走 unknown 路径返回 `no_known_family_match`）；threshold_eval_inputs 可空（空时 threshold_evaluations=[]，不算 unknown）|
| 公式 | **5 步 pipeline**：<br/>(1) H3 `resolve_family_conflict(candidate_families, conflict_group_id)` → `(selected_family_ids, conflict_reason)`；<br/>(2) 若 selected_family_ids 非空 + threshold_eval_inputs 非空，per input 调 H5 `build_threshold_evaluation` 构造 ThresholdEval；<br/>(3) 若 selected_family_ids 为空，构造 unknown context dict（`has_known_family_match` + conflict_reason 翻译 + extra_unknown_context 合并）；<br/>(4) H4 `derive_unknown_reason_code(context)` → reason_code；<br/>(5) projection_status = `covered` if selected_family_ids else `unknown` |
| Reject (P0) | 无（H1 总能返回有效结果 — empty candidate 走 unknown 兜底，非异常路径）|
| Repair (P3) | (a) conflict_reason=`multi_family_conflict` → 进 unknown context 由 H4 路由；(b) candidate_families 为空 → unknown_reason_code=`no_known_family_match`；(c) 其他 13 priority 条件按 extra_unknown_context 路由 |

**来源**：W0 规格 07 §4.2 多 family 竞争处理 + a12 §13.3 + 勘探报告 §11.6 evaluate_fragment_projection_candidates 段。

## 7. `resolve_family_conflict`（H3，公开 helper）

| 项 | 规格 |
|---|---|
| 输入 | `candidate_families: List[Dict]`（每项含 `family_id` / `applicability_score: float` / `target_component_id` / `required_slots_present: bool`）+ `conflict_group_id: Optional[str]` |
| 输出 | `(selected_family_ids: List[str], unknown_reason_code: Optional[str])` 元组 — selected 非空时 unknown_reason_code=None；selected 空时返回 reason_code |
| 边界条件 | candidate_families 可空（空时返回 `([], "no_known_family_match")`）|
| 公式 | 按 W0 规格 07 §4.2 5 种竞争处理逐行检查：<br/>(1) candidate 全空 → `([], "no_known_family_match")`；<br/>(2) `required_slots_present=True` 的 applicable 全空 → `([], "no_known_family_match")`；<br/>(3) 仅 1 个 applicable → `([family_id], None)`；<br/>(4) 多 applicable 且 target_component_id 全互异 + conflict_group ∈ `{drainage, ubw_fire, assessment_repair}` → allow multi-family；<br/>(5) 一个 family 是另一个的 strict parent → 选 child；<br/>(6) conflict_group=`structural_external_surface` → highest_applicability_score selector 选 1；<br/>(7) 其他兜底 → `([], "multi_family_conflict")` |
| Reject (P0) | 无（H3 总能返回有效元组）|
| Repair (P3) | 所有 unknown 路径都由该函数路由 reason_code（`no_known_family_match` / `multi_family_conflict`）|

**注**：4 个 conflict_group 的 selector 完整定义按 W0 规格 07 §4.1 conflict_group named entities 表（详见本包 `07_threshold_regime与冲突回退.md`）。

**来源**：W0 规格 07 §4.1 / §4.2 + a12 §11.5。

## 8. `derive_unknown_reason_code`（H4，公开 helper）

| 项 | 规格 |
|---|---|
| 输入 | `context: Dict[str, bool]` — 13 个 priority 触发条件位（按 W0 规格 06 §16.3 + W0 规格 07 §5）|
| 输出 | `Optional[str]` — 第一个满足 priority 的 reason_code 或 None（None 表示 family 已 covered，无 unknown 条件）|
| 边界条件 | context 可缺省任意 key（缺省视为 False，例外：`has_known_family_match` 缺省视为 True）|
| 公式 | **按 priority 顺序逐位检查**（13 条 priority 路由，按 specificity 由细到粗）：<br/>1. `multi_family_conflict`；<br/>2. `no_known_family_match`（`has_known_family_match=False` 触发）；<br/>3. `coverage_unimplemented_domain`；<br/>4. `binding_registry_gap`；<br/>5. `measurement_family_unimplemented`；<br/>6. `method_class_unimplemented`；<br/>7. `unsupported_material_system`；<br/>8. `unsupported_component_type`；<br/>9. `unsupported_damage_pattern`；<br/>10. `unsupported_location_context`；<br/>11. `unit_incompatible`；<br/>12. `projection_binding_incompatible`；<br/>13. `sidecar_only_fact_pattern` |
| Reject (P0) | 无 |
| Repair (P3) | 该函数本身是 P3 fallback 路由的主体；返回 reason_code 后由调用方写入 `NormativeProjection.unknown_reason_code` |

**封口注**：unknown reason code 固定 13 条；sidecar 不可用使用 `sidecar_only_fact_pattern`。

**来源**：W0 规格 06 §16.3 完整枚举 + W0 规格 07 §5 explicit unknown fallback + a12 §11.6 unknown_reason_code 派生。

## 9. `build_threshold_evaluation`（H5，公开 helper）

| 项 | 规格 |
|---|---|
| 输入 | `rule_id: str` + `slot_id: str` + `operator: str`（8 项 `<= / < / >= / > / == / != / in / not_in`）+ `threshold_value` + `observed_value` + `measurement_family: str` + `slot_unit: Optional[str]` + `integer_compare: bool` |
| 输出 | `ThresholdEval`-compatible dict — 含 `rule_id` / `slot_id` / `operator` / `threshold_value` / `observed_value` / `regime_tag`（5-bin + `not_numeric` 兜底）/ `pass_bool`（bool）|
| 边界条件 | operator 必须在 8 项枚举内 + observed_value / threshold_value 必须可类型对齐（数值通路要求双方 coerce 为 float；string 通路用作 fallback）|
| 公式 | (1) 调 H6 `compute_threshold_width(threshold_value, measurement_family, slot_unit)` → width；<br/>(2) 调 `classify_threshold_regime(observed, threshold, measurement_family, slot_unit, integer_compare)` → regime_tag（按 5-bin 分箱，详见本包 `07_threshold_regime与冲突回退.md` §1）；<br/>(3) 调 `_evaluate_threshold_operator(operator, observed, threshold, integer_compare)` → pass_bool；<br/>(4) 构造 dict 返回 |
| Reject (P0) | operator 不在 8 项枚举 / measurement_family 不在 W0 measurement_family 体系（5-bin 评估走 not_numeric 兜底，非 reject）|
| Repair | 无（评估期不修；regime / pass 由 fallback 函数兜底）|

**关键不变量**：`regime_tag` 跟 `pass_bool` **是两套独立维度** — regime_tag 描述测量值相对阈值的位置（5-bin + not_numeric），pass_bool 描述测量值是否通过 operator 检验；同一 `near_below` 在 `<=` 是 pass、在 `>=` 是 fail。

**来源**：a12 §11.1 / §11.3 + W0 规格 04 §20 ThresholdEval 字段合约 + 勘探报告 §11.3 build_threshold_evaluation 段。

## 10. `compute_threshold_width`（H6，公开 helper）

| 项 | 规格 |
|---|---|
| 输入 | `threshold: float` + `measurement_family: str` + `slot_unit: Optional[str]` |
| 输出 | `float` — width 浮点值；fallback 兜底 0 |
| 边界条件 | threshold 必须可 coerce 为 float（否则返回 0）+ measurement_family / slot_unit 至少一个可路由（否则兜底 0）|
| 公式 | **路由优先级**：<br/>(1) family 表 hit：按 measurement_family 路由（`geometry_length / width / depth` / `geometry_area` / `ratio` / `count` / `rate` / `stress` / `bool` / `enum`）— 每 family 对应 `max(abs_min, rel * threshold)` 公式（详见本包 `07_threshold_regime与冲突回退.md` §1.2 width 公式表）；<br/>(2) fallback：family 表 miss 时按 `slot_unit` 推断（`mm` / `m` / `m2` / `ratio` / `N_per_mm2` / `count` / `count/25m2` 等）；<br/>(3) 兜底：上两步全 miss 返回 0 |
| Reject (P0) | 无（兜底 0 不算 reject）|
| Repair | 无 |

**注**：family 表 + unit fallback 两套体系经 `compute_threshold_width` 单一路由 — family 表为权威主路径，unit fallback 解决 measurement_family 命名差异问题。

**来源**：a12 §11.2 width 参数规则 + 勘探报告 §11.3 compute_threshold_width 段。

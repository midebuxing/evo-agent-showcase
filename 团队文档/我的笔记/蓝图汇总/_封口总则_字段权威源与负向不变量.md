# 封口总则：字段权威源、跨包依赖与负向不变量

状态：W0 / W1 / W2 数据生成层封口版。

本文件是 W0 静态资源层、W1 实例生成流程层、W2 法规映射层三包之间的权威源总索引。它不新增业务规则；它只规定：同一字段 / enum / 红线 / 旧蓝图偏离在三包之间以谁为准，哪些概念不得再进入正式 spec。

## 1. 封口口径

W0 / W1 / W2 三包共同定义“数据生成层”：

- W0 定义静态资源、registry、schema、measurement / sidecar contract 与实例对象字段。
- W1 使用 W0 资源生成具体 `WorldBundle` / `SidecarRuntimeBundle`，并保持 rule-blind。
- W2 消费 W0 / W1 输出与 rule_card v2 bundle，生成 per-fragment `NormativeProjection` 与 batch 级法规映射输出。

对外汇报时，数据生成层可以表述为：

> 数据生成层已完成 W0 静态资源、W1 worldgen、W2 法规映射三包封口；W2 只给出训练 / 评测用法规映射参考真值，不替代人类巡检员作最终决定。后续 evo-agent 只消费已采样输出，不反推 W2 内部 evaluator 配置。

## 3. 字段与 enum 单点权威表

| 字段 / enum | 包归属 | 正式取值 / 形态 | 封口说明 |
|---|---|---|---|
| `registry_count` | W0 | 19 | 19 张物理 registry；`normative_projection_registry` 虽由 W2 定义 records 语义，但仍在 W0 registry bundle 中被编排加载 |
| `normative_projection_registry` | W2 语义 / W0 编排 | 11 字段 schema | W0 可列为 registry，但 records source-of-truth 与 projection binding 由 W2 06 管 |
| `unknown_reason_code` | W2 | 13 条 | 不新增第 14 条；sidecar 派生异常并入 `sidecar_only_fact_pattern` 语义兜底 |
| `sidecar_join_status` | W2 | `available` / `partial` / `unavailable` | `sidecar_derivation_failed` 不得出现 |
| `ProjectionFamilyEval.verdict` | W2 | `pass` / `fail` / `unknown` / `not_applicable` | `pending` 不属于当前数据生成层输出 enum |
| `NormativeProjection.expected_verdict` | W2 | `pass` / `fail` / `unknown` / `not_applicable` | per-fragment reference truth；不是最终人工决定 |
| `projection_status` | W2 | `covered` / `uncovered` / `conflict` | family 覆盖状态；不得与 `expected_verdict` 混用 |
| `coverage_status` | W2 | `world_core_ready` / `unsupported` | 世界端核心 slot 到位状态；不得替代 projection verdict |
| `regime_tag` | W2 | `far_below` / `near_below` / `exact_threshold` / `near_above` / `far_above` / `not_numeric` | 位置标签，与 `pass_bool` 正交 |
| `basis_kind` | W2 | `threshold_compare` / `bool_assertion` / `family_uncovered` / `world_origin` / `measurement_origin` | HiddenGold 删除后，basis_items 是 projection 可追溯性的唯一正式结构 |
| `CoverageControlBatchMetadata` | W2 | batch 级 audit metadata | 不写入 `NormativeProjection`；不作为 evo-agent feature；不反馈 W1 规则原因 |
| `fact_source_kind` | W0 / W1 输出 provenance | 当前包固定 `synthetic_worldgen` | 未来 3DGS 是另一事实源，不在当前封口包内静默混入 |

## 4. 跨包单向依赖矩阵

| 方向 | 允许 | 禁止 |
|---|---|---|
| W1 → W0 | W1 读取 W0 registry / schema / formula / constraint / sidecar contract | W1 修改 W0 registry；W1 用法规阈值反推 W0 分布 |
| W0 / W1 → rule_card | W0 / W1 不读 rule_card | W1 worldgen 读取 rule_card threshold / family / rule_id 来调世界生成参数 |
| W2 → W0 | W2 读取 W0 canonical slot / registry / measurement / sidecar contract | W2 反写 W0 registry；W2 改 W0 formula / distribution |
| W2 → W1 | W2 读取 W1 已生成的 `WorldBundle` / `SidecarRuntimeBundle` 具体输出 | W2 写回 W1 输出；W2 读取 W1 内部 distribution 参数、recommended_mean、surrogate 中间变量、生成 seed 策略 |
| W2 → rule_card v2 | W2 通过 manifest + 13 sub-file + runtime mapping 消费 rule_card | W2 复写 rule_card v2 数据规格；W2 在 spec 中复制 rule_card 全量字段规范 |
| W2 → evo-agent | evo-agent 后续只消费已采样的具体 W2 输出 | evo-agent 看到 W2 evaluator 内部配置、threshold width 公式参数、unknown reason priority、conflict selector 内部权重、coverage control target ratio |
| Coverage control → W1 | W2 可在采样侧丢弃 candidate；外层编排可请求重新抽取一个世界 / fragment | W2 不得把 near-threshold、neighbor-family、recoverable-missing、family_id、threshold regime、unknown reason 作为调参信号传回 W1 |
| 数据层 → Closure Verifier / 人类巡检 | W2 输出 reference truth 与 basis_items，供后续 verifier / 人类审查使用 | W2 不得输出 `final_decision`，不得把 AI 判定包装成人类巡检最终决定 |

## 5. 负向不变量 / 红线矩阵

| ID | 不变量 | 违反形态 |
|---|---|---|
| NI-001 | rule-blind 只约束 W0/W1 worldgen；W1 不读 rule_card 反推世界 | W1 用法规阈值、rule_id、family coverage 目标调采样分布 |
| NI-002 | W2 只读 W1 具体输出，不反写 W1 | W2 修改 `WorldBundle` / `SidecarRuntimeBundle`，或把 reject 原因传给 W1 调参 |
| NI-003 | W2 不读 W1 内部派生过程 | W2 读取 distribution 参数、surrogate 中间变量、recommended_mean、typical_bounds、physical_bounds、mean_semantics |
| NI-004 | evo-agent-blind | 将 W2 evaluator 配置参数、priority、threshold width、conflict selector 内部细节作为 evo-agent 可见输入 |
| NI-005 | rule_card 独立责任域 | W2 spec 复写 rule_card v2 schema 或把 rule_card 字段定义搬进 W2 当权威 |
| NI-006 | 16 family 甲方案不可简化 | 用 9 family coverage baseline 或 13 entry simplified routing 替代 16 family baseline |
| NI-007 | 巡检员模拟全砍 | `HiddenGold` / `AdjudicationState` / `ObservationState` / `QueryEpisode` / `GoldLabeler` 任一对象进入正式字段、流程或输出 |
| NI-008 | 当前输出无 `pending` | `ProjectionFamilyEval.verdict` 或 `expected_verdict` 输出 `pending` |
| NI-009 | 无 `sidecar_derivation_failed` | 将其作为 reason code、sidecar status、basis kind、fallback enum、字段名或占位值输出 |
| NI-010 | 字段权威源单点 | W0 与 W2 同时维护 `NormativeProjection` 字段表，且字段不一致 |
| NI-011 | spec 正文不承载 code/test/DEBT 状态 | “当前代码未实现”“import audit”“实现缺口”“工单解除路径”作为正式 spec 内容 |
| NI-012 | 无 domain-expert pending 权威 | `DEBT021_pending` 或“等 domain expert 复核后才权威”出现在封口正文 |
| NI-013 | AI 不替代人类巡检员 | 输出 `final_decision`、`human_decision`，或把 `expected_verdict` 描述为最终合规判断 |
| NI-014 | 3DGS 不静默混入 | 未标 provenance 地把 3DGS 事实源和 W1 synthetic worldgen 输出混成同一字段来源 |
| NI-015 | 旧蓝图偏离必须标授权 | 删除 / 改写旧蓝图结构但不写保留或偏离依据 |

## 6. 删除 / 退役对象黑名单

| 名称 | 状态 | 替代结构 |
|---|---|---|
| `HiddenGold` | 删除 | `NormativeProjection` + `basis_items` + `expected_verdict` |
| `AdjudicationState` | 删除 | 不在数据生成层建模 |
| `ObservationState` | 删除 | 不在数据生成层建模 |
| `QueryEpisode` | 删除 | 不在数据生成层建模 |
| `GoldLabeler` | 删除 | 不在数据生成层建模 |
| `sidecar_missing` | 删除 | sidecar 缺 / 不可用归入 `sidecar_join_status` + `unknown_reason_code` |
| `sidecar_derivation_failed` | 撤回 | `sidecar_join_status=unavailable` 或 `partial`；原因用 `unknown_reason_code=sidecar_only_fact_pattern` |
| `pending` verdict | 当前输出禁用 | 若未来 obligation chain 另立规格，必须另建版本，不污染本封口版 |
| `final_decision` | 禁止 | 后续 Closure Verifier / 人类巡检流程处理；W2 只出 reference truth |

## 8. 3DGS / 双源事实源口径

当前 W0 / W1 / W2 封口包的事实源是 `synthetic_worldgen`。未来 3DGS 数字孪生数据回来后，可作为另一事实源进入更上层双源 KG-RAG / fact ingestion，但不得静默改写当前 W1 synthetic worldgen 字段含义。

当前封口版只要求：凡对外导出的数据样本必须能标识 fact source provenance；当前包内统一为 `synthetic_worldgen`。

## 9. 正式 spec 正文禁入项

以下内容可保留在历史笔记、工程跟踪表或非正式备忘，但不得作为封口 spec 正文：

- 当前代码是否实现、哪一行代码缺字段、import audit、grep 结果、工单解除路径。
- 测试计划、实施进度、工程排期。
- DEBT 编号作为必须解除的 spec 条件。
- “等待 domain expert 才能权威”的措辞。
- “W2 待建 / 正在建立 / 框架建立中”的状态措辞。

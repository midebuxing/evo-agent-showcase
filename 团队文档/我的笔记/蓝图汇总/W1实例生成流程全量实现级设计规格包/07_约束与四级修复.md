# 约束与四级修复（P0/P1/P2/P3）

> 跨包权威源与负向不变量见：`../_封口总则_字段权威源与负向不变量.md`。如本章与总则冲突，以总则和字段所属包权威章节为准。


W1 实例生成流程中的约束验证 + 修复优先级体系。本节是 W0 spec 07 §1 + a12 §9 在 W1 阶段的合约整理。

## 1. P0/P1/P2/P3 优先级体系

按 a12 §9 + W0 spec 07 §1：

| 优先级 | 名称 | 含义 | 触发动作 | W1 阶段 |
|---|---|---|---|---|
| **P0** | `reject_or_resample` | 逻辑性错误，不可修复（无钢筋出露筋、几何矛盾、graph cycle、incompatible material 等）| 直接 reject 当前实例，重采或丢弃 | Step 1-8 任一段命中 P0 → 整次生成丢弃 |
| **P1** | `repair_world_truth_geometry_or_state` | 世界真相数值轻微越界（extent 超 fragment area、severity > 1.0 等）| 修世界真相（clamp 几何到合法区间 / 重算 flag）| Step 1-9 任一段命中 P1 → 修后继续 |
| **P2** | `repair_measurement_rounding_or_bounds` | measurement 数值需 rounding / clamp 到 unit bounds（ratio > 1 / count 负数 / unit precision）| 修测量数值（round / clamp）| Step 6-8 measurement family 命中 P2 → 修后继续 |
| **P3** | `projection_fallback_to_unknown_or_not_applicable` | 多变量耦合冲突（无法修复）+ 法规映射层 unable to cover | projection fallback `unknown` / `not_applicable` | **属 法规映射层，不在 W1 范围** |

## 2. W1 约束分类

按约束触发位置：

### 2.1 Schema-level 约束（Step 1 build 时）

- registry primary_key 唯一性
- registry cross-reference 完整性（component_type 必须在 component_type_registry、material 必须在 material_system_registry 等，详见 W0 spec 03 §3 跨表引用）
- fragment_template 必须引用合法 building_template_id（W0 `building_template_registry` 含 T-30 引入的 15 个 HK archetype 主键，详见 W0 spec 03 §4.8）

### 2.2 Physical-level 约束（Step 2-5 condition / domain state 派生时）

- material-mechanism 兼容（无钢筋构件不生成 corrosion_spall mechanism）
- component-mechanism 兼容（fire_door 只生成 fire_safety_deficiency；drainage_stack 只生成 drainage_fault）
- condition extent ≤ fragment geometry
- mechanism severity `[0, 1]`

### 2.3 Measurement-level 约束（Step 6-8 measurement 派生时）

- ratio `[0, 1]`
- count `≥ 0`
- area `≥ 0`，且 ≤ fragment_area
- length `≥ 0`
- 计算输入字段非空（DEBT-010 / DEBT-011 closure：fragment_template_id / component_type_id 缺时输出 `not_applicable` 不 silently drop）

### 2.4 Derived-flag 约束（Step 9 派生 flag 时）

- derived flag 引用的 risk / repair / verification 输入必须在 registry 中注册
- contradictory flags（按 W0 spec 06 §11.X 推导矛盾对清单 7 对，如 `repair.required=true` AND `repair.outcome.safe_until_next_cycle=true` / `safe_until_next_cycle=true` AND `verification_test_failed=true` / `maintenance=true` AND `risk_emergency=true` 等）→ Step 9 重算

详见 `04_函数实现规格卡.md` §1-§9 每段卡片的 "Reject (P0)" / "Repair (P1/P2)" 字段。

## 4. 修复原则

按 a8 §4 "局部修复 + 拒收"原则：

- **修的是"靠近可行域"的状态，不是修世界逻辑**
- 多变量耦合冲突（如 corrosion 严重度跟 cover_depth + chloride 同时矛盾）：**优先回到机理层重算**，不直接硬改末端 measurement
- 不允许 silent 修复：每次修复必须 audit trace，按 priority 分 granularity：
  - **P1 修复**：per-action detail — `check_id / before / after / fragment_id`，写入 `GateResult.repair_actions` + `BatchGateStats.repair_action_counts`。便于单 instance debug
  - **P2 修复**：aggregate summary — per `check_id` 含 `count / max_magnitude / mean_magnitude` + 前 **K=20** 个代表性 sample detail（含 `slot_id / fragment_id / before / after`）；超 K 后只增 count + 累积 max/mean magnitude。写入 `BatchGateStats.p2_clamp_summaries: Dict[check_id, P2ClampSummary]`
  - **P2 audit 范围边界**：
    - ✅ **覆盖**：W0 spec 06 §11.5 **Path A**（recommended_distribution 完备时）的 `typical_bounds clip` + `physical_bounds clip` + precision rounding + count nonneg clamp — DEBT-026 closure 主路径
    - ❌ **不覆盖**：W0 spec 06 §11.5 **Path B**（typical 字段缺失 fallback）的 named noise model 内部 clip — 理由：Path B 是 backstop，DEBT-026 落地后基本不命中；slot_id 上下文在 noise model 层已丢失，强加 audit 工程成本高 vs 价值低
    - ❌ **不覆盖**：sidecar 派生层 prior 输入 sanitize（如 prevalence clip）— 按 spec 边界这不算 measurement-level P2 修复（属 hidden state 派生预处理）
  - **Caller wrap 责任**：P2 audit 用 contextvars accumulator 实现，**caller 必须显式 wrap `audit_capture()` context manager 才能收到 audit**。`generate_world_batch_with_stats` 已自动 wrap；`generate_world_bundle` 单独调用 + 任何绕过 batch 入口的路径**caller 自己责任** wrap（否则 P2 修复 silently 不记 — 由 docstring warning 提示，不 raise）
  - **Granularity 分级理由**：P1 是事后 check 触发的稀疏事件 + 修世界真相（per-action detail 必要）；P2 是 generation-time inline clip + 修 measurement 数值（触发可能频繁，aggregate summary + bounded sample 已 cover 99% audit trace 目标 — 调试 / 频率分析 / 合规审计 — 剩 1% 罕见 outlier 场景按需升级到 full detail，架构不冲突）
- P0 reject 不允许 silent skip：必须计入 batch_stats（DEBT-022 P1 repair 性能 trace 同源）

## 5. P3 不在 W1

P3 projection fallback `unknown` / `not_applicable` **属 法规映射层**：

- spec 06 §11.X derived flag table 已经为每个 derived flag 定义 unknown_policy（"no scope target → not_applicable" 等）
- 法规映射层 projection executor 在 Step 10 按 unknown_policy 触发 fallback
- W1 阶段**不应该**在 worldgen 内部输出 `not_applicable` 字段（这是 projection 层语义）

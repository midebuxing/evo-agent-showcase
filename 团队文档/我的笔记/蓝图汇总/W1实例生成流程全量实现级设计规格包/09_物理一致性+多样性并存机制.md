W1 实例生成流程层在保证物理一致性的同时如何长出多样性。本节是 a8 §4 "如何保证物理一致性与多样性并存" 在 W1 阶段的合约整理 + 与 a9 §5 反作弊机制的桥接。

| # | 机制 | 含义 | 在 W1 对应 |
|---|---|---|---|
| 一 | **分层因果采样** | "上下文 → 驱动 → 机理 → 损伤 → 测量" 作为硬骨架；结果不是独立 slot 拼出来的 | W1 Step 1-8 严格按 fragment → driver → mechanism → condition → measurement 五层串行（详见 `05_依赖图.md` §1）|

## 2. 一致性来源 vs 多样性来源

按 a8 §4 line 249-252：

| 维度 | 来源 |
|---|---|
| **一致性** | causal（五层因果链单向）+ constraints（hard schema + physical bounds + P0 reject）|
| **多样性** | fragment 模板（17 个 fragment_template）+ driver 组合（多 driver 同 fragment 多激活）+ 多机理耦合（同 fragment 多 condition / multi-DC overlay）+ ~~observation mask + counterfactual pairs~~（注：observation / counterfactual 属 法规映射层 / evo-agent 训练侧，不在 W1）|

W1 多样性具体来源：

- **archetype 多样**：15 个 BT_HK_* 主键 × 多个 archetype 复用（T-30 落地 2026-05-12 引入；entry 全表见 W0 spec 03 §4.8 + 11_inventory §1.X）
- **driver 多样**：每个 archetype 多 driver 组合（外部环境 + 建材老化 + 维护历史 + 改装等）
- **mechanism 耦合**：同一 fragment 多 mechanism 同时激活（crack + spall_rebar 共现 / corrosion + chloride_diffusion 共现）
- **measurement 噪声**：truncated normal + 三档 precision rounding（`06_测量噪声三层合约.md`）
- **sidecar 双路径**：sidecar bool / categorical 走 marginal prevalence + conditional formula 双路径派生（spec 09 §1.2 / spec 06 §11.6）

## 5. 多样性 vs 一致性失衡的两种典型场景

按 a8 §4 + a12 §10 失衡风险：

### 5.1 一致性过强 → 多样性不足（lock-in 风险）

**症状**：所有 archetype 的 condition 分布高度相似；measurement 落在窄区间；evo-agent 看不到边界 case。

**根因**：
- driver 组合过少 → 同 fragment 总是激活相同 mechanism set
- noise sigma 设得太小 → measurement 集中在 mean 附近
- typical_bounds 区间过窄 → 5%/95% 区间没拉开

**修法**：
- 增加 driver 组合（DEBT-020 Round 4 marginal prevalence 已经在做）
- 校准 recommended_sigma（DEBT-026 Round 7 已落地工程现实分布参数）
- 拓宽 typical_bounds（DEBT-026 Round 7）

### 5.2 多样性过强 → 一致性破坏（不真实 risk）

**症状**：condition 出现在不该出现的 component 上（spall on non-RC）；measurement 落到 unphysical 区间（fsp > 2.0 / ratio > 1.0）；mechanism / condition / measurement 之间相互矛盾。

**根因**：
- hard constraints 缺失或失效
- P0 reject 不触发（silent 修复 / 配置错误）
- 公式 surrogate 输入字段被 silently drop

**修法**：
- 补 hard constraint 到 schema / physical 约束层（详见 `07_约束与四级修复.md` §2.1-2.2）
- 加强 P0 reject log + batch_stats 计数（DEBT-022 P1 repair trace 同源）
- 修复 DEBT-010 / DEBT-011 类（公式输入缺时输出 `not_applicable` 不 silently drop）

## 6. 与 evo-agent 训练侧的耦合点

W1 worldgen 输出对 evo-agent 训练的影响（详见 `00_范围与过滤决策.md` §2）：

- W1 输出 = WorldBundle + SidecarRuntimeBundle（rule-blind）
- 法规映射层 projection 投影到 rule_card → projection_output（含 trigger / regime / coverage 等）
- evo-agent 训练侧消费 W1 + 法规映射层 projection 输出，做 counterfactual / family-holdout / near-threshold 训练样本采样

W1 阶段**只需保证 rule-blind 输出物理真实 + 分布合理**，不需直接接触 evo-agent 训练逻辑。封口版通过本章与 `10_禁止依赖.md` 固化 W1 / W2 / evo-agent 三层之间的硬断开。

## Coverage-controlled rejection 与 W1 的边界

coverage-controlled rejection 属 W2 采样侧，不属于 W1 worldgen。

W1 的多样性来源只能来自 W0/W1 授权的 fragment 模板、driver 组合、多机理耦合、物理噪声与 sidecar 派生；不得来自 W2 family / threshold / near-threshold / unknown reason / coverage bucket 的反向调参。

W2 可以在自身采样侧丢弃一个 candidate world / fragment 的 projection 输出。若外层编排需要重新抽取样本，传给 W1 的只能是通用重新生成请求，不得携带以下内容：

- near-threshold / neighbor-family / recoverable-missing 标签
- `projection_family` / `conflict_group`
- `regime_tag` / threshold width / threshold value
- `unknown_reason_code`
- rule_card id / rule id / family coverage target

因此，W1 始终保持 rule-blind；W2 的 coverage control 只影响 W2 采样侧 accept/reject，不把法规侧信息写回世界生成层.

## 1. W1 的定位

W1 是 `WorldGenerator` 的**实例生成流程层**，位于 W0 静态资源层之后、法规映射层之前。

W1 职责：

1. 消费 W0 资源（registry / formula / surrogate / constraint / sidecar contract）；
2. 按建筑 archetype + driver 采样，**生成具体 `WorldBundle` 实例**（building / component / location / fragment / driver / mechanism / condition / damage 等楼宇物理事实）；
3. 派生 measurement records（geometry / coverage / technical validation / assessment）；
4. 跑约束验证 + P0/P1/P2 修复；
5. 派生 risk / repair / verification / assessment flags；
6. 由 sidecar 派生层生成 `SidecarRuntimeBundle`（行政过程 / 历史合规 B 类事实，按 W0 spec 09 §1.2 双路径派生）。

W1 不做：

- **法规映射 / projection 编译**（属 法规映射层，见 spec 05 §1 第 6-7 步）；
- HiddenGold / Observation / QueryEpisode / Adjudication / inspector simulation（已删）；
- benchmark gold / runtime trace / skill evaluation（已删）；
- 反向读取 rule_card threshold / family / gold（rule-blind 红线）。

## 2. 主设计原则：分层结构因果生成

W1 的**核心生成范式**是**分层结构因果生成**，不是"末端值直接采样 + 后期约束修复"：

```
FragmentContext
    ↓ 条件采样
DriverState （隐含驱动：z_load / z_restraint / z_durability / z_age / z_workmanship / z_maintenance / z_event）
    ↓ 机理激活 + 严重度
MechanismState （m_load_crack / m_restraint_crack / m_corrosion / m_delam_spall / m_local_event）
    ↓ 几何 / 拓扑物化
ConditionState (含 DamageState 几何信息)
    ↓ surrogate 公式派生
MeasurementRecord （crack_width_mm / spall_area_m2 / rebar_exposed_length_m 等）
```

**严格的因果向下**：

- `x_f ~ P(fragment template)`
- `z ~ P(driver | x_f)`
- `a_m ~ Bernoulli(sigmoid(f_m(x_f, z)))` — 机理激活
- `s_m ~ Truncated(g_m(x_f, z), bounds_m)` — 机理严重度
- `d = H(x_f, {a_m, s_m})` — damage / condition 几何
- `y = Q(d, x_f) + bounded noise` — measurement 派生

**禁止跳层**：

- 禁止 `crack_width_mm ~ Uniform(0, 5)` 等 measurement primitive 直接抽
- 禁止跳过 mechanism 直接给 damage geometry
- 禁止从 measurement 反推 mechanism

### 2.1 五层因果模型详述

#### 2.1.1 FragmentContext（起点）

至少包含：构件类型 / 材料系统 / 位置与暴露 / 结构属性 / 构造代理量。

W1 实例生成的入口对象。每个 building 实例化多个 fragment（按 building archetype 的 fragment template 配置）。

#### 2.1.2 DriverState（隐含驱动层）

**7 类 latent factors**（最小保留）：

| Driver | 物理意义 |
|---|---|
| `z_load` | 荷载需求比 / 使用应力水平 |
| `z_restraint` | 收缩 / 温差 / 约束不相容 |
| `z_durability` | 湿度 / 氯盐 / 碳化 / 渗水 / 干湿循环 |
| `z_age` | 有效龄期 / 累积暴露时间 |
| `z_workmanship` | 施工与细部质量 |
| `z_maintenance` | 维护 / 修复 / 保护状态 |
| `z_event` | 冲击 / 施工扰动 / 局部破坏事件 |

#### 2.1.3 MechanismState（损伤机理层）

机理是 defect 的**父节点**，不是 defect 彼此独立抽样。

至少 5 类模块：

| Mechanism | 物理意义 |
|---|---|
| `m_load_crack` | 荷载 / 受力裂缝 |
| `m_restraint_crack` | 收缩 / 温差 / 约束裂缝 |
| `m_corrosion` | 钢筋腐蚀 / 体积膨胀 |
| `m_delam_spall` | 保护层开裂 / 空鼓 / 剥落 / 掉角 |
| `m_local_event` | 冲击或局部偶发损伤 |

W1 应支持 extension domain 的 mechanism（drainage_fault / ubw_alteration / fire_safety_deficiency 等），机理一律走 `mechanism_library_registry` 注册。

#### 2.1.4 ConditionState / DamageState（缺陷几何 / 拓扑层）

包含：

- 裂缝是否存在 / 位置 / 方向 / 长度 / 连通性 / 开口潜变量；
- 保护层分离区 / 剥落斑块的面积 / 深度 / 边界；
- 保护层损失深度；
- 外露钢筋的长度 / 根数 / 位置；
- 伴随现象：锈蚀迹象 / 渗水痕迹 / 空鼓等。

#### 2.1.5 MeasurementRecord（测量值层）

所有 measurement 值都是 ConditionState / DamageState 的**下游派生**，不是 primitive：

```
crack_width_mm = φ(load, restraint, corrosion_expansion, local_stiffness, crack_geometry)
spall_area_m2 = ψ(corrosion_severity, cover_depth, bar_layout, patch_geometry)
rebar_exposed_bool = 1[spall_or_cover_loss exceeds cover and reinforcement exists]
```

具体 measurement surrogate 公式见 W0 spec 06 §1-§10。

## 3. 物理一致性 + 多样性并存的五件保障

W1 实施级原则：单技术不足以同时保障物理一致性 + 多样性，**5 件事必须同时上**。

### 3.1 分层因果采样（已含 §2）

让"上下文 → 驱动 → 机理 → 损伤 → 测量"成为硬骨架。这保证结果不是独立 slot 拼出来的。

### 3.2 机理 surrogate 库

每个机理只做**低阶、可解释、可校准**的 surrogate，**不做高保真仿真**。

W1 当前最小可用 surrogate（详细公式见 W0 spec 06）：

- corrosion progression surrogate
- crack opening surrogate
- spall / cover-loss surrogate
- drainage fault surrogate
- UBW alteration surrogate
- fire-safety deficiency surrogate
- structural assessment surrogate (FSP)

这比 FEA / BIM 轻量得多，但比"手写 measurement primitive 数字"强得多。

### 3.3 Hard constraints + Soft priors

| 类型 | 内容 | 例 |
|---|---|---|
| **Hard constraints** | 不可能组合 / 几何上限 / 因果顺序 | 无钢筋构件不应生成"外露钢筋"；`spall_area > 0` 必须伴随剥落存在；component-material 兼容（spec C004）|
| **Soft priors** | 常见共现 / 分布相关性 / 不同 fragment 经验频率 | DEBT-020 的 typical distribution + recommended_mean/sigma；fragment_template 的 typical area_range |

Hard 保真，Soft 保像真。

### 3.4 局部修复 + 拒收

按 P0/P1/P2/P3 优先级（详见 W1 spec 07）：

| 优先级 | 触发情况 | 动作 |
|---|---|---|
| **P0 reject_or_resample** | **逻辑性错误**（无钢筋出露筋、几何矛盾、graph cycle）| 直接 reject 重采，整次生成丢弃 |
| **P1 repair_world_truth** | **几何 / state 数值轻微越界** | project 回可行域（clamp / rebuild flag）|
| **P2 repair_measurement** | **measurement 数值 rounding / clamp**| round / clamp 到 unit bounds |
| **P3 projection_fallback** | **多变量耦合冲突（无法修） + 法规映射层无法 cover**| projection 层 fallback `unknown` / `not_applicable`（属 法规映射层，W1 不处理）|

**优先级原则**：修的是"靠近可行域"的状态，不是修世界逻辑。多变量耦合冲突优先回到机理层重算，不要直接硬改末端 measurement。

### 3.5 Coverage-controlled rejection（不在 W1 范围）

a8 §4 第五件"coverage-controlled rejection"是**采样层控制**（按 5-bin regime / neighbor-family / recoverable missing 过采），不是世界生成逻辑。**属 法规映射层 + evo-agent 训练侧采样器，不在 W1 范围**（W1 不读 rule_card 不知 family 边界，无从过采）。

详见 `09_物理一致性+多样性并存机制.md` §1 第五件 + §6 evo-agent 训练侧耦合点。

> **巡检员模拟相关 over-sampling 已删**：原 a8 §4 第五件含"observation mask coverage" 已废止（按用户原则砍掉 observation/QueryEpisode）。

## 4. 三层接口边界（W1 输出契约）

W1 输出对象 schema + 字段合约见 **W0 spec 04 §1.1**（BuildingContext / ComponentNode / LocationNode / FragmentContext / CoverageRelation / DriverState / MechanismState / ConditionState / DrainageState / UBWState / FireSafetyState / RepairAssessmentState / MeasurementRecord）+ **W0 spec 09 §1.2**（sidecar 边界契约）。

W1 输出**只产出** `WorldBundle` + `SidecarRuntimeBundle`，**绝不产出**：`rule_family_id` / `trigger_id` / `threshold_regime value` / `gold_route` / `missing_slots`（按 observation 层定义的）/ `acceptable_next_questions` / `HiddenGold`。

法规映射层**只消费** W1 输出（+ W0 资源 + projection_registry），W1 **不消费** 法规映射层 的输出 — 严格单向（继承 W0 spec 01 §2 边界表 + a8 §6 三层接口主设计）。

## 5. Rule-blind 在 W1 的具体应用

W1 严格继承 W0 spec 01 §1.1（操作判据 + A/B 类）+ §1.1.1（4 层分布校准）。本节只列**W1 实例生成路径上的操作落地**，不重复原则。

| W1 生成路径 | rule-blind 落地 |
|---|---|
| Fragment 实例化 | fragment 选择按 building archetype + accessibility_prior；不按 rule_family 配比 |
| Driver 采样 | driver 范围按 fragment + age / exposure；不看 rule_card threshold |
| Mechanism 激活 | activation 公式只用 driver；不引 rule_card |
| Condition / Damage 派生 | mechanism + fragment 决定几何；不引 rule_card |
| Measurement 派生 | surrogate 只看 damage + fragment + driver；按 W0 spec 01 §1.1.1 Layer 2，采样输出不可反推 threshold value |
| Sidecar 派生 | 按 W0 spec 09 §1.2 双路径；prevalence 可参考法规分布形状但不直接 anchor threshold |

## 6. 反作弊 / 反泄漏机制（W1 输出审计红线）

W1 输出必须经过以下 audit（按 a9 §5 反作弊机制裁剪掉 observation/gold 相关后的剩余清单）：

| Audit | 验证目标 |
|---|---|
| **Schema firewall** | W1 输出对象 schema 不含任何 rule_family_id / threshold / gold / observation 字段 |
| **Projection-only rule use** | rule_card 只在 法规映射层消费 W1 输出，绝不在 W1 路径中读取 |
| **Round-trip parse check** | W1 输出 + 重读 → projection 结果一致（无 silent mutation）|
| **Leakage audit on surface** | W1 输出表层（measurement value / fragment surface tag）无法反推 rule_family / threshold value |
| **Counterfactual test** | 同 fragment + 不同 rule_card profile → W1 输出 byte-identical（DEBT-020 Audit2 trace）|
| **Held-out family / neighbor-family split** | 训练 / 评估 batch 按法规 family 分割时，W1 不应"看到"哪些 family 是 held-out |

具体 audit 落地清单见跟踪表 §6 DEBT-030 + §3 code 区。

## 7. W1 本体边界

W1 拥有的本体对象 + sidecar 边界详见 **W0 spec 04 §1.1**（13 个 world object）+ **W0 spec 09**（sidecar B 类本体）+ **W0 spec 11_inventory §7.2/§7.3**（sidecar_measurement / sidecar_bool 全 entry）。本节只列 W1 阶段的本体归属边界：

| 类别 | 本体 | 归属 |
|---|---|---|
| **W1 worldgen core 直接拥有**（写 `WorldBundle`）| Building / Component / Location / Fragment / Coverage / Driver / Mechanism / Condition / Damage / Drainage / UBW / FireSafety / Measurement / RepairAssessment / derived flags | W1 |
| **W1 sidecar 派生层拥有**（写 `SidecarRuntimeBundle`，按 W0 spec 09 §1.2 双路径）| procedure / supervision / artifact / qual / fire_safety.upgrade_outstanding / duration / interval | W1 |
| **W1 不拥有** | NormativeProjection / rule_card / family / threshold value | 法规映射层 / rule_card 系统 |
| **W1 不拥有（已删）** | ObservationState / QueryEpisode / AdjudicationState / HiddenGold | — |

## 8. W1 与 W0 / 法规映射层 / evo-agent 的边界

W0 / W1 / W2+ 边界主体见 **W0 spec 01 §2 边界表**。W1 端的具体边界：

| 边界 | 内容 |
|---|---|
| W0 → W1 | W1 消费 W0 资源；不修改 W0 资源；不绕过 W0 直接定义新 slot / 新 schema |
| W1 → 法规映射层 | W1 输出 `WorldBundle` + `SidecarRuntimeBundle`；法规映射层 只读不写；W1 不消费 法规映射层 的 `NormativeProjection` |
| W1 → evo-agent | W1 输出是 evo-agent 训练 / 评估的事实侧数据源；evo-agent 不可调 W1 内部 distribution 参数（按 W0 spec 01 §1.1.1 Layer 2，采样输出不可反推 threshold value）|

## 9. 不在 W1 范围的设计决策

按 a8 §8 + a9 §7.3 + 用户原则，以下明确**不属 W1**：

- 完整建筑物理模拟器 / BIM / 有限元（W1 用 fragment-level surrogate 不做高保真）
- 从法规直接反推世界（rule-blind 红线）
- 纯人工规则库 / 人工枚举 case
- 纯统计分布学习器（当前数据量 / 覆盖不够）
- 端到端 diffusion / world model（把世界生成 / 观测 / 问题 / 判题揉成一团，无审计性）
- 直接采样最终 measurement（按 §2.1.5 严格禁止）

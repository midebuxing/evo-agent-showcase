# W1 输入合约与 W0 依赖

W1 实例生成流程只消费 **W0 静态资源层** 资源 + **building archetype seed + config**。本文列出 W1 各 step 消费的 W0 资源清单 + 入口 + 字段契约 cross-ref。

## 1. 总入口

```text
W1 输入 = (archetype_id, seed, config, registries)
     │
     ▼
generate_world_bundle(archetype_id, seed, config, registries) → WorldBundle
     │
     ▼（sidecar 派生层并行运行，按 spec 09 §1.2 双路径）
build_sidecar_runtime(world_bundle, sidecar_contract) → SidecarRuntimeBundle
```

- `archetype_id`：W0 `building_template_registry` primary key（合规枚举 15 条，见 W0 spec 11_inventory §1.1）
- `seed`：确定性随机种子（worldgen 全栈用，保证 deterministic_key byte-identical）
- `config`：运行时配置（archetype_distribution / batch size 等，**不**包含 rule_family / threshold）
- `registries`：W0 19 张 registry bundle。W1 只消费其中与 worldgen / sidecar 派生相关的 W0-owned registry；`normative_projection_registry` 虽在 bundle 中存在，但 W1 不读取其 family / threshold / rule binding 语义。

**入口图的抽象层定位**：上面 `generate_world_bundle(archetype_id, seed, config, registries)` 是 **概念入口**——它描述 W1 在逻辑上"接受什么、产出什么"（单 archetype 输入 → 单 `WorldBundle` 输出），用于固定输入合约边界。实现层为性能可对外暴露 batch 化入口（如 `generate_world_batch` + `building_index` 等批处理设施），把多个 archetype 实例在一次调用内成批生成。概念入口与实现签名之间的抽象层差异（单实例语义 vs 批处理签名）属正常工程分层，不构成 spec ↔ code 冲突；只要实现层 batch 入口对每个 archetype 实例保持本章定义的输入合约与只读边界即可。

## 4. W1 不消费的 W0 资源

| W0 资源 | 不消费的原因 |
|---|---|
| `normative_projection_registry` | rule-blind 红线（W1 不读法规 family / threshold）|
| `threshold_regime_index` | 同上，由 法规映射层消费 |
| `slot_index` / `semantic_slot_registry` / `family_coverage_baseline` | 同上，rule_card 系统侧 |
| `controlled_vocabularies_v1.json` 中 `actor_role_key` enum | W1 不直接消费 vocab；sidecar 派生层用 W0 spec 02 §1 sidecar_bool_slot_registry 中 enum_values |



W1 不读取以下 W2 / rule_card 派生信号：

- `projection_family`
- `applicability_predicates`
- `threshold_regime` / `regime_tag`
- `unknown_reason_code`
- `coverage_control_bucket`
- rule_card threshold value / rule_id / family id

## 5. W1 → W0 反向写入禁止

W1 **绝不修改** W0 资源（registry / formula / surrogate / constraint / sidecar contract）：

- 不修改 `RegistryBundle` 任何字段
- 不在运行时新增 entry
- 不通过 `config` 注入新 slot 定义
- 不 patch surrogate 公式
- 不绕过 W0 直接定义新 schema

W0 资源是 W1 的**只读输入**。如需扩展 / 修订 W0 资源，走 spec → code 单向（先改 W0 spec 包 → 用户 confirm → 改 W0 spec → 改代码）。

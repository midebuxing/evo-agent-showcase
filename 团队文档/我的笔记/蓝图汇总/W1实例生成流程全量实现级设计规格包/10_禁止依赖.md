# 禁止依赖

W1 实例生成流程层 rule-blind 红线 + 禁止依赖清单。本节是 W0 spec 05 §5 在 W1 阶段的接管 + a8 §6 / a9 §5.1-5.2 的整合。

## 1. 一句话红线

> **世界层不看法规，query 层不看 gold，gold 层不看 runtime。**（a8 §6 line 385）

W1 worldgen 处在"世界层"，对应红线是 **rule-blind**：

- 不读 rule_card / projection_registry / threshold_regime_index 决定世界真相
- 不读 法规原文（MBIS / CoP / Cap.123）反推世界
- 不读 query text / runtime trace / gold labels

## 2. 禁止依赖完整清单

| # | 禁止依赖 | 理由 | 来源 |
|---|---|---|---|
| 1 | **W1 worldgen 读取 rule_card / projection_registry 反向生成世界真相** | rule-blind 红线 line 1；a9 §2.1 world truth 不能由法规直接生成 | a9 line 56-85；a8 §6 line 309-385 |
| 2 | **Measurement 直接 primitive 抽最终值** | a8 §3 五层因果链要求 measurement 由 surrogate 下游派生（fragment → driver → mechanism → condition → measurement）；coverage/test/assessment 也必须有独立上游 | a8 line 131-141；a11 line 346-364 |
| 3 | **Projection 写回 world truth** | projection 只读 world/measurement/qualifier；不写 world | a12 line 1502-1506 |
| 4 | **Sidecar 派生失败时伪造 facts** | projection 可 fallback，但不得伪造 sidecar facts 或修改 world truth；sidecar bundle 总由 worldgen 派生层生成，"缺失"态废止，仅可能是 `not_applicable` / 派生异常 | a12 line 1932-1936；W0 spec 09 §1.2 / §6（修订 2026-05-09）|
| 5 | **Sidecar 派生层依赖外部 admin record / SidecarInput 注入** | 数据生成项目无外部供给方；统一 worldgen 自家采样 | W0 spec 09 §1（用户口径 2026-05-09）|
| 6 | **生成 HiddenGold / Observation / QueryEpisode / Adjudication** | 用户原则删除巡检员模拟 / benchmark gold 主链；W1 不产出 gold-related 字段 | `09_用户原则说明.md` line 5-8 / line 20-25 |
| 7 | **W1 worldgen 字段中出现 `rule_id / family_id / trigger_id / gold_*`** | a9 §5.1 schema firewall；这是黑名单字段 | a9 line 635-646 |
| 8 | **W1 worldgen 字段中出现 `acceptable_next_questions / missing_slots`** | 同上；属 gold layer 输出 | a8 line 326-330 |
| 9 | **distribution_source 字段标 `derived_from_rule_card_threshold` 或 `threshold ± epsilon`** | 4 层校准 Layer 4 红线 / rule-blind 红线；分布参数可参考法规分布形状（双向锚点对齐 evo-agent blind）但不允许 silent 反推 | W0 spec 01 §1.1.1 / 记忆 `feedback_dual_anchor_alignment_evo_agent_blind.md` |
| 10 | **公式 surrogate 输入字段缺时 silently drop** | 缺时输出 `not_applicable` 不 silently drop；保证 audit trace 完整 | W0/W1 约束口径 |
| 11 | **W2 coverage backpressure** | W1 不接收 W2 的 near-threshold / neighbor-family / recoverable-missing / unknown_reason / family / threshold / regime 信号 | 防止 W2 法规侧采样目标反向污染 worldgen，保持 rule-blind |
| 12 | **W2 internal evaluator config** | W1 不读取 `applicability_predicates`、threshold width、conflict selector、unknown priority | 这些属于 W2 内部 evaluator 配置，不是世界生成参数 |

## 3. 与 a9 §5 反泄漏机制的字段黑名单交叉

a9 §5.1 schema firewall 列出的黑名单字段在 W1 必须**字段层硬断开**：

| 层 | 黑名单字段 | 理由 |
|---|---|---|
| `WorldBundle` | `rule_id` / `family_id` / `trigger_id` / `gold_route` / `gold_*` | a9 §5.1 |
| `WorldBundle` | `acceptable_next_questions` / `missing_slots` | a9 §5.1 |
| `WorldBundle` | `query_text` / `template_id` / `runtime_trace` | a8 §6 |
| `SidecarRuntimeBundle` | `family_id` / `gold_action` | 同上 |

W1 worldgen 函数签名 + 输出字段合约必须满足上述（详见 W0 spec 04 §1.1 + 04 §17 字段合约）。

## 4. dependency import boundary（防规则侧泄漏）

按 a9 §5.2，W1 的依赖边界为：

| 类别 | 边界 |
|---|---|
| **禁止读取** | 法规层（rule_card / projection registry / threshold regime / W2 evaluator config 等任何 rule snapshot 数据源）+ W2 法规侧采样信号 |
| **允许读取** | W0 静态资源层（registry / formula / constraint / sidecar contract）+ W1 worldgen 自家模块 |

本章只规定 spec 边界，不记录实施审计状态。


## 5. 双向锚点对齐 vs 反推作弊的边界

按记忆 `feedback_dual_anchor_alignment_evo_agent_blind.md`：

| 行为 | 是否允许 | 理由 |
|---|---|---|
| 字段含义 / 公式按 物理 + RI 报告 + 业务真实 定义 | ✅ 允许 | 头端锚点（物理） |
| 分布参数（mean / sigma / typical_bounds）参考 法规阈值分布形状 | ✅ 允许 | 尾端锚点（法规阈值是分布 ~85 percentile 等显式对齐声明）|
| 分布参数 silent 反推法规阈值（`source = derived_from_rule_card_threshold`）| ❌ 禁止 | rule-blind 红线 |
| 分布参数表达式中显式出现法规阈值（`mean = threshold + epsilon` 即便 comment）| ❌ 禁止 | 4 层校准 Layer 4 红线 |

**判定方法**：看 `distribution_source` 字段：
- `engineering_judgment_xxx` / `engineering_basis_xxx; threshold_alignment_note = 法规阈值落在分布 ~85 percentile` → 允许
- `derived_from_rule_card_threshold` → 红线
- `threshold ± epsilon`（即便注释为 noise）→ 红线

## 6. 不允许 silent 修复 + silent fallback

按 a8 §4.4 局部修复 + 拒收：

- 每次 P1 / P2 修复必须 log（不允许 silent 修改 measurement 数值）
- P0 reject 必须计入 batch_stats（DEBT-022 P1 repair 性能 trace 同源）
- 公式输入缺时输出 `not_applicable` 不 silently drop（DEBT-010 / DEBT-011 closure）

silent 操作的危害：
- 失去 audit trace（事后不知道哪里被修了）
- evo-agent 训练数据混入合成噪声（看不出 measurement 是真实采样还是修复值）
- 长期累积偏差不可察觉

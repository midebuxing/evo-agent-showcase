# 术语表与名词解释

## 1. 阅读规则

本文件解释新版 W0 规格包中的核心名词。每个术语都尽量说明三件事：

| 项 | 含义 |
| --- | --- |
| 定义 | 这个词在本规格包里具体指什么 |
| 新版状态 | 保留、删除、边界保留、仅作历史来源，或需要人工确认 |
| 易混点 | 容易和哪个旧概念混淆 |

本规格包的过滤原则是：只要旧蓝图中的实现级内容属于 W0 物理事实、技术测量事实、派生事实、法规投影、canonical slot、sidecar 边界，且不与删除巡检员模拟的原则冲突，就应保留；专门服务于巡检员模拟、隐藏答案、题面、追问、评测裁决的内容删除。

## 2. 层级与边界

### Rule-blind

Rule-blind 指使用 W0 资源生成物理世界时不直接读取具体法规条文来“倒推”世界，而是先生成独立的 world truth / measurement truth，再由 法规映射层读取 `normative_projection_registry` 做法规投影。

新版状态：保留。

易混点：rule-blind 不是“不做法规投影”。法规投影保留，只是不能反向生成世界。

### MBIS

MBIS 指 Mandatory Building Inspection Scheme，是 canonical a4 中本轮覆盖的法规范围。a4 明确这份 coverage baseline 只计入 MBIS 分支，不计入 MWIS。

新版状态：保留为法规范围背景。

易混点：MBIS 是法规来源范围，不是 W0 资源域。

### W0 / WorldGenerator 静态资源层

W0 是 WorldGenerator 的静态资源层。它负责定义 19 张 registry、schema、surrogate、formula、constraint、canonical slot 对齐和 sidecar boundary。具体建筑实例由 W1 使用 W0 资源生成；法规映射参考真值由 W2 生成。

W0 不消费 rule_card v2，不输出 `NormativeProjection` 字段表，不定义 evo-agent 训练侧采样策略.


### 实例生成流程

实例生成流程指 WorldGenerator 使用 W0 registry / surrogate / formula / constraint 生成某栋具体建筑的 `WorldBundle`、measurement 和 derived facts。

新版状态：保留为 W0 资源的参考消费流程。

易混点：实例生成流程不是 W0 静态资源本体。

### W0+ 家族

W0+ 是一个统称，指 W1 / W2 / W3 / ... 所有"W0 之后"的层族；它本身不是某个具体层，只表示"W0 之外的后续层范围"。

新版状态：保留为家族级术语。

易混点：早期文档里曾用 "W+" 当作法规映射层的代号，是术语错误；"W+" / "W0+" 都只表示家族范围，法规映射层是该家族中的某一个具体 Wx — **2026-05-13 用户决策编号为 W2**。

### 法规映射层 = W2（2026-05-13 编号确定）

法规映射层指在某个具体 `WorldBundle` 已经生成后，读取 world truth、measurement truth、derived facts、projection registry 和可选 sidecar join，产出 `NormativeProjection` 参考真值的层。

**编号确定**：**2026-05-13 用户拍板该层编号为 W2**（W0+ 家族中第二层，跟 W1 实例生成流程层并列；W1 在前，W2 在后消费 W1 输出）。后续工作以 W2 名义开展，规格包命名为 "W2 法规映射层"。"法规映射层"和"W2"两个称呼可共用 — 前者是 layer 描述名，后者是 layer 编号。

新版状态：保留。

易混点：
1. 法规映射层（W2）不是巡检员模拟，也不是 HiddenGold；它是后续合规检验参考真值层。
2. 法规映射层 ≠ "W+"。"W+" 不是层名，是早期文档误用的家族符号，统一替换为"法规映射层"或"W2"；指家族范围时用"W0+"。
3. W2（法规映射层）与 W1（实例生成流程层）不是同一层；W1 生成 `WorldBundle`，W2 在生成完之后消费 `WorldBundle` 做投影输出 `NormativeProjection`。

### W1 生成规则层

W1 是运行 W0 资源时的生成规则层，包含约束库、校准配置、采样策略、运行参数等。旧蓝图中有些 `ConstraintLibrary`、`CalibrationProfile` 的内容应从 W0 静态表里分离到 W1。

新版状态：边界保留。

易混点：W1 可以控制 W0 如何生成，但不等于 W0 的 registry 本体。

### W2+ Runtime

W2+ 指运行时系统，包括后续查询、接口调用、执行器、用户交互等。

新版状态：本规格包不展开。

易混点：旧蓝图中的 investigator runtime、follow-up、trace、skill evaluation 不因属于 runtime 而保留；它们属于已删除的巡检员模拟链。

### Runtime Convenience

Runtime Convenience 指旧文档中为运行时使用方便而附带的字段或对象，例如 HiddenGold 作为 research / runtime contract 的便捷副本。

新版状态：按语义过滤。

易混点：方便 runtime 不等于 W0 必需。若 runtime convenience 服务 HiddenGold、episode、adjudication，则删除。

### World Truth

World Truth 指 W0 生成的物理世界真相，例如建筑属性、构件、材料、位置、片段、缺陷状态、排水状态、僭建状态、消防物理缺陷、修缮与验证派生结果。

新版状态：保留。

易混点：World Truth 可以被法规投影或旧模拟链消费，但它本身不是巡检员模拟。

### World-derived Truth

World-derived Truth 指由 W0 物理状态和测量派生出来的事实，例如 risk flags、repair_required、verification_failed、safe_until_next_cycle。

新版状态：保留。

易混点：它不是原始物理状态，但仍属于 W0 / derived layer，不是法规裁决，也不是调查员评分。

### Measurement Truth

Measurement Truth 指 W0 生成或派生的测量事实，包括几何测量、覆盖率/采样测量、技术验证测量、结构评估测量。

新版状态：保留。

易混点：测量结果可能在旧蓝图中被调查题面使用，但“测量值是多少”本身仍属于 W0。

### Normative Truth

Normative Truth 指 法规映射层由 World Truth、Measurement Truth、qualifier、sidecar join 经过法规投影后得到的法规语义结果，例如适用 family、required slots、threshold regime、verdict、basis items。

新版状态：保留。

易混点：Normative Truth 不是 HiddenGold。HiddenGold 是旧系统把 NormativeProjection 拷贝成隐藏答案的评测外壳。

### Qualifier

Qualifier 是限定某个事实、slot 或 measurement 适用范围的分类信息，例如 `qual.component_type`、`qual.location_class`、`qual.method_class`、`qual.actor_role`。

新版状态：保留。

易混点：qualifier 本身不是最终 verdict；它用于选择 family、绑定 slot、解释 basis。

### Sidecar Boundary

Sidecar Boundary 划定 worldgen core（A 类，写入 `WorldBundle`）与 sidecar 派生层（B 类，写入 `SidecarRuntimeBundle`）之间的容器边界。两者**都由 worldgen 在同一 pipeline 生成**，桶分离仅为 ontology 边界（A 类 = 楼宇物理状态；B 类 = 行政过程 / 历史合规状态）。projection 可同时 join 消费两个 bundle。

新版状态：保留边界。**2026-05-09 修订**：原描述"W0 不生成这些 sidecar truth / 输出缺失 marker"基于"sidecar 由外部 admin record 送入"前提；本数据生成项目无外部供给方，sidecar bundle 由 worldgen sidecar 派生层自家采样生成（详见 spec 09 §1.2）。

易混点：sidecar 边界不是巡检员模拟；artifact/evidence 如果被包装成观察题面，则属于删除范围。

### Join

Join 指 projection executor 通过稳定键把 W0 world / measurement 与 sidecar facts 对齐，例如 `world_id`、`building_id`、`fragment_id`、`component_id`、`slot_id`。

新版状态：保留。

易混点：允许 projection join sidecar，不代表 W0 生成 sidecar truth。

## 3. 核心对象

### WorldBundle

WorldBundle 是 W0 输出的世界包，聚合 building、component、location、fragment、coverage、condition、measurement、derived flags、projection 等对象。

新版状态：保留。

易混点：WorldBundle 是世界事实容器，不是 LatentCase。

### ComponentGraph

ComponentGraph 是旧文档中描述 component 类型、关系和拓扑的一层概念。在 W0 规格包中，它主要落实到 `component_type_registry`、`building_template_registry.component_graph_template_ids` 以及生成后的 `ComponentNode` 结构。

新版状态：保留语义，不一定作为独立对象保留。

易混点：ComponentGraph 不是巡检员图谱，也不是 evidence graph。

### BuildingContext

BuildingContext 描述建筑级上下文，例如 building id、用途、结构类型、楼层范围、材料、配置等。

新版状态：保留。

易混点：building metadata 会被法规 scope 使用，但不是法规本身。

### ComponentNode

ComponentNode 描述建筑构件，例如梁、外墙、排水管、消防门、檐篷、招牌等。它通常引用 component type、material、location、父子关系和 geometry proxy。

新版状态：保留。

易混点：component graph 不等于 ComponentGraph 术语本身；在实现上对应 `component_type_registry` 与实例化后的 component nodes。

### LocationNode

LocationNode 描述位置类别和空间标签，例如 common part、private premises、external wall、roof、pipe duct、escape route 等。

新版状态：保留。

易混点：location 是 W0 scope / coverage / drainage / UBW 的基础 qualifier，不是观察位置。

### FragmentContext

FragmentContext 是 W0 的片段级判断单位，通常由 component + location + area/length + driver + mechanism 组合而来。

新版状态：保留。

易混点：FragmentContext 是世界片段，不是 evidence fragment 或 case fragment。

### CoverageRelation

CoverageRelation 描述构件或片段的覆盖/遮挡/检查比例关系，例如 covered area ratio、external wall inspected ratio、obscuration class。

新版状态：保留。

易混点：coverage 在这里是物理/测量覆盖关系，不是测试覆盖率，也不是 evidence coverage。

### Graph Cycle

Graph Cycle 指 component parent/child 图出现环。`C001_GRAPH_NO_CYCLE` 要求 component graph 不得成环。

新版状态：保留约束。

### DriverState

DriverState 描述潜在驱动状态，例如 service load、moisture、chloride、carbonation、maintenance deficit、workmanship deficit、alteration propensity 等。

新版状态：保留。

易混点：driver 是物理机制的上游因素，不是 agent 行为驱动。

### MechanismState

MechanismState 描述退化机理或故障机理的激活状态，例如 load crack、restraint crack、corrosion spall、drainage blockage、UBW alteration、fire safety deficiency。

新版状态：保留。

易混点：mechanism 是物理机理，不是推理机制或运行时策略。

### ConditionState

ConditionState 描述缺陷/状态结果，例如 crack、spall、delamination、drainage leakage、UBW alteration、fire-safety deficiency 等。

新版状态：保留。

易混点：旧文档里有 `DamageState`，a12 中已升级为更泛化的 `ConditionState`。新版应保留缺陷几何和 manifestation 语义，删除 episode/gold 语义。

### DamageState

DamageState 是旧蓝图中较早的缺陷状态对象，偏结构/外墙损伤语义。

新版状态：部分语义迁移到 ConditionState。

易混点：不要把旧 `DamageState` 整体作为新版对象重复保留；应以 a12 的 `ConditionState` 为准。

### DrainageState

DrainageState 描述排水系统故障状态，例如 blockage、leakage、misconnection、sewage backflow 等。

新版状态：保留。

易混点：排水的物理故障属于 W0；排水相关报告、通知、程序记录属于 sidecar。

### UBWState

UBWState 描述 unauthorized building works / subdivided-unit signs / unauthorized alteration 等物理改动状态。

新版状态：保留物理状态。

易混点：UBW 的物理存在可进 W0；审批、通知、记录等程序事实不进 W0。

### FireSafetyState

FireSafetyState 描述消防安全物理缺陷，例如 fire door deficiency、escape route obstruction、fire component deficiency。

新版状态：保留物理缺陷。

易混点：record-driven statutory upgrade outstanding 这类法定升级记录不应直接混入 world truth，需按 sidecar / projection 口径处理。

### RepairAssessmentState

RepairAssessmentState 描述修缮、验证、评估相关派生事实，例如 repair_required、verification_failed、safe_until_next_cycle、FSP deficit。

新版状态：保留。

易混点：修缮结果和验证失败是 world-derived truth；修缮建议书、表格、提交记录属于 sidecar。

### MeasurementRecord

MeasurementRecord 是测量记录对象，承载 slot_id、value、unit、precision、method_class、target refs、derivation refs、noise/rounding 等信息。

新版状态：保留。

易混点：MeasurementRecord 会被旧巡检员模拟消费，但它不是巡检员模拟。删除的是“它如何被观察/追问/评分”的外壳。

### DerivedFlags

DerivedFlags 是风险、修缮、验证、评估等由 world / measurement 派生出的布尔或枚举事实集合。

新版状态：保留。

易混点：DerivedFlags 不是法规裁决；它是 projection 的输入之一。

### ReportBasisItem

ReportBasisItem 是法规投影输出中解释 basis 的条目，用来说明某个 verdict 或 threshold eval 依据了哪些 world / measurement / sidecar slots。

新版状态：保留。

易混点：ReportBasisItem 不是 HiddenGold。它是 projection 可解释性的一部分。

### RuleSnapshot

RuleSnapshot 指旧文档或实现中可能出现的法规规则快照。新版 W0 规格包不把 RuleSnapshot 作为 W0 生成对象；规则侧输入应通过 `normative_projection_registry`、canonical slots、family coverage 等配置进入 projection。

新版状态：边界概念。

易混点：RuleSnapshot 不是 WorldBundle，也不是 registry bundle。

### ProjectionExecutorConsumes

ProjectionExecutorConsumes 是 a12 sidecar contract 中给出的消费合约，说明 projection executor 读取 `WorldBundle`、`MeasurementRecord[]`、`DerivedFlags` 以及可选 sidecar。

新版状态：保留。

易混点：它是 projection 消费接口说明，不是生成函数。

## 4. 法规投影与 slot

### NormativeProjection

NormativeProjection 是 法规映射层的参考真值输出，负责把某个具体 world truth、measurement truth、qualifier、sidecar join 映射成法规语义。

新版状态：保留。

易混点：NormativeProjection 不属于 W0 静态资源层本身的输出终点，也不应继续生成 HiddenGold。新版法规映射链路应停在 projection 输出。

### ProjectionFamilyEval

ProjectionFamilyEval 描述某个 regulation family 的适用性、规则命中、required slots、verdict、basis 等评估结果。

新版状态：保留。

易混点：family eval 是法规投影结果，不是 adjudication。

### ThresholdEval

ThresholdEval 描述某个阈值判断，例如 measured value 是否高于、低于、接近或等于阈值。

新版状态：保留。

易混点：threshold eval 是法规投影用的数值判断，不是评分标签。

### Canonical Slot

Canonical Slot 是 a4 canonical slot universe 中定义的 document-level factual key，用来表示法规全文反复要求的事实类型。

新版状态：保留。

易混点：canonical slot 不等于 a12 的实现侧 slot_id；两者可能需要 alias / mapping。

### Slot Class

Slot Class 是 canonical slot 的类别。a4 定义五类：`world_truth_slot`、`measurement_slot`、`qualifier_slot`、`artifact_requirement`、`procedure/gate requirement`。

新版状态：保留。

易混点：`artifact_requirement` 与 `procedure/gate requirement` 是法规事实需求，但不代表 W0 要生成 artifact/procedure truth。

### World Truth Slot

`world_truth_slot` 是 canonical slot 的一类，表示事实应来自建筑、构件、缺陷、风险、修葺结果等 world truth。

新版状态：保留。

### Measurement Slot

`measurement_slot` 是 canonical slot 的一类，表示事实应来自比例、面积、数量、时间、应力、公式、采样率等测量或测量派生值。

新版状态：保留。

易混点：某些 procedure duration 在 a4 中是 measurement_slot，但 carrier 可能是 procedure sidecar，不一定进 W0 world truth。

### Artifact Requirement

`artifact_requirement` 是 canonical slot 的一类，表示法规要求存在某类报告、表格、日志、相片、图则、证书或声明。

新版状态：保留为 sidecar boundary，不进 WorldBundle truth。

### Procedure / Gate Requirement

`procedure/gate requirement` 是 canonical slot 的一类，表示委任、提名、通知、认可、开始、完成、送交、最终检验等程序状态。

新版状态：保留为 sidecar boundary，不进 WorldBundle truth。

### Regulation Family

Regulation Family 是法规投影中的规则族或业务族，例如 scope、inspection、repair、reporting、procedure、supervision 等 family。

新版状态：保留。

易混点：regulation family 不是 5 大业务域，也不是 6 大资源域。它是法规投影维度。

### Normative Slot Registry

Normative Slot Registry 是把 canonical slots 落成机器可读 registry 的方向，用于支撑 normative projection。

新版状态：保留为后续工程产物。

易混点：它不是 worldgen 算法，也不是 HiddenGold。

### `normative_projection_registry`

`normative_projection_registry` 是 W0 registry bundle 中 19 张物理 registry 之一，但其 records 语义、projection binding、16 family baseline、`applicability_predicates` 与 conflict group 权威归 W2 `06_canonical_slots与projection_binding.md`。

W0 列入该 registry 的原因是跨层编排需要统一加载 registry bundle；这不表示 W0 拥有法规映射输出语义.


### Projection Fallback

Projection Fallback 指 projection 在 slot 缺失、binding 不兼容、多 family 冲突、sidecar 派生失败等情况下输出 `unknown`、`not_applicable` 或 unknown_reason_code。（2026-05-09 废止 `sidecar_missing` 输出——sidecar bundle 总是由 worldgen 同时生成，不存在缺失态；详见 spec 09 §1.2/§6）

新版状态：保留。

易混点：projection fallback 的 unknown 不是 episode 中“调查员不知道”的 unknown。

### Projection Status

Projection Status 描述 projection 覆盖状态，例如 `covered`、`uncovered`、`conflict`。

新版状态：保留。

易混点：projection status 不是 HiddenGold 的评分状态。

### Verdict

Verdict 指法规投影输出的结论，例如 `pass`、`fail`、`unknown`、`not_applicable`。

新版状态：保留。

易混点：verdict 是 projection 输出，不是 agent 答案对错。

### Basis Item

Basis Item 是 projection 说明 verdict 的依据项，通常引用 world / measurement / sidecar slots。

新版状态：保留。

易混点：basis item 可用于解释法规投影，但不应复制成 hidden gold。

## 5. Registry 与资源域

### Registry

Registry 是 W0 静态资源表。它不是一次生成出来的 world instance，而是生成器运行前的配置和约束来源。

新版状态：封口版 W0 使用 19 张 registry：原 17 张 + `sidecar_measurement_registry` + `sidecar_bool_slot_registry`。旧稿 17 / 18 张为历史口径。

易混点：registry 是生成输入；WorldBundle 是生成输出。

### Registry Bundle

Registry Bundle 指将多张 registry 汇总后的配置包。封口版仅声明 registry bundle 作为规格配置集合，不记录实现层接入状态。

新版状态：保留为工程概念。

易混点：registry bundle 不是 WorldBundle。

### 六大资源域 + 一项边界契约

本规格包用六大资源域 + 一项边界契约组织 19 张 registry：资产空间域、缺陷字典域、驱动测量域、派生风险域、机理引擎域、高阶评估域、Sidecar 边界契约。

新版状态：保留。

易混点：“域 / Domain”是资源职能分组，不是 slot ownership cluster。

### 5 大业务域

5 大业务域指结构/外墙、排水、僭建、消防、技术验证等业务问题维度。

新版状态：保留。

易混点：5 大业务域不是 19 张 registry 的一对一细分。它们和 19 张表是多对多关系。

### RegistryTable 总数

封口版 W0 使用 19 张 registry。旧稿的 17 张 / 18 张均为历史口径；正式 spec 中如需引用旧数字，必须写明“旧口径”。

## 6. Surrogate、公式、噪声

### Surrogate

Surrogate 是用来近似物理机制、测量或评估结果的可执行函数或公式族。

新版状态：保留。

易混点：surrogate 是生成/评估物理事实的机制，不是 agent 推理策略。

### `surrogate_id`

`surrogate_id` 是 registry 里指向具体 surrogate 实现的标识。

新版状态：保留。

易混点：`surrogate_id` 是规格层路由键；实现层接入状态不进入封口正文。

### Formula

Formula 是 registry 中声明的表达式，例如 risk derivation formula、sampling formula、failure rule、assessment formula。

新版状态：保留。

易混点：formula 不是自由文本说明；最终应有安全 expression evaluator 或受控 DSL。

### Noise Model

Noise Model 描述测量值如何从真实值变成报告值，例如 relative noise、absolute noise、rounding、clipping。

新版状态：保留。

易混点：噪声模型不是数据污染；它是模拟测量不确定性的工程约束。

### TruncatedLogNormal

`TruncatedLogNormal` 是一种带上下界截断的对数正态分布，常用于生成正值且右偏的物理量或测量误差。

新版状态：保留。

### UniformInt

`UniformInt` 是整数均匀分布，常用于生成计数类字段或范围内整数。

新版状态：保留。

### Sigmoid

`sigmoid` 是将线性组合压到 `[0,1]` 区间的函数，旧蓝图中用于机理激活分数、腐蚀/裂缝/缺陷严重度等。

新版状态：保留。

### Clip / Clamp

`clip` / `clamp` 指把数值限制在给定上下界内，是 P1/P2 repair 常用动作。

新版状态：保留。

### Precision Steps

Precision Steps 描述不同精度等级下的 rounding 步长，例如 coarse、standard、fine。

新版状态：保留。

### Coarse / Standard / Fine

`coarse`、`standard`、`fine` 是 precision steps 中的精度等级，用于控制 measurement rounding 步长。

新版状态：保留。

### Threshold Regime

Threshold Regime 描述测量值相对法规阈值的位置，例如 far_below、near_below、exact_threshold、near_above、far_above。

新版状态：保留。

易混点：threshold regime 是法规投影和 QA 分布用语，不是 HiddenGold。

### Unknown Policy

Unknown Policy 描述输入缺失、不兼容、未覆盖时如何处理，例如 not_applicable_if_inputs_missing、false_if_no_drainage_state。

新版状态：保留。

易混点：unknown policy 是生成/投影规则，不是调查员不知道。

### Measurement Family

Measurement Family 是 measurement slot 的类别，常见包括 `geometry`、`coverage_sampling`、`technical_validation`、`assessment`。

新版状态：保留。

### Geometry Measurement

Geometry Measurement 是由 condition geometry 或 component geometry 派生出的测量，例如 crack width、spall area、exposed rebar length。

新版状态：保留。

### Coverage / Sampling Measurement

Coverage / Sampling Measurement 是覆盖比例、采样比例、检查数量、间隔等测量，例如 covered_area_ratio、external_wall_area_ratio、pull test count。

新版状态：保留。

### Technical Validation Measurement

Technical Validation Measurement 是修缮或验证测试相关测量，例如 pull test stress、failure follow-up test count。

新版状态：保留。

### Assessment Measurement

Assessment Measurement 是结构评估测量，例如 FSP ratio、core sample strength、structural performance ratio。

新版状态：保留。

## 7. Sidecar 术语

### Sidecar

Sidecar 是 W0 外部的配套事实容器，用于 artifact、procedure、supervision、actor role 等非 world truth 内容。

新版状态：保留边界，不在 W0 中生成 truth。

### Artifact Sidecar

Artifact Sidecar / `ArtifactSidecar` 承载报告、表格、日志、相片、图则、证书、声明等工件事实。

新版状态：保留边界。

易混点：artifact requirement 是法规需求；artifact truth 不进入 WorldBundle。

### Procedure Sidecar

Procedure Sidecar / `ProcedureSidecar` 承载 appointment、submission、recognition、deadline、completion 等程序状态。

新版状态：保留边界。

### Supervision Sidecar

Supervision Sidecar / `SupervisionSidecar` 承载 supervision team、site visit、SP1/SP2、witness record 等监督事实。

新版状态：保留边界。

### Sidecar Missing（旧概念黑名单）

`sidecar_missing` 是旧版 projection fallback marker，表示某个 sidecar-only slot 被法规投影需要，但 sidecar facts 不存在或不可 join。

新版状态：**2026-05-09 废止**。本数据生成项目无外部 admin record 供给方，sidecar bundle 总是由 worldgen 在 pipeline 中同时生成（spec 09 §1.2）。"sidecar 缺失"这个态本就不应存在；派生层异常只表现为 `unknown` / `not_applicable` 或 conflict（详见 spec 09 §6）。

易混点：原来易混点写"sidecar_missing 不是模拟调查员没问到，而是 projection 输入缺失"——这一条本身就把 sidecar 假设成需要外部输入，已随本版废止。

### Not Applicable

`not_applicable` 表示某法规 family、slot 或 condition 对当前 world 不适用。

新版状态：保留。

易混点：not_applicable 不是 unknown，也不是 pass。

### Missing

`missing` 表示需要的输入事实缺失。

新版状态：在 projection / validation 语义中保留。

易混点：旧 LatentCase 中 missing 可能用于认识状态；那部分删除。

### Conflict

`conflict` 表示多个来源、family 或 binding 之间无法稳定选择。

新版状态：保留为 projection / validation 语义。

易混点：conflict 不是 agent 问答冲突。

### Marker

Marker 是 W0 可输出的需求标记，例如 artifact_required_marker、procedure_required_marker、worldgen_sidecar_conflict_marker。（2026-05-09：废止 `sidecar_missing_marker`——sidecar bundle 总是生成）

新版状态：保留，限于接口/QA。

易混点：marker 不是 sidecar truth 本身。

### Artifact Required Marker

`artifact_required_marker` 表示 projection 或 QA 发现某类 artifact sidecar 被法规需要。

新版状态：保留 marker，不生成 artifact truth。

### Procedure Required Marker

`procedure_required_marker` 表示某类 procedure sidecar 被法规需要。

新版状态：保留 marker，不生成 procedure truth。

### Supervision Required Marker

`supervision_required_marker` 表示某类 supervision sidecar 被法规需要。

新版状态：保留 marker，不生成 supervision truth。

### No Sidecar Dependency

`no_sidecar_dependency` 表示当前样本不依赖 sidecar-only slot。

新版状态：保留为 QA / batch marker。

## 9. Benchmark 与 QA 的区别

### Inspector-simulation Benchmark

Inspector-simulation benchmark 指旧蓝图中把 world truth / NormativeProjection 包装成 QueryEpisode，再用 HiddenGold / AdjudicationState 对 agent 追问和判断进行评分的题库评测链。

新版状态：删除。

易混点：这里的 benchmark 不是所有测试。它特指巡检员模拟题库 / hidden-answer 评分链。

### Benchmark Gold

Benchmark Gold 指用于上述题库评测的隐藏标准答案，例如 HiddenGold、gold_route_action、gold_missing_slots、acceptable_next_question_bundle_ids。

新版状态：删除。

### Gold 标尺

旧蓝图中“gold 标尺”有时指 NormativeProjection 及其派生 HiddenGold。新版应拆开：NormativeProjection 保留为法规投影输出；派生 HiddenGold / benchmark gold 删除。

新版状态：术语替换。

推荐改写：使用 `projection basis`、`expected_verdict`、`projection output`，避免继续写 “gold 标尺”。

### W0 QA

W0 QA 指检查生成器输出是否满足 schema、约束、分布、物理合理性、projection basis、sidecar boundary 等质量要求。

新版状态：保留。

易混点：W0 QA 不是巡检员模拟 benchmark。不要因为删除 benchmark gold 而删除 schema validation、constraint validation、projection regression 或 release QA。

### Regression

Regression 指回归测试，确保生成器、projection、schema、QA 在版本变化后仍保持预期行为。

新版状态：保留。

### Batch Tier

Batch Tier 指 smoke_batch、dev_batch、release_batch 等样本批次规模和用途。

新版状态：保留非评测题库语义。

易混点：旧 `benchmark_batch` 名称含 ablation / report quality evaluation，应删除或改名；但大样本 QA 的需求可以保留为非 benchmark 名称。

### Smoke Batch

`smoke_batch` 是快速检查 schema、surrogate、validator 的小批次。

新版状态：保留。

### Dev Batch

`dev_batch` 是日常生成与 projection regression 使用的开发批次。

新版状态：保留。

### Release Batch

`release_batch` 是 registry version release QA 使用的大批次。

新版状态：保留。

### Benchmark Batch

`benchmark_batch` 是旧 a12 中带有 ablation / report quality evaluation 语义的批次名。

新版状态：删除名称和题库评测语义。

易混点：删除 `benchmark_batch` 不等于删除 1200 样本级大批量 QA；如仍需要，应另命名。

### Batch Manifest

Batch Manifest 是批次输出的元数据，包含 `batch_id`、`generated_at`、`generator_version`、`registry_bundle_hash`、`projection_registry_hash`、`batch_config_hash`、`random_seed_root`、`sample_count`、`validation_report_id`。

新版状态：保留。

### Registry Bundle Hash

`registry_bundle_hash` 是 registry bundle 的内容哈希，用于可复现性和版本审计。

新版状态：保留。

### Projection Registry Hash

`projection_registry_hash` 是 projection registry 的内容哈希，用于追踪法规投影配置版本。

新版状态：保留。

### Batch Config Hash

`batch_config_hash` 是 batch config 的内容哈希，用于生成批次复现。

新版状态：保留。

### Random Seed Root

`random_seed_root` 是批次随机种子的根值，用于 deterministic generation。

新版状态：保留。

易混点：`random_seed_root` 与下文的 "seed worldgen / seed v1" 完全不是一回事。前者是随机数种子，后者是已废弃的旧蓝图实现版本号。

### Seed worldgen / seed v1（已废弃）

Seed worldgen 是 a10 旧蓝图阶段定义的"最小可用 worldgen"早期实现——只覆盖窄范围（裂缝、剥落露筋、砌体异常等），不是 a12 的全量覆盖。`v1` 是该实现的版本号。

**新版状态：废弃**。a10 的 seed v1 实现已被 a12 全量覆盖完整取代，新版规格包**不再使用**这一实现，也不应在新版任何 worldgen 实现中保留任何 seed v1 残留。

**继承的只是原则，不是实现**：

- a10 seed v1 当年立下的几条原则（"unknown 不是兜底垃圾桶"、"crack 必须 RC"、"rebar exposure 必须有钢筋"等）作为约束准则保留到新版（见 `07_约束与失败策略.md` §6 旧 a10 seed constraints 作为补充口径）。
- 这些原则的**法律地位**已经升级为 a12 全域 C001-C026 约束的一部分，引用 a10 只是出于历史可追溯性。
- 新版 worldgen 实现**不应**因此引用任何 seed v1 数据集、seed v1 范围限制或 seed v1 代码模块。

易混点：

- "seed v1" ≠ `random_seed_root`（前者是 worldgen 实现版本，后者是随机数种子，已分别说明）。
- "seed constraints"（07 §6 标题）指**原则**，不是 seed v1 实现本身——避免读者误以为 seed v1 还在新版使用。

### Validation Report ID

`validation_report_id` 是批次校验报告的 id。

新版状态：保留。

## 10. 约束与失败策略

### Hard Constraint

Hard Constraint 是生成或投影过程中必须满足的硬约束，例如 graph 不成环、component 必须有 location、measurement 必须引用 derivation、projection basis 不为空。

新版状态：保留。

### Constraint ID

Constraint ID 是 C001-C026 这类硬约束编号。

新版状态：C001-C025 保留；C026 因 HiddenGold 删除而删除。

### C001-C026

| 范围 | 含义 |
| --- | --- |
| `C001-C005` | 图、位置、片段、材料、机理兼容性 |
| `C006-C012` | condition、area/length、露筋、drainage、fire、UBW 兼容性 |
| `C013-C020` | measurement bounds、方法兼容、derivation refs、measurement 来源 |
| `C021-C022` | repair / verification derived flag 一致性 |
| `C023-C025` | projection unknown、conflict group、basis nonempty |
| `C026` | HiddenGold thin-copy 约束，新版删除 |

新版状态：C001-C025 保留，C026 删除。

### P0 / P1 / P2 / P3

P0-P3 是 a12 定义的失败处理优先级：

| 等级 | 含义 |
| --- | --- |
| P0 | reject_or_resample |
| P1 | repair_world_truth_geometry_or_state |
| P2 | repair_measurement_rounding_or_bounds |
| P3 | projection_fallback_to_unknown_or_not_applicable |

新版状态：保留。

### Reject

Reject 指违反硬约束时丢弃当前生成结果或重新采样。

新版状态：保留。

### Repair

Repair 指对几何、状态、测量 bounds、rounding、derived flag 等进行可控修复。

新版状态：保留。

易混点：这里的 repair 是生成器修复动作，不是建筑修缮事实。

### Fallback

Fallback 指当 projection 无法稳定匹配或 sidecar 派生失败时，输出 unknown / not_applicable 等状态。（2026-05-09 废止 `sidecar_missing`——sidecar 由 worldgen 同时生成，不存在缺失态；详见 spec 09 §1.2/§6）

新版状态：保留。

### Unknown Reason Code（权威迁出 W2）

Unknown Reason Code 是 projection unknown 的原因码，例如 no_known_family_match、unsupported_material_system、multi_family_conflict、binding_registry_gap 等。

新版状态：保留。

常见值：

| code | 含义 |
| --- | --- |
| `no_known_family_match` | 没有 known family 适用 |
| `unsupported_material_system` | 材料/构件不被当前 binding 支持 |
| `unsupported_damage_pattern` | condition_class 无 binding |
| `multi_family_conflict` | 多 family 同组竞争无法解 |
| `projection_binding_incompatible` | required slots 存在但 unit/method 不兼容 |
| `sidecar_only_fact_pattern` | worldgen core 有事实但全属 sidecar-only 模式 |
| `coverage_unimplemented_domain` | 当前 projection registry 未覆盖该 domain |
| `binding_registry_gap` | registry schema 无法绑定 slot |

## 10.1 QA 与版本术语

### Schema Validation

Schema Validation 检查字段、类型、必填性、枚举、id pattern 是否合规。

新版状态：保留。

### Constraint Validation

Constraint Validation 检查 C001-C025 等硬约束是否通过。

新版状态：保留。

### Projection Regression

Projection Regression 检查同一 world / registry / projection config 在版本变化后是否仍输出预期 projection。

新版状态：保留。

### Physical Plausibility

Physical Plausibility 检查生成世界是否物理合理，例如材料、构件、缺陷、测量范围是否自洽。

新版状态：保留。

### SemVer / Compatibility Rule

SemVer 是 major/minor/patch 版本规则。a12 中 major 对应 breaking schema change、enum removal、primary key change；minor 对应 new enum value、new registry entry、new surrogate family；patch 对应 parameter default update 或 bugfix。

新版状态：保留。

### Current Implementation Gap

Current Implementation Gap 指当前整理稿记录的代码与规格差距，例如 registry 尚未成为生成输入、surrogate_id 未接驳、formula 未执行、原子表填充不均。

新版状态：保留为实施差距。

易混点：实现差距不是规格的一部分，但会影响落地计划。

### Alias Map

Alias Map 指 canonical a4 slot_id 与 a12 实现侧 slot_id 的映射表。例如 `ratio.covered_area.inspected` 与 `covered_area_ratio` 需要明确对应。

新版状态：需要新增工程产物。

### Migration Registry

Migration Registry 指迁移旧字段名、旧 slot_id、旧对象名到新版规格名的映射表。

新版状态：建议新增。

## 11. 常见混淆速查

| 容易混的词 | 正确区分 |
| --- | --- |
| NormativeProjection vs HiddenGold | 前者保留，是法规投影；后者删除，是隐藏答案副本 |
| MeasurementRecord vs ObservationState | 前者保留，是测量事实；后者删除，是观察题面 |
| canonical slot vs implementation slot_id | 前者来自 a4 法规事实需求；后者来自 a12 实现侧 measurement / projection 字段，需要 alias map |
| sidecar boundary vs sidecar truth | 边界保留；artifact/procedure/supervision truth 不由 W0 生成 |
| benchmark vs QA | 巡检员模拟题库 benchmark 删除；W0 生成器 QA 保留 |
| LatentDriver vs LatentCase | 前者保留，是物理驱动；后者删除/拆分，是旧 case 包装 |
| Repair action vs Repair outcome | 前者是约束修复动作；后者是建筑修缮派生事实 |
| unknown fallback vs agent unknown | 前者保留，是 projection 状态；后者删除，是调查员模拟认识状态 |
| Domain vs Cluster | Domain 是业务/资源域；cluster 若出现于 slot ownership，指 ownership 分组，不等于 §2 资源域 |
| Artifact requirement vs Evidence topology | 前者是法规要求的工件 slot，保留为 sidecar 边界；后者是观察/证据暴露设计，删除 |

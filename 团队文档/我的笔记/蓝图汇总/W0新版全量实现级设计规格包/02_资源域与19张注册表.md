### 1.1 派生风险域职责边界（2026-05-13 加，DEBT-030 D3 收口）

派生风险域 2 张注册表（`risk_derivation_registry` + `repair_outcome_registry`）**只覆盖综合派生类派生标志** — 即依赖多个业务核心层 + 多个测量 / 条件作输入做复合判定的标志。

按 a12 §13.2 派生标志全表（共 15 个，其中 1 个 `family_uncovered` 属法规映射层），W0 派生层 14 个标志分两类存放：

**A. 综合派生类（6 个）— 数据存放派生风险域注册表**

| 标志 | 所在注册表 | 依赖层 |
|---|---|---|
| `risk.building_safety.emergency` | `risk_derivation_registry` | 条件 + 测量 |
| `risk.public_health.emergency` | `risk_derivation_registry` | 排水核心 |
| `risk.public_danger.present` | `risk_derivation_registry` | 条件 + 消防/僭建 |
| `repair.required` | `repair_outcome_registry` | 条件 + 派生 |
| `repair.outcome.safe_until_next_cycle` | `repair_outcome_registry` | 修缮 + 技术测量 |
| `maintenance.pre_next_cycle.required` | `repair_outcome_registry` | 条件 + 风险 |

注册表实际条目清单详见 `11_registry_entries_inventory.md` §5.1 / §5.2。

**B. 业务核心层直通类（8 个）— 数据存放各业务核心层 State 字段 + 派生规则在规格 06 §11 派生标志表格描述**

| 标志 | 业务核心层 | 数据所在 State 字段 |
|---|---|---|
| `drainage.misconnection.present` | 排水核心 | `DrainageState.connection_state` |
| `ubw.present` | 僭建核心 | `UBWState.alteration_type` + `authorization_status_proxy` |
| `subdivided_unit_sign.present` | 僭建核心 | `UBWState.subdivided_unit_sign_present` |
| `fire_safety.deficiency.present` | 消防核心 | `FireSafetyState.deficiency_present` |
| `verification.test.failed` | 测量域 | 测试强度 / 比率 / 计数 vs 代理阈值（规格 06 §11 描述）|
| `assessment.fsp.below_required_safety` | 测量域 | `fsp_structural_performance_ratio` vs `fsp_floor_proxy`（规格 06 §11 描述）|
| `coverage.insufficient` | 测量域 | covered / inspected 比例 vs `coverage_floor_proxy`（规格 06 §11 描述）|
| `defect.cause_or_extent.uncertain` | 条件核心 | `ConditionState.uncertainty_flag` |

**为什么这样拆分**：a12 §13.2 表格的"依赖层"列已经隐含给出这条业务语义归属原则——综合派生类依赖多个核心层 + 派生层综合判定，业务直通类依赖单一业务核心层内部字段。两类标志最终都被法规映射层 projection executor 消费（按 `normative_projection_registry::required_world_core_slots` 字段引用），消费方相同，存放方式按业务语义分。

**派生标志全表 + 派生规则**见规格 06 §11；**法规消费契约**见规格 08 normative_projection 章节。

## 4. 关键依赖顺序

```text
building_template_registry
  -> component_type_registry + material_system_registry + location_class_registry
  -> fragment_template_registry + coverage_relation_registry
  -> latent_driver_registry
  -> mechanism_library_registry + defect_condition_taxonomy_registry
  -> technical_measurement_registry + sampling_plan_registry
  -> verification_test_registry + assessment_surrogate_registry
  -> risk_derivation_registry + repair_outcome_registry
  -> normative_projection_registry (法规映射层 projection binding)
  -> sidecar_ownership_registry join contract
  -> sidecar_measurement_registry (procedure / supervision / inspection_execution duration & interval / inspection-coverage / inspection-plan schema, used by projection executor for B 类 measurement slots)
  -> sidecar_bool_slot_registry (procedure / artifact / supervision bool + qualifier categorical slot generation schema, consumed by worldgen sidecar 派生层 _sample_sidecar_bool_slots_for_fragment)
```

该顺序来自 `a12` 的 registry 引用关系与跨层执行顺序：先 world core，再 condition / technical measurements，再 constraints，再 derived flags；最后由 法规映射层读取 `normative_projection_registry` 执行 projection。（来源：`01_a12_权威旧蓝图.md`:L572-L592、L1828-L1837）

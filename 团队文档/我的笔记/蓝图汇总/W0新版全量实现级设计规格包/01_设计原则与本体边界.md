# 设计原则与本体边界

## 1. W0 的定位

严格意义上，W0 是 `WorldGenerator` 的静态资源层，位于具体世界实例生成与运行时之前。当前整理稿把 W0 定位为 “Generation Resources”，负责先验分布、逻辑公式、registry 与机理库，是实现 rule-blind 与多样性入口的核心。（来源：`08_W0全量实现级设计文档_当前新版整理稿.md`:L5-L23）

新版 W0 的职责是定义以下资源和契约：

1. 读取 19 张 registry。
2. 定义 building / component / location / fragment / condition / measurement 等对象字段合约。
3. 定义 surrogate、formula、noise、unknown policy。
4. 定义物理 / 几何 / 测量 / projection 约束。
5. 定义 risk / repair / verification / assessment 派生规则。
6. 定义 `normative_projection_registry`、canonical slot 对齐和 projection fallback。
7. 定义 projection 可消费的 sidecar boundary 与 join marker。

使用 W0 资源后，会有两个后续参考流程：

1. **实例生成流程**：生成某栋具体建筑的 `WorldBundle`、`MeasurementRecord`、derived facts。
2. **法规映射层**：读取该 `WorldBundle`、measurement、derived facts、projection registry 和可选 sidecar join，产出 `NormativeProjection` 参考真值。

因此，`NormativeProjection` 是 法规映射层的参考真值输出，不是 W0 静态资源层本身的输出终点。

新版 W0 不做：

* inspector / investigator 模拟；
* observation / evidence 暴露计划；
* query episode；
* adjudication；
* HiddenGold；
* benchmark gold；
* runtime trace；
* skill evaluation。

删除依据来自用户原则。（来源：`09_用户原则说明.md`:L5-L8、L20-L25）

### 1.1 rule-blind 原则的操作判据与 B 类语义小口

新版 W0 总体守 rule-blind：worldgen **不读** `normative_projection_registry`，**不调** 法规 family / rule binding。这一约束对 worldgen core（A 类）和 worldgen sidecar 派生层（B 类）**同样生效**。

canonical slot universe 里有一类 slot（如 `fire_safety.upgrade_outstanding`、所有 `procedure.*` / `supervision.*` / `artifact.*`），它们的语义描述的是**过去行政过程 / 历史合规状态**——"是否完成 RI appointment"、"是否提交 MBI 表"等。这类 slot 由 worldgen 的 sidecar 派生层生成（用建筑物理 state 做 conditional 采样输入 + sidecar 自家分布参数），写入独立的 `SidecarRuntimeBundle`，不进 `WorldBundle`。

因此按 **slot 语义所描述的对象** 分两类（**不是**生成路径分类——两类生成路径相同）：

| 类                                        | slot 语义                                                                                | rule-blind 处理                                                                            | ownership                                          | 例                                                                                                        |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **A 类：物理 / surrogate 派生事实** | slot 描述楼宇物理 / 几何 / 测量 / defect / risk 状态                                     | 严格 rule-blind：worldgen 任何路径不读 `normative_projection_registry`、不调法规 family  | worldgen core / derived layer →`WorldBundle`    | `defect.*`、`crack_width_mm`、`risk.*.emergency`、`repair.required`、`verification.test.failed` |
| **B 类：行政过程 / 历史合规事实**   | slot 描述行政程序节点 / 监管动作 / 文档提交 / actor 角色 / BD statutory order 等过去状态 | 同样严格 rule-blind：sidecar 派生层不读 `normative_projection_registry`、不调法规 family | worldgen sidecar 派生层 →`SidecarRuntimeBundle` | `fire_safety.upgrade_outstanding`、`procedure.*`、`supervision.*`、`artifact.*`                   |

边界（不可越线）：

1. worldgen core 与 sidecar 派生层任何路径**不得读** `normative_projection_registry`（A、B 同）；
2. worldgen core 与 sidecar 派生层任何路径**不得调** 法规 family / rule_ids（A、B 同）；
3. B 类 slot **不进** `WorldBundle`，写入独立的 `SidecarRuntimeBundle`，由 worldgen sidecar 派生层生成；不存在外部 SidecarInput / admin record 注入路径；
4. sidecar 派生层无法对某 slot 采样时（如对当前 fragment 不适用），输出 `not_applicable` / `unknown`；不伪造、不做中点 fallback、不直接 anchor 到 rule_card threshold；
5. canonical slot universe 「所有欄位的官方名冊」必须显式标 A / B，不允许"mixed"或含混。

判据是**语义性**的——看 slot 描述的是"楼宇物理状态"还是"行政过程状态"。**生成路径上 A / B 一致**——都用 building 物理 state + recommended_distribution 采样。例：`risk.building_safety.emergency` 描述楼宇风险物理判断（A 类），由 worldgen severity surrogate 派生；`procedure.ri.appointment.completed` 描述行政程序状态（B 类），由 sidecar 派生层按楼龄 / building condition 推条件概率采样。

#### 1.1.1 rule-blind 在分布校准上的精炼（2026-05-07 初稿 / 2026-05-08 二次精炼）

DEBT-025 长跑暴露问题：A 类 slot 的 surrogate 分布过于泛宽（如 `length.rendering.total_thickness` bounds `[0, 100]`mm），导致 release_batch threshold_regime 100% `far_below`、QA 信息量崩盘。2026-05-08 per-slot 诊断进一步发现 `_sample_value_for_slot` 用 `(lo + hi) / 2` 中点采样（DEBT-026），8/8 有 threshold 的 slot 单独看也是 1 bin 独占。

> **术语澄清（§1.1.1 内统一）**：本节"generator input" 指 **W0 generator 内部用的数据源**（distribution 参数 / threshold value / engineering basis 等），**不是**运行时（W2+ / evo-agent）调参 API。spec 09 §1.2 修订后 W0 已统一为静态派生路径，所有数据源都在静态 registry 内，不接收 runtime 输入。

##### 第一层精炼（2026-05-07，rule-blind 真意）

reframing 关键论证：法规"划定范围"≠"给具体数值"。**rule-blindness 真意是 thresh-value-blind**——禁止使用 rule_card threshold value 作为 generator input，但**允许使用工程现实分布作为 generator input**。

##### 第二层精炼（2026-05-08，user 提：两头约束对齐哲学）

W0 加的隐状态体系（`condition` / `mechanism` / `severity_index` / `driver` 等）目的是**物理约束**——让生成的 measurement 符合物理现实。但单靠物理约束不够：

- **物理约束只管"physically possible"**：批荡厚度物理上 0-100mm 都可能
- **法规约束才决定"informationally useful"**：让分布 typical 区间能跨 threshold = 20mm，让 5-bin QA 有信息量

**系统真正要的是物理约束（一头）+ 法规约束（另一头）的对齐**。光有物理约束 → mean=50 vs threshold=20 失衡；光照法规出题 → 失去物理多样性 + 数据隔离破坏。

**为什么这与 rule-blind 不冲突**：

W0 的隐式分布参数（`recommended_mean` / `recommended_sigma` / `recommended_distribution`）**不外泄给 evo-agent / W2+ runtime**——evo-agent 看到的是已采样具体数值，**不可反推**出"这个数值是按 threshold ± noise 采的"。

**判据从此前的"source 独立"改为"采样输出不可反推 threshold value"**：

| 旧判据（过严）                        | 新判据（精确）                       |
| ------------------------------------- | ------------------------------------ |
| source 是否独立于 rule_card threshold | 采样输出是否可反推出 threshold value |
| 看见 threshold = leak 嫌疑            | 隐式分布不外泄 = 不构成 leak         |
| Layer 2 必须忽略 rule_card            | Layer 2 允许法规辅助划定分布形状     |

操作上：calibration source 可以是"工程基础 + 法规阈值参考共同 inform 分布形状"——只要 ① 这部分参数留在 W0 内部不外泄 evo-agent，② 不是"照法规阈值出题"（即 mean = threshold ± noise 这种直接 anchor）。

##### 4 层区分（精炼后）

| 层次    | generator input                                                                |              是否合规              | 备注                                                                                  |
| ------- | ------------------------------------------------------------------------------ | :---------------------------------: | ------------------------------------------------------------------------------------- |
| Layer 1 | 仅 slot 存在 + 泛宽 bounds + 中点采样                                          | ⚠ 不违反 rule-blind 但分布无信息量 | DEBT-026 baseline，待退役                                                             |
| Layer 2 | 工程现实分布（typical range + shape + sigma），可参考 rule_card 辅助选工程基础 |               ✅ 推荐               | calibration source 写明工程基础 + 法规对齐说明                                        |
| Layer 3 | 真实 MBIS 检验数据集 empirical distribution                                    |              ✅ 视来源              | 长期目标                                                                              |
| Layer 4 | 任意无工程规范依据的公式 / 直接 anchor 在 rule_card threshold value            |               ❌ 禁止               | 严禁任何未经规范定义的拍脑袋参数或公式、以及基于 threshold 的反推（破坏物理约束语义） |

**关键差异**：Layer 2 vs Layer 4 的边界不是"看没看 threshold"，是"采样 mean/公式 站不站得住脚"。"站得住脚"意味着必须由工程基础推出（碰巧或有意识地与 threshold 对齐），Layer 4 则是毫无依据的拍脑袋，或者为了硬凑 threshold 而反推出来的造假值（比如 threshold ± epsilon）。

##### 操作落地

所有 measurement slot 的 bounds + sigma 校准必须在 spec 04 §17 / 06 §15 注释里声明 source，并附 distribution-threshold alignment 自检。允许形态：

- `source = engineering_judgment_xxx`
- `source = proagent_engineering_estimate_current_authority_round5_2026_05_10`

该 source token 表示当前封口 spec 的工程估值权威。后续若有实测校准，必须另起版本 token 显式覆盖；当前 token 不表示等待外部专家确认，也不构成 TODO / pending 状态。
- `source = engineering_basis_xxx; threshold_alignment_note = 法规阈值落在分布 ~85 percentile，对齐良好`

不允许形态：

- `source = derived_from_rule_card_threshold`
- `source = threshold ± epsilon`（即便注释为 noise）

详细执行计划见 DEBT-020 / DEBT-021 / DEBT-026 entry。

## 3. 四类 truth / boundary

### 3.1 World Truth

World truth 是 W0 生成的建筑 / 构件 / 缺陷 / 条件 / 状态真相。它包括：

* `BuildingContext`
* `ComponentNode`
* `LocationNode`
* `FragmentContext`
* `CoverageRelation`
* `DriverState`
* `MechanismState`
* `ConditionState`
* `DrainageState`
* `UBWState`
* `FireSafetyState`
* `RepairAssessmentState` 中的 derived world flags

`a12` 的 `WorldBundle` 已列出这些对象容器。（来源：`01_a12_权威旧蓝图.md`:L50-L89）

### 3.2 Measurement Truth

Measurement truth 是 W0 生成或派生的测量事实。新版必须支持：

1. geometry measurement：裂缝宽度、裂缝长度、剥落面积、露筋长度等；
2. coverage / sampling measurement：覆盖面积比例、外墙检查比例、簷篷检查点数、间隔等；
3. technical validation measurement：拉拔测试、厚度、修补深度、钢筋截面损失、氯化物含量等；
4. assessment measurement：FSP、芯样数量、芯样率等。

这些 measurement 在 `a12` 中通过 `MeasurementRecord.measurement_family` 与 slot contracts 定义；`a11` 也明确 measurement 必须从单一 defect-derived 扩成多分支 taxonomy。（来源：`01_a12_权威旧蓝图.md`:L413-L475；`03_a11_权威旧蓝图.md`:L346-L364）

### 3.3 Normative Truth

Normative truth 是 法规映射层用 `NormativeProjection` 对 world truth + measurement truth + qualifier 进行法规投影后得到的参考真值。法规只解释世界，不生成建筑 / 构件 / 缺陷 / 测量真相。（来源：`04_a9_权威旧蓝图.md`:L34-L85）

`NormativeProjection` 可包含：

* matched families；
* selected family；
* projection status；
* required slots；
* threshold evaluations；
* basis items；
* expected verdict；
* unknown reason code。

字段来源于 `a12` 的 projection 字段合约。（来源：`01_a12_权威旧蓝图.md`:L481-L538）

### 3.4 Sidecar Boundary

Sidecar boundary 把 artifact / procedure / supervision / actor 角色等 B 类 slot 隔离到独立桶 `SidecarRuntimeBundle`，不进 `WorldBundle`。**生成由 worldgen sidecar 派生层负责**——不依赖任何外部 admin record，使用建筑物理 state（楼龄 / defect / fire_safety_state 等）做 conditional 采样输入 + `sidecar_measurement_registry.recommended_distribution` 做随机分布。W0 还提供 ownership map、join keys、projection consume contract、派生异常时的 fallback 语义。（来源：`01_a12_权威旧蓝图.md`:L1894-L1936；`03_a11_权威旧蓝图.md`:L220-L240；用户口径 2026-05-09）

## 4. Rule-blind 原则

World truth 的主导者是独立 `WorldGenerator`，不是法规、trace、LLM。旧 `a9` 明确指出：建筑 / 构件 / 缺陷 / 测量 canonical truth、缺陷严重度与测量值本身不能由法规直接生成；法规定义“如何解释世界”，不定义“世界本身是什么”。（来源：`04_a9_权威旧蓝图.md`:L11-L14、L56-L85）

新版落实为：

```text
W0 worldgen core:
  生成 WorldBundle (A 类)；不读取 RuleSnapshot；不读 normative_projection_registry

W0 sidecar 派生层:
  生成 SidecarRuntimeBundle (B 类)；输入 = 建筑物理 state + sidecar_measurement_registry
  与 worldgen core 同守 rule-blind：不读 RuleSnapshot / normative_projection_registry
  不依赖任何外部 admin record / SidecarInput 注入

NormativeProjection (法规映射层):
  读取 WorldBundle + SidecarRuntimeBundle + measurement truth + qualifier + projection registry

Sidecar:
  与 WorldBundle 在 worldgen pipeline 同时生成；可被 projection join 消费；不改写 world truth
```

## 6. Time / event boundary

当前 W0 只生成 state snapshots，不建立事件链或时序引擎。时间字段只作为 scalar qualifiers 或 snapshot 输入，例如 `age_years`、`maintenance_deficit`，不生成 temporal reasoning engine。（来源：`01_a12_权威旧蓝图.md`:L1951-L1962）

# cursor grok 第三方评审:DEBT-065 v3 设计(2026-07-24)

> 真第三方 lens(非 ChatGPT 系),破 copilot/codex/PlusAI 同源盲区。**前台**跑得(后台无 TTY 挂死 24 分钟 0 输出)。

## 总判

**v3「单 bundle 编译式」方向对,应定稿;但 v3 正文仍缺三条契约,且与已落码的 v2.2 第一波并存——在补齐并正式废止运行时组装前,不宜再扩第一波接线。**

## 必须处理(四项)

### 1. 规格权威双轨(阻塞)
仓库同时存在 v2.2(第一波已进验证器/检索/灌库)与 v3(写明取代 v2.2,生成器已写,验证器仍走 v2.2)。**这不是小版本演进,是判据承载位置的换轨**;继续在 v2.2 路径打补丁 = 在已判定过重的机器上烧预算。
**决策**:立刻宣布"运行时权威 = v3";第一波运行时路径只作对照/影子、不扩功能,或明确冻结为可丢弃探针。**不可两轨并行当正式实现**。

### 2. 卡绑定时效在 v3 被掏空(高)
v2.2 用 `card_content_sha256`+修订号做条目级失效(改卡即失权);v3 卡清单只存 `authorized_target_leaf`,强校验只在**生成瞬间**做。生成后若卡改了、清单未重建,运行时仍可能按旧授权早退。PlusAI 原案是"授权嵌进已发布卡元数据",现行 v3 落成**旁路清单**,漂移面又回来了。
**须补契约(三选一写死)**:①清单条目钉卡内容摘要,加载时与当前卡包比对,失配→该卡当 null;②bundle 钉住整包卡内容摘要,失配→整路径禁用早退;③发布门禁强制"清单与卡包同提交原子重建",失败则拒发。**仅靠"记得重跑生成器"不够**。

### 3. Bundle 指针与"一跳运输"未定义(高)
v3 只说"只加载被指向的那一个",但未写死:**谁指向**(批配置/运行元数据/规则切片策略)?身份清单在世界生成目录、卡清单在法规目录——**多世界批如何选对 bundle**?断路时除"不早退"外,是否必须在运行元数据留**显式关闭原因**(否则静默全关,难与"故意保守"区分)?
**"去掉 KG 多跳" ≠ "无运输"**;编译式设计的正确性取决于这一跳的契约,此处空白会重演 P1-2,只是换载体。

### 4. 触发器级语义在 v3 正文缺席(中高)
§1.3 只写卡级谓词;§6 待办提"触发器共用 helper",但未重述 v2.2 §3.2 的硬约束(恒等于授权目标、仅 `bound=∅`、废止组件维楼级结构 NA、measure 触发器豁免)。第一波 `obligation_deriver` 已按 v2.2 接线,不写进 v3,换轨时会再次分叉三份实现(正是要消的问题)。

## 设计优点(它确认的)

病灶诊断准(问题在运行时组装与可模仿标记,不在叶×叶排斥本身);谓词够小、缺省安全;判定权与 blind 未破;发布五道门对准"单测伪造掩盖断路"——尤其真实 bundle 端到端对照 + 负向来源测试,这是 v2.2 缺的闭合件。

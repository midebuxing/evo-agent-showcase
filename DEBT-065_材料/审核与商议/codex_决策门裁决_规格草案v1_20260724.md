总裁决：**路线二继续，但草案 v1 暂不能定稿落第一波代码。** D1、D3 同意；D2、D6 有条件同意；D4 否决并改为正向授权；D5 数学账通过，但在 D4 改案后只能先作条件预测。

## 1. D1–D6 裁决

1. **D1：同意两波拆分。**

   第一波只改类型格、组件判据与重锚；第二波再动卡面、严格身份和派生索引。第二波会引起 catalog/hash 全变，草案已正确识别，见 `spec草案_DEBT065类型格与授权状态轴_20260724.md:90-94,119`。

2. **D2：同意“单一 JSON、不要 W0 RegistryTable 双写”，但须改两点。**

   - 类型格应是共享上游本体的单一数据源，放 regulations 包合理；这也符合 grok 的“共享本体，不是 W0 独权”，见 `grok_乙案裁决全文.txt:28-35`。
   - `component_category_members` 不能继续作为第二权威。草案把它收进 lattice 的 `subsumption`，但现文件仍有独立表 `projection_runtime_mapping_v1.json:104-109`，§5 只说裁掉 overlaps 腿，见草案 `:36,99`。应规定：类目派生也从 lattice.subsumption 读取，旧表删除或仅作由 lattice 机械生成的缓存并断言逐字一致。
   - 卡侧“精确目标授权”不要塞进类型格；另建版本化的规则解释资产，避免类型本体随卡片修订一起升版。

3. **D3：同意 v1 不做 `structural_member` 叶化。**

   当前映射明确把它塌成父类 `structural_component`，见 `projection_runtime_mapping_v1.json:50-61`；现在叶化会同时改变投影、绑定和量化口径。另须把草案 `:36` 的 `structural_component → cantilevered_canopy 待裁`从 v1 删除并明确延期，不能让定稿资产保留“待裁”。

4. **D4：异议，否决“默认精确目标 + 空例外表”。**

   这与第三条锁相反。第三条锁要求卡侧有**正向声明**；黑名单方案却把“未审过”解释成“已授权”。新卡、旧卡新增限定符或漏登记一张卡，都可直接产生未证成 NA。

   改案：

   - 默认不授权早退。
   - 建 `exact_fragment_target_authorizations_v1` 正向表，至少绑定 `rule_card_id + 卡内容/解释版本哈希 + target_types`；证据定位到 `slot_ref_id/condition_id`。
   - 卡级早退读取显式 `exact_fragment_target_types`，不得再把全卡所有 slot/trigger 限定符简单并集当目标类型。
   - 当前审读面并不失控：只读枚举为 **118 张卡、169 个叶值限定来源项**，不是 397 张全卡。

   现成反例是 signboard 卡：法规句说 signboard 面积触发外墙覆盖义务，见 `rule_cards.json:230-247`；`area.signboard.display` 却带 `component_type_key=external_wall`，见 `:275-283`，同卡还有真正的外墙作用域限定 `:302-313`。卡级黑名单无法区分“目标限定”与“跨组件证据限定”。

5. **D5：数字一致，但不同意现在写成无条件硬预测。**

   在“118 张叶值卡全部获精确目标授权、例外为空”的原量化假设下，数字完全一致：

   - 组件 NA：`10,602 - 6,605 + 535 = 4,532`
   - 总义务：`84,911 + 7,061 = 91,972`
   - 增幅：`7,061 / 84,911 = 8.3158%`

   对应上一轮原文 `codex_路线二量化_叶型分区可证占比_20260724.md:130-159`。其中 535 个恢复的 scope 早退替换了 2,541 条下游义务，故总义务减少量是 2,006，不是 535。

   D4 改为正向授权后，`4,532/91,972` 应标为**全授权条件预测**；授权表定稿后再重放生成硬验收值。磁盘基准 83,831 仍见 `baseline_v4_final_seed301/batch_summary.json:90-95`。

6. **D6：同意沿用 UBWState，不上提 ComponentNode；但第二波表示法未闭合。**

   `UBWState` 已有 `authorization_status_proxy`，见 `worldgen/models.py:150-158`，生成三值见 `worldgen/generator.py:1150-1175`，所以无需污染 `ComponentNode`。

   但“给词表加 `authorization_status_key`，再机械替换 21 处 qualifier”目前不可执行：

   - `authorization_status_proxy` 现在是一个事实值，不是其他事实上的 qualifier，见 `fact_retriever.py:105-108`。
   - UBWState 挂在 Component，不带 fragment_id，见 `kg/queries.py:105-115`；现 enrich 的载体反查也不含 UBWState，见 `fact_retriever.py:503-516`。
   - 严格 DTO 明确只准八个限定符键；第九键会 hard-fail，见 `closure/source_dtos.py:58-90`。
   - 20 卡 21 处中含 §39C validated、报告记录等不同语义，不能一律机械映射为 `unauthorized_like`。

   推荐第二波优先把 `authorization_status_proxy` 建成独立 slot/value 条件；若坚持 qualifier 方案，必须另规格化 `UBWState.component_id → fragment` 的唯一投影及盖章规则。

## 3. §3.1/红线的反例结论

**目前四条件+七红线不逻辑完备，至少有四条绕过路径。**

1. **黑名单漏项反例。** 新卡只在证据槽带叶值 A，实际义务作用于 fragment B；未进例外表时四条件全部成立，A×B 显式 disjoint，于是整卡 NA。这里缺的是“精确目标”证明，而不是类型证明。

2. **伪单值身份反例。** 当前 enrich 只在事实尚无 `component_type_key` 时补值，已有值不覆盖，见 `fact_retriever.py:520-551`。而普通 SidecarEntry provenance 没有“结构身份”标记，见 `retrieval/pack_builder.py:229-268`。若结构别名缺失、但恰有一条普通非派生事实自带叶值，便可能被误认作原始身份。

3. **楼级触发器反例。** 草案 `:78` 声称“楼级永不早退”，但当前触发器代码用 building component 集合缺值直接 NA，见 `obligation_deriver.py:463-488`；现测试甚至明确钉了楼级 NA，见 `test_trigger_structural_na.py:50-59`。新 helper 必须要求 `scope_fid != None` 和单值 fragment identity，不能继续接 building set。

4. **卡级/触发器取值漂移。** 卡级把 slot-role 与 trigger 限定符取并集，见 `validator.py:1179-1196`；触发器则是 `trigger.qualifiers or map_qualifiers`，不是合并，见 `obligation_deriver.py:390-404`。此外 measure trigger 在结构检查之前已经返回，见 `:413-418`。所以“改 463-488 即两路径同判据”不成立。

fragment 路径本身的判断：

- 收官批只读复扫仍是 **120/120 fragment 非类目值唯一**，与冻结量化 `:66-75` 一致。
- 但若不剔类目，41/120 fragment 会同时带叶值与 `external_component`。实物例：原始 `external_wall` 行在该批 fact pack `:15636-15649`，类目复制行在 `:20166-20181`。
- generator 的任选兜底不会破坏“实际组件身份”：它最终仍把选中的真实 ComponentNode 写入 `FragmentContext.component_id`，见 `generator.py:686-698,735-739`。但这证明了**模板不是权威**。回归测试必须构造“模板 A、兜底组件 B”，断言身份为 B。
- 最稳改法是 retriever 从 `Fragment.component_id → Component.component_type → 固定版本 alias` 一次生成带专用 provenance 的 `w0_component_identity`；validator 只读该通道，不扫描一般事实限定符。

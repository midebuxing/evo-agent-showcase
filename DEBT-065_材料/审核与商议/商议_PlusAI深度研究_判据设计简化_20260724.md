# PlusAI 深度研究:DEBT-065 判据设计简化商议(2026-07-24)

> PlusAI 会话"设计判据简化与漏洞分析",4 分钟研究、19k 字符,全文可回会话查。
> 证据分层(按我方要求严格区分):**项目事实**=我方提供的前提(它不独立验证);**工程判断**=基于公开文献——Saltzer & Schroeder 设计原则(economy of mechanism / fail-safe defaults / complete mediation)、W3C PROV(来源证明)、SLSA 构建来源、SemVer(数值版本优先级、已发布内容不可改)、Parnas 表格法(完备性/冲突可检)、组件集成与端到端测试。

## 结论一:v2.2 确实过重(高置信)

目标 runtime 判据其实**很窄**(授权卡单目标叶 × fragment 单可信叶身份 × 显式排斥对 → 早退,其余保守不早退),但 v2.2 用一堆分离的活动部件(类型格资产 + runtime 授权表 + 专用身份通道 + 三方版本冻结 + 卡指纹)去实现这个小判据。**三轮审计发现全在这些间接层,不在 leaf×leaf 排斥想法本身**——"证明义务很小但承载它的 runtime 机器很大"时,正会出现我们列的那种缺陷模式。

最尖锐的批评:当前设计花大量机制预算去**证明** runtime 值"真的来自 W0""真的是对的卡绑定",而不是让这些属性**结构上不可能出错**。来源证明标准(PROV/SLSA)视可信性为"产出与绑定方式"的属性,不是任意 actor 断言的字符串标签——**如果普通事实能在语法上模仿可信身份通道,那这个通道在保障意义上就不是来源证明通道**。

## 结论二:三候选评估(b、c 必须;a 定位要改)

| 候选 | 评估 | 理由 |
|---|---|---|
| a 离线烘焙全表 | 好,但**最强是作离线 oracle / 发布门禁产物**;生产服务路径视情形 | 决策表让条件/动作显式、可查完备性与冲突(Parnas);但"全 fragment × 全卡"生产表会 snapshot 特定 + 运维笨重,且把错误前移 ≠ 消除 |
| b 直接锚 W0 离线产物 | **强烈推荐** | 直击最大缺陷类(可伪造/被转发的身份):validator 应消费 W0 自己产出的产物/manifest,而非转发或重编码的标签 |
| c 范围缩小 | **必须(是安全条件不是偏好)** | fail-safe defaults 的教科书应用:不是单一已授权叶、不是单一可信 fragment 叶、不在显式排斥对 → 一律不早退 |

## 推荐设计:单 bundle 编译式适用性(生产用 b+c,a 作发布 oracle)

**一句话**:早退 NA 当且仅当——已发布卡带一个已授权义务目标叶 ∧ 该 fragment 的 W0 精确输出带一个可信物理叶身份 ∧ 二者在显式叶×叶排斥矩阵中;否则继续正常求值。

**只要三个可信输入**:
1. 固定叶排斥规格(5 物理叶 + 10 显式排斥对)。
2. 已发布卡 manifest:每卡**内嵌** `authorized_target_leaf ∈ {五叶} | null`(授权嵌进**不可变的已发布卡元数据**)。
3. W0 fragment 身份 manifest:每 fragment `physical_leaf_identity ∈ {五叶} | unknown`(**直接读 W0 自己的发布输出**)。

**由此消除**:独立 runtime 授权表、专用身份通道、runtime 卡指纹匹配器、三资产版本冻结——正是产生全部审计发现的耦合点。

**版本模型塌成一个精确 bundle manifest**:validator **不问"最新是什么"**,只加载被指定的那个精确版本(+digest)的发布 bundle;manifest 缺失/不符/未验证 → 该路径禁用早退。(SemVer:版本优先级是数值不是字典序,1.10.0 > 1.9.0;已发布内容不得修改。)

**"卡值≠授权目标"结构性变难**:runtime **不从自由文本卡值推断**授权叶;卡发布流程发布规范化、审核过的 `authorized_target_leaf`;runtime 只消费规范叶 ID(不消费 authoring 标签/别名/法律属性词表值),runtime 域保持小、避免语义漂移。

**全表的正确用法**:每个发布 bundle,从真实卡包 + 真实 W0 fragment manifest 生成全答案表,与最小 runtime 判据的输出**精确比对**,不一致则发布失败。

## 五道发布门禁(专门闭合"单测伪造掩盖"这一缺口)

1. **微小域穷尽语义检查**:早退只依赖 5 叶 + unknown/null + 显式排斥,可穷举抽象函数真值表,证明所有非授权/未知输入都回落"不早退"。
2. **真实发布数据端到端 oracle 比对**:在精确发布 bundle 上,离线全表 vs 生产 validator,要求**精确相等**(候选 a 最有价值之处)。
3. **负向来源证明测试**:故意注入"携带相同字符串值的普通事实"→ 必须被忽略;故意改运输字段名 / 删 bundle 成员 / 损坏 digest / 换 manifest → 唯一允许结果是保守回落。**直击伪造 + 断路两类**。
4. **精确版本测试(不是"最新可用")**:验证 validator 只加载被指向的 bundle;数值版本优先级正确;没有任何静默按字典序或包新近度选资产的路径。
5. **shadow 模式度量**(加强,它标为推断非标准要求):先并行计算简化判据、与当前保守路径比对,在真实 bundle 上记录与离线 oracle 的分歧——验证保住预期 NA 回收率而不扩大假 NA 面。

## 对 37.7% 的保留

该数字是我方提供的估计,PlusAI 不独立验证,建议在新发布门禁 oracle 下**重新测量**;设计本身应保持大致相同的回收包络(它明确标注这句是推断,非既证事实)。

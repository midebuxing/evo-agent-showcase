# 实验报告 EXP-001：分诊 skill —— 在闭包 open 家族里挑真 fail（精度 + 省轮 双度量）

- **日期**：2026-05-30
- **状态**：方案（结果待补）
- **模型**：sixthsense `deepseek-v4-flash-h`
- **定位**：skills-evo 受控概念验证的一环；自挖自填、作研究过程，不作论文头条。

---

## 0. 一句话

闭包对每栋楼标出 ~10 个 `open` 家族（高召回、低精度），其中真正 W2-fail 的只 1–2 个。本实验测：一个 skill 能否在这些 open 里**分诊出真 fail**，从而 ① 提精度 ② 省下推理期的核验轮数；并检验 LLM（带世界知识 / 学到的经验）在「没见过的楼型 / 稀疏」regime 下能否赢过纯统计量。

## 1. 背景与由来（怎么走到这一步）

- **早期 L1–L4c**（rule-blind 检索 + 闭包的鲁棒性/退化自愈系列，见 `agent_v1/experiments/mvp/skills_evo_poc_记录_20260529.md`）。经 3 种子方差检验的核心结论：**一次性 LLM 选 scope 高方差，反馈自纠把它稳成可靠**（L3 三种子稳 98=oracle）；条件化要 per-type 隔离反馈（L4c）。
- **反复撞到的边界**：信息同源时 **LLM ≈ 统计量**；LLM 只在统计量「数据饿」（分布漂移 / 稀疏 / 高维）时靠世界知识赢。喂原始数值 measure 反而更差（LLM 没阈值读不懂，那是闭包的口粮）。
- **摸数据发现闭包真实形态**：每栋 ~652 义务、**92% 是 `open`**（高召回低精度，非 bug）；open 大头是 `depends_on_open_trigger` 级联（75%）。**不可约根因每栋仅 ~17 项固定结构化合规槽位、跨楼并集不增长** → 完整信息能塞 prompt、**不必造工具**。`threshold` kind 仅占 3% 且值未填，所以信号不在数值阈值、在「缺证据/缺触发」完整性。
- **收拢**：分诊（open 里挑真 fail）= 之前讨论的「减轮 / 数值→语义翻译 / 世界知识 / 反馈」诸线的**共同载体**，不是替代它们。

## 2. 一个 skill，五个侧面（前面讨论的线，一个不落）

核心任务 = **分诊 open 家族**。其余侧面各归其位：

| 之前讨论的 | 在本实验里是什么 |
|---|---|
| 减轮 / 翻页 / 抄近路 | 分诊**买到的东西**：预测准 → 优先核验那几个 → 更少轮查到真 fail。分诊与省轮是同一 skill 两个视角。 |
| 数值→语义翻译 | 分诊的**输入处理**：把楼的原始事实读成「哪个家族高危」。阈值在**法规卡**里（义务里没阈值不影响）。 |
| LLM 独有信息 / 世界知识 | 分诊在**没见过/稀疏** regime 下 LLM 赢统计量的本钱。 |
| 鲁棒性 / 反馈自纠（L1–L4c）| 把分诊 skill **学稳**的办法（反馈、护栏、精英保留）。 |

## 3. 假设

- **H1（精度）**：skill 能把真 fail 在 open 集合里排到前面，精度显著高于「把所有 open 等同对待」。
- **H2（省轮）**：按 skill 优先级核验，比按检索秩序，更少轮查全所有真 fail。
- **H3（LLM 增量，诚实预期）**：在「没见过的楼型 / 稀疏训练」regime，LLM（+学到的经验）赢纯统计量；同分布大样本下二者打平——打平也如实记。

## 4. 任务与机制

- 闭包对一栋楼产出 open 家族集合 O（~10 个粗家族，**实测为 W2-fail 的超集、零遗漏**）。
- skill 输入：楼的**语义画像**（在场事实→语义 + 楼型）+（带技能时）学到的经验。
- skill 输出：对 O 的排序/打分（哪个最可能真 fail）。
- 度量：
  - **精度**：真 fail 在 O 里的排名 / precision@k。
  - **省轮**：按 skill 序核验 vs 按检索序，查全真 fail 所需轮数。

## 5. 对照（三方 + oracle）

| 配置 | 含义 |
|---|---|
| `statistic` | per-type 频率（哪个 open 家族通常真 fail），确定性、无 LLM = "跟大模型无关"基线 |
| `llm_noskill` | LLM 凭语义画像自己排，无学到的经验 |
| `llm_skill` | LLM + 学到的经验（事实条件化） |
| `oracle` | 暴力最优排序（天花板） |

成立判据：`llm_skill` 同时赢 `statistic`（自适应/知识 > 固定）和 `llm_noskill`（经验有用）。

## 6. 数据与 regime（关键）

- 数据：`release_batch_evo_v11_data_pool_20260527/gen_seed_42` W2 真值（**fail-only 投影**：只枚举 fail、不枚举 pass）+ `杂物箱/subset_500.json`。
- **regime**：测试放在**训练没见过的楼型**（让统计量数据饿）；可叠加稀疏训练。训练型 vs 测试型不相交。

## 7. 信号（数值→语义翻译，用上帝视角学）

- 喂 LLM 的是**语义画像**，不是原始 measure。
- 翻译用**训练上帝视角**学：训练时有 ① 法规卡（阈值 / `source_quote`）② fact pack（实测）③ W2 真值（标签）→ 学「measure 相对卡阈值 + 楼型 → 风险」。
- 完整不可约信息（~17 槽位/栋、跨楼不增长）**全量喂 prompt，不造工具**（已实测体量 ~0.5 KB/栋）。

## 8. 学法（鲁棒性 / 反馈）

- skill 用反馈自纠学（L3 已证全局反馈环跨种子稳）；条件化用 per-type 隔离（L4c）。
- 训练看真值天经地义；推理不看（blind 红线，见记忆 `feedback_train_vs_inference_blind_separation`）。

## 9. 成功标准（诚实）

- H1/H2：`llm_skill` 在测试楼型上精度/省轮显著优于「等同对待 open」的 base。
- H3：`llm_skill` > `statistic` 在没见过楼型上拉开差距；同分布打平也如实记。
- **必配方差检验（≥3 种子）**，单种子不下结论（教训：L2 单种子 98 实为 70/98/70）。
- 必配确定性基线 + blind 消融 + oracle 天花板（见记忆 `feedback_deterministic_baseline_control`）。

## 10. 已知风险 / 诚实声明

- **LLM ≈ 统计量是同分布默认结局**；本实验靠 regime（漂移/稀疏）逼出 LLM 增量，逼不出就如实写负结果。
- **W2 fail-only**：只知 fail 不知 pass，非 W2 家族当非违规处理。
- 受控合成数据、自挖自填，作研究过程、不作论文头条。
- 摸数据阶段子代理已修一个 W2 coarse 映射 bug（`projection_family` 本已 coarse，误套 `coarse_of()` 致重合假性归零），根因体量与重合结论为修正后、可信。

## 结果页

> 跑完追加：实际数字、方差、per-building/per-type 拆解、判据是否达成、诚实评估。

### Stage 1：数据骨架验证（2026-05-30，✓ 通过）
- 14 栋（4 训练型 + 3 测试型，各 2）：**14/14 O ⊇ W2-fail、零遗漏**；平均 |O|=9.9、|W2-fail|=1.0 → 分诊 = 从 ~10 个嫌疑里挑 1 个真 fail。
- 语义画像 14/14 可用（每栋 12 条 salient_facts）。
- **关键坑（影响 Stage 3 设计）**：O **近乎常量**（跨楼几乎同一组 ~10 家族、无区分度）→ 分诊信号几乎全在 salient_facts；而画像是**原始数值 measure** → **数值→语义翻译为必需**（否则重蹈 v2：原始 measure 直接喂 LLM 反而更差）。
- W2 fail-only、每栋 1 个 fail → precision@1 = 命中/否；省轮上限紧。
- 脚本：`杂物箱/exp001_stage1_harness.py`。

### Stage 2：统计量 + 随机基线（2026-05-30，✓ 完成，单种子）

分诊 = 从 ~10 个 open 家族里挑出唯一真 W2-fail。脚本 `杂物箱/exp001_stage2_statistic.py`，纯确定性。

| 配置 | precision@1 | 平均轮数 |
|---|---|---|
| 训练型·统计量 | 0.200 | 3.20 |
| 训练型·随机 | 0.101 | 5.47 |
| 测试型(没见过)·统计量 | **0.074** | 5.06 |
| 测试型(没见过)·随机 | 0.101 | 5.46 |

- **统计量在没见过的测试型上崩塌、甚至低于随机**（0.074 < 0.101）：全局频率把 `structural/repair` 排首，但测试型真 fail 在 `ubw/fire_safety`（全局稀有）→ 系统性误排。**这就是 LLM 世界知识该填的 gap。**
- 训练型统计量也只 0.200（仅略胜随机）——每楼型 fail 分布分散、无单一主因家族 → 标杆本身不高，LLM 在训练型也有空间。
- 样本：学频率 训练型 evolve_train 各 ~20 栋（共 80）；评测 训练型留出 n=30 / 测试型没见过 n=54。随机用闭式期望（可复现）。
- ⏳ **单种子（gen_seed_42），未做方差**——方向明确（测试型退化跌破随机），正式结论前需补多种子（§9）。

### Stage 3：LLM 世界知识分诊（typeonly，3 种子，✗ 负结果）

没见过测试型 n=21 ×3 种子。脚本 `杂物箱/exp001_stage3_llm_typeonly.py`。

| 配置 | P@1 | 平均轮 |
|---|---|---|
| random | 0.101 | 5.48 |
| statistic | 0.048 | 5.81 |
| **llm_typeonly（3种子均）** | **0.095** [0.095,0.095] | 5.60 |

- **负结果**：llm_typeonly ≈ random（0.095 vs 0.101），未稳定超统计量、未拉开。3 种子极稳（都 0.095）。
- **诊断（关键）**：LLM **几乎给每栋都挑 `external_components`**——连名字直含 ubw 的 UBW-PRONE 都没挑 ubw → 根本没调用"楼型→家族"世界知识。疑似 **elicitation 问题**：O 是无释义 coarse 家族 ID + framing 是"哪个 open 是真 fail"，而非 L2 里 work 过的"这类楼特征性弱在哪"。
- TONG-LAU 看似略好（llm 0.286 > stat 0.143），实为"恒挑 external_components 碰巧命中"（TONG 常 fail external_components），非知识。
- **下一步 Stage 3b**：改 elicitation（家族加中文释义 + L2 式 per-type"特征性违规家族"排序），诊断是 elicitation 还是 LLM 真做不到。
- 数据：`exp001_stage3_llm_typeonly.json`。

### Stage 3b：改 elicitation（家族释义 + per-type 排序，3 种子）—— 部分正面

没见过测试型 n=21 ×3 种子。脚本 `杂物箱/exp001_stage3b_pertype_ranking.py`。

| 配置 | P@1 | 平均轮 |
|---|---|---|
| random | 0.101 | 5.48 |
| statistic | 0.048 | 5.81 |
| **llm_pertype（释义+排序框架）** | **0.190** [0.190,0.190] | 4.30 |
| type-only oracle（每型选模态 fail）| **0.571** | — |

- **确认 Stage 3 负结果 = elicitation 问题**：加中文释义 + "这类楼特征性弱在哪"排序后，LLM 从 ≈random(0.095) 升到 **0.190**（3 种子全 0.19，稳），稳超统计量 0.048 与随机 0.101、省 ~1.5 轮。世界知识在，之前没问对。
- **但 LLM 的 type-prior 粗且 miscalibrated**：三个测试型**都把 ubw 排第 1**（泛化"老楼→僭建"）。真值却是 LEGACY-WALKUP fire×6/ubw×1（应 fire#1，它排 fire#5）、UBW-PRONE fire×4/ubw×3（fire 比 ubw 还多）、TONG-LAU 以 external_components/gate 为主。**方向对（赢崩掉的统计量）、校准偏**——这些老楼其实更常 fail 在消防。
- type-only 天花板仅 **0.571**，LLM 0.19 只吃到 ~1/3。
- **深层洞察（指向下一步）**：纯改问法**修不了错的先验**（LLM 先验"老→ubw" vs 现实"老→fire"）；只有**数据/反馈**能纠 → 正好接 L3：给几条审计样本让 LLM 自纠先验（skills-evo 闭环）。
- 数据：`exp001_stage3b_pertype_ranking.json`。

### Stage 3c：反馈自纠先验（K=3，held-out n=36，3 种子）—— 关键边界结果

| 配置 | P@1 | 平均轮 |
|---|---|---|
| statistic_feedback (K=3) | 0.444 | 2.50 |
| **llm_feedback (3种子均, K=3)** | **0.444** [0.444,0.444] | 2.41 |
| （参照）llm 无反馈 (3b) | 0.190 | 4.30 |
| （参照）statistic 无反馈 (3b) | 0.048 | 5.81 |
| type-only 天花板 | 0.571 | — |

- **反馈大幅纠错**：llm 0.190→0.444（+0.254）、statistic 0.048→**0.444**（+0.40）。K=3 审计实例就把 miscalibrated"老→ubw"先验纠了大半（离天花板 0.571 还差 0.127）。
- **但有反馈后 LLM 先验 washout**：llm_feedback (0.444) **= statistic_feedback (0.444)**，+0.000。给够几条实例后，世界知识先验**不再有额外增益**——傻瓜模态计数器追平。
- 冒烟早期信号印证：LLM 看实例后部分更新（fire 升第 2）但强先验抗拒翻首位；statistic 直接翻向模态；净结果打平。
- 数据：`exp001_stage3c_feedback.json`。

### ★ EXP-001 核心结论（浮现，待 Stage 4 K-sweep 定量）

> **LLM/skills-evo 的价值在冷启动 / 数据饿那一刻**：没见过的楼型 + 零审计时，LLM 世界知识（P@1=0.19）远胜被外推统计量误导的基线（0.048＜随机 0.101）；**但一旦攒下哪怕 K=3 条审计，简单频率计数器就追平（0.444=0.444）——数据冲掉先验。**

与全项目反复出现的边界严丝合缝：同源/有数据 → LLM ≈ 统计量；数据饿 → 世界知识赢。诚实定位：skills-evo 是**冷启动/迁移到新场景**时的价值，不是稳态大样本下的"更强估计器"。

### Stage 4：样本效率曲线（K-sweep，固定 held-out n=36，3 种子）

| K | llm_feedback P@1 | statistic_feedback P@1 | llm−stat | llm轮 | stat轮 |
|---|---|---|---|---|---|
| 0 | **0.306** | 0.000 | **+0.306** | 3.77 | 6.19 |
| 1 | 0.389 | 0.444 | −0.056 | 3.37 | 4.22 |
| 2 | 0.389 | 0.444 | −0.056 | 3.05 | 3.31 |
| 3 | 0.389 | 0.389 | +0.000 | 2.54 | 2.58 |
| 5 | 0.389 | 0.444 | −0.056 | 2.33 | 2.39 |

（random 0.101；type-only 天花板 0.571）

- **K=0 冷启动：llm 0.306 >> statistic 0.000（+0.306）**。零审计时统计量无信息（默认排 `coverage_and_preinspection`、从不命中→0.000），LLM 世界知识给出 0.306 → **冷启动 LLM 决定性领先**。
- **K≥1：统计量追平/略胜**（0.444 vs llm 0.389）。一拿到审计数据，傻瓜模态计数器就 ≥ LLM。
- **LLM 对 K 几乎平（恒 0.389）**：强先验"老→ubw"压过 K 条实例（fire 升第 2 但 ubw 不让首位），**几乎不随审计量改善**；统计量却干净地跟着审计模态走。**"从经验学习"反而是计数器做得更好。**
- crossover_K=3（实为统计量在 LEGACY 审计模态 K=3 短暂翻 ubw 的 dip 造成的瞬时打平；总体 K≥1 统计量 ≥ LLM）。
- 数据：`exp001_stage4_ksweep.json`。

## ★★ EXP-001 总结（收口，2026-05-30 夜）

**结论：LLM/skills-evo 的价值窄而真——只在绝对冷启动（零审计 + 没见过的楼型）。**

- **冷启动（K=0）= 真价值**：统计量从训练型外推到没见过型时**主动误导**（Stage 2 崩到 0.048<随机；零数据退化到 0.000 无信息）；LLM 世界知识给有用先验（0.19–0.31）。**skills-evo 立得住的价值 = 冷启动 / 迁移到新场景时避免坏的初始决策。**
- **一旦有数据（K≥1）= 计数器赢**：傻瓜模态计数器追平/略胜（0.444 vs 0.389）；**且 LLM 强先验反成累赘——几乎不从审计更新（flat），计数器干净地学**。
- **与全项目规律严丝合缝**：同源/有数据 → LLM ≈ 或 ＜ 统计量；数据饿/冷启动 → 世界知识赢。
- **诚实 caveat（→ EXP-002 诊断）**：LLM flat 可能部分是反馈纳入方式（"常识+实例结合"让它过度偏先验）；更强的"以审计为准"框架也许让它更新——但计数器已近数据天花板，上限有限。
- 设定：受控合成数据、fail-only W2、type-only 天花板 0.571（within-type 需 per-building 信号，Stage1 警示薄）；LLM 侧 3 种子方差全稳。

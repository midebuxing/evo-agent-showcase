- **日期**：2026-05-30
- **状态**：方案（结果待补）
- **模型**：sixthsense `deepseek-v4-flash-h`
- **定位**：EXP-007 翻车后的**正确重定**。回到 EXP-001 多维框架 + 满血版真实形态（带工具箱的自主 agent）。

## 0. 一句话

agent 是**带工具箱的自主 ReAct agent**（可选调用：读建筑信息 / 读法规原文 / 读法规卡 / 跑闭包 …），目标是**做尽量完整的闭包核验**（**不判违规**）。skills（冷启动世界知识先验）优化它「调哪些工具 / 核验哪些家族」的决策，更高效 / 更完整地核验。**W2（完整闭包结果的参考真值）只在事后评测看，推理全程不碰。**

## 1. 由来：EXP-007 的根错与纠正（用户拍正）

EXP-007「活探索版翻页省轮」三处**根错**，全部作废：

1. **把 `W2-fail` 当成「agent 要找的违规」** → 错。**agent 不判违规**，它多轮做的是「尽量完整的闭包核验」；**W2 是「完整闭包结果」的参考真值**，不是「是否违规」的标签。
2. **detection 偷看 W2**（`det = f in fail_present`，推理时用 W2 真值当「查中没中」）→ 违反 blind 红线（推理 blind、真值只学习/评测看）。探针实证：blind 下闭包对真 fail 家族 **9/9 判 `unknown`、`violated`=0**，所以「翻页找违规」本就是伪命题，能跑出数只因偷喂了 W2。
3. **把「检索法规原文」写成固定步骤** → 错。读建筑信息 / 法规原文 / 法规卡是 **agent 工具箱里可选的工具调用**，自主 ReAct 决定调哪个、何时调。

纠正后回到 **EXP-001 多维框架**（精度 / 召回 / 效率 / 世界知识 / 反馈自纠），不死磕「省轮」。

## 2. agent（evo 探索版）= LLM + 工具箱 + 自主调用

- **形态**：跟满血版一致（LLM + function calling + 工具箱）。区别只在：探索版是我们做 skills 实验的版本；**满血版固定不动、作参照**（不混用）。
- **工具箱**（实现时照满血版已有的来对接）：
  - 读建筑信息（fact：这栋楼的实测 measure）
  - 读法规卡（conditions / threshold / measure 判据）
  - 读法规原文（source_quote）
  - 跑闭包（对某家族子集求 obligation 状态：closed / open / 缺啥）
  - 看当前还有哪些 open 家族
- **自主 ReAct**：思考 → 选工具 → 看结果 → 再思考 → … → 把闭包推到尽量完整 / 预算用尽。

## 3. skills 怎么插

- **skills = 冷启动世界知识先验**（夜间 EXP-001~005 验证过的强框架先验）：面对楼型，告诉 agent「这类楼**重点核验哪些家族 / 先读哪些卡 / 先查哪些建筑事实**」。
- **注入点 = agent 的工具调用决策**（优先级、顺序），不是写死步骤。
- **价值**：少走冤枉的工具调用 → 更高效 / 更完整地把闭包核验做出来。

## 4. 度量（EXP-001 多维，blind，W2 只事后评）

挑能拉开、有意义的维度（符合 evo 宽泛定义即可，不限省轮）：

- **完整性 / 覆盖**：agent 核验后，闭包完整度（推进到判定的家族数）/ 覆盖 W2 完整真值里该核验家族的比例。
- **效率**：达到某完整性所需的工具调用次数 / 轮数。
- **正确性**：agent 核验结果与 W2 完整闭包参考真值的匹配度。

## 5. 对照（三方 + 冷启动 regime）

- **满血版**（固定，参照基准，不动）。
- **evo 探索版 + skills**（冷启动世界知识先验）。
- **evo 探索版 无 skills**（LLM 裸调工具，无先验）。
- **确定性基线**（统计量 / 检索秩决定工具调用顺序，无 LLM = 跟大模型无关）。
- **冷启动 regime**：测试放在没见过的楼型（让统计量数据饿、逼出世界知识价值），对齐夜间 EXP-001。

## 6. blind 红线（这次死守）

- 推理时 agent 只用工具读**建筑信息 / 法规卡 / 法规原文 / 闭包输出**，**绝不碰 W2**。
- W2 只在事后评测 / 学习总结看。
- EXP-007 那个「偷看 W2 当 detection」已彻底删除。

## 7. 待实测前提（我自己跑数据确认，不预设、不劳用户）

- **open 在工具调用下能闭合到什么程度**（决定「完整」上限）—— 探针已知当前 93% open。若大多是 world 数据缺口、补不了，则「完整性」度量改为「在可闭合范围内的覆盖 / 效率」。
- **满血版工具是否支持对家族子集核验**（决定 agent 能不能「翻页式」逐步核验）。
- 实现时先摸满血版的真实工具 / loop，对齐后再搭探索版。

## 8. 诚实声明

## 结果页（2026-05-30 夜）

> 实验从"翻页省轮"重定为「带工具箱 agent 做完整闭包核验 + skills-evo 学技能优化核验」。
> skill 的落点 = agent 多轮 `run_closure` 分批闭包时「优先核验哪些家族」的决策。下分 4 块。

### A. 件1：闭包阻碍的正确落点 = `run_closure` 分批（不是 `query_open`）

**问题**：旧实现把"闭包查询预算"加在 `query_open_obligations`（读取已算好的闭包结果），不影响 `closure_result` 的家族覆盖 → `family_recall` 恒 1.0、5 个 ablation variant 全同（skill 零作用）。

**修正**（`杂物箱/run_paired_real_pipeline.py` patch C，monkey-patch 不改 src）：闭包阻碍移到 `run_closure_verification`（分批闭包）。机制 = 首次算全量缓存（资源充足天花板，客观存在）→ skill 家族排序 → 每轮 `run_closure` 只推进一批家族、累积重建**只含已覆盖家族**的子集 `closure_result` → 限轮数预算（`EVO_CLOSURE_QUERY_BUDGET` 轮 × `EVO_CLOSURE_BATCH_FAMILIES` 家族/轮）。这落地了「agent 多轮自主翻页、一次不返回全部、靠中间结果决定查清哪些能闭包」。

**自检**（`杂物箱/selfcheck_paged_closure.py`，确定性不烧 token）：4 测 PASS。端到端（真 `family_crosswalk`）证 `family_recall` 响应"agent 预算内覆盖了哪些家族"——同预算下 skill 把 recall 从 0.0 拉到 1.0（覆盖到真值家族）。**闭包计算本身是确定性纯 Python（非瓶颈），全量算一次缓存；分批模拟的是 agent 的工具调用/确认覆盖预算（LLM 才是受限资源）。**

### B. 确定性 induction 闭环：训练→归纳→holdout 全确定性（不烧 token）

**数据真相**（`杂物箱/selfprobe_train_coverage.py` + `run_det_induction_loop.py`）：
- 全局 W2 truth = **7 个 coarse family**（`family_recall` 分母）。
- 每栋全判覆盖全部 7 truth coarse → **oracle 天花板 = 1.000**，结构性漏 = 0。
- budget=默认 fine 字典序前 N 个 → 只覆盖部分 coarse。**train 30/30 栋系统性漏掉 2 个高价值 coarse**：`investigation.gate_and_proposal` + `repair.external_structural_validation`（在 truth、但 fine 字典序靠后被预算挤掉）。

**induction v1 → 负结果**（照实记）：第一版"提前漏的 coarse 的全部 fine"，holdout skill = baseline = 0.714、random 0.762（skill 没用、random 还更高）。**诊断**：① 固定 budget 下"提前漏的 fine"零和（覆盖 A 挤掉 B）；② 锚点 fine 楼型特定（COASTAL 学的、holdout 其他楼型不产）；③ random > 字典序说明字典序是差基线。

**v2 修正 = coarse 级 set-cover**：skill 学"哪些 coarse 高价值（在 truth）" + 每 coarse 选 1 代表 fine（去冗余）。锚点用 **coarse 级（楼型无关）→ 泛化**。

**holdout 40 栋（5 楼型，跨 train 楼型）budget 曲线 `recall_budget` 均值**：

| budget | oracle | **skill** | baseline | random | skill−base |
|---|---|---|---|---|---|
| 3 | 1.000 | **0.429** | 0.286 | 0.381 | **+0.143** |
| 5 | 1.000 | **0.714** | 0.286 | 0.524 | **+0.429** |
| 7 | 1.000 | **1.000** | 0.571 | 0.667 | **+0.429** |
| 10 | 1.000 | **1.000** | 0.714 | 0.810 | **+0.286** |
| 13 | 1.000 | **1.000** | 0.857 | 0.952 | **+0.143** |

**skill 全 budget 领先 baseline（+0.14~+0.43）、全程 > random**——非"刚好 budget 够"。价值梯度清晰：预算紧但够 set-cover 时（budget 5-7）知识重分配价值最大。train 主 COASTAL/COMMERCIAL、holdout 含 INDUSTRIAL/INSTITUTIONAL/LEGACY 没见过的楼型 → **coarse 级锚点泛化成立**。呼应记忆「LLM 真赢在预算约束下靠知识重分配」。

**诚实标注**：这是确定性 skill 排序的**机械效果（价值下界）**，非 LLM 在环智能。anchor = 全 7 truth coarse（W2 `matched_families` 全局固定 7 类，不分楼型）→ skill 学的是"这 7 类检查高价值"的领域知识 + set-cover 去冗余，归纳难度不高（近乎常量）。学习阶段对照 W2 是监督学习常识（防 leak 落点是推理 blind + artifact 输出，不是屏蔽 trainer 输入）。

### C. 接件1：真 agent 路径的 coarse set-cover

`_order_families_skill_aware`（patch C）从"skill fine 简单提前"改为 **coarse 级 set-cover**：skill `scope.rule_families`（fine）经 crosswalk 映射 anchor_coarse，每 anchor coarse 选 1 代表 fine 提前（去冗余）。无 skill/crosswalk 缺失 → 字典序（baseline 不变）。

**次归污染 bug 修**：anchor fine 用 `coarse_to_fine` 展开会带进次归成员（primary 落在 non-truth coarse 的 fine），件1 反推 anchor_coarse 时污染 → 改用 `fine_to_coarse`（primary 归属）筛，得 29 个干净 fine。自检 set-cover 测 A/D PASS。

### D. 真 LLM holdout（主 pipeline `--skip-phase1` + 件1 budget + induction anchor skill）

holdout 2 栋（COASTAL）× 5 ablation variant，budget=4 轮 × 2 fine，真 agent 自主多轮 `run_closure` 翻页 + set-cover skill 注入。20.1 min，10/10 ok。**aggregate 的 "completion +0.0000" 是假象**（completion≠family_recall；baseline `tool_calls=0` 只是 evo_mode=False 不记 trace）。下钻 per-case `family_recall`：

| variant | RC-10916 | RC-4711 | 均值 | vs baseline |
|---|---|---|---|---|
| baseline_static | 0.571（满 8）| 0.571（满 8）| 0.571 | — |
| **skill_only** | 0.286（浅 2）| **1.000（满 8）** | **0.643** | **+0.071** |
| trace_only | 0.571 | 0.286 | 0.429 | −0.143 |
| policy_only | 0.571 | 0.286 | 0.429 | −0.143 |
| full_evo | 0.286 | 0.286 | 0.286 | −0.286 |

括号 = `family_count`（闭包覆盖 fine 数 = 翻页深度 × batch2）。

**核心发现（诚实）**：
1. **真 agent 翻页深度（family_count 2 或 8）主导 recall，是真 agent 引入的混淆变量**——翻满 8 fine 才有意义，翻 1 轮（2 fine）必低。
2. **翻满时 set-cover 兑现确定性闭环承诺**：RC-4711 `skill_only` 翻满 → **1.0 vs baseline 0.571（+0.43）**，与确定性曲线 budget≈8 时 +0.43 吻合；`closed=2/na=2`（其余 variant 全 0）证 skill 让 agent 多确认了家族。
3. **翻浅时 skill 反低**：RC-10916 `skill_only` 只翻 1 轮（0.286 < baseline 0.571）——skill 引导"关键家族先覆盖"后，agent 可能提前 finalize（"更少轮达质量"的反面）。
4. **N=2 太小，方差淹没信号**；skill 均值 0.643 略高但不显著，trace/policy/full <baseline 是噪声。

**结论**：确定性闭环（固定翻满）set-cover 稳赢 +0.43；真 agent（自主翻页）"早停"噪声盖过 recall 优势。真 LLM 在环暴露的真实张力。

### E. 效率指标重新框定（用户拍板：符合 agent 自主精神）

承认真 agent 自主翻页/早停是真实行为 → skill 价值不是"强制翻满后的 recall"，而是**单位预算覆盖更多 truth coarse**（set-cover 去冗余）。`eff = 覆盖 truth coarse 数 / 消耗 fine 数`。该指标不受早停干扰（早停=小预算，小预算时 skill 更聚焦、eff 更高）。

**真 LLM holdout 效率**：
| variant | avg_eff | 翻满点（8 fine） |
|---|---|---|
| baseline_static | 0.500 | 8f→4c（字典序冗余）|
| **skill_only** | **0.938** | **8f→7c = 0.88**（vs baseline 0.50，**+75%**）|

**确定性 budget 曲线效率（固定翻满，金标准）**：

| budget | skill_eff | base_eff | skill_rc | base_rc |
|---|---|---|---|---|
| 3 | 1.000 | 0.667 | 0.429 | 0.286 |
| 5 | 1.000 | 0.400 | 0.714 | 0.286 |
| 7 | 1.000 | 0.571 | 1.000 | 0.571 |
| 10 | 0.700 | 0.500 | 1.000 | 0.714 |
| 13 | 0.538 | 0.461 | 1.000 | 0.857 |

- skill_eff 在 budget≤7 **恒 1.0**（每 fine 1 新 coarse，完美 set-cover）；baseline 仅 0.40~0.67（冗余）。
- **达 recall=1.0 所需预算：skill 7 fine vs baseline 外推 >16 fine → 预算效率 ≈ 2.3×。**

**诚实标注**：
- eff 在小预算 / agent 翻浅时**饱和**（2f→2c 无冗余空间，eff 都=1.0）——`full_evo` 那个 avg_eff=1.0 是两栋都翻浅的假象、非真高效。
- **确定性 budget 曲线（固定翻满）是金标准证据**；真 LLM 翻满点印证它，但受 agent 翻页噪声 + N=2 限制。
- **结论：skill 真价值 = 预算利用效率（set-cover 去冗余），符合"活探索版 agent 自主翻页"精神。**

### 全晚收束（2026-05-30，从压缩恢复一路到这）

A 件1 闭包阻碍正确落点 ✅ → B 确定性 induction 闭环（负结果诊断→set-cover 修正→跨楼型泛化）✅ → C 接件1 真 agent 路径 ✅ → D 真 LLM holdout（翻页深度主导、翻满兑现 +0.43）✅ → E 效率指标重框定（skill = 预算效率 2.3×）✅。**核心论点**：受限预算下，induction 学的 coarse 锚点 + set-cover 让 agent 用更少预算覆盖更多高价值家族（知识重分配，呼应 Scaling Law 延伸到运行阶段）。

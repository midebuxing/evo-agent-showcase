# 实验报告 EXP-002：反馈纳入方式 —— LLM 能否从审计数据更新（而非死抱先验）

- **日期**：2026-05-30（夜）
- **状态**：方案（结果待补）
- **模型**：sixthsense `deepseek-v4-flash-h`

## 由来
EXP-001 Stage 4 发现：`llm_feedback` 对审计量 K 几乎**恒 0.389**（强先验"老→ubw"压过 K 条审计实例，fire 只升第 2、不让首位），而傻瓜模态计数器随 K 干净更新、K≥1 时 ≥ LLM（0.444 vs 0.389）。**问题**：LLM 这个"不更新"是反馈纳入方式（提示词框架）问题，还是 LLM 本质不善于被少量反馈纠先验？

## 假设
换成**强"以审计数据为准、世界常识只用来补审计没覆盖的空"**的反馈框架后，LLM 能随 K 更新、K≥1 追平计数器、K=0 仍靠世界知识领先 → 成为**跨 K 的 Pareto-≥ 方案**（冷启动靠知识、有数据后追数据）。

## 设计
- 复用 EXP-001 Stage 4 的 K-sweep 骨架（固定 held-out n=36、audit 池互斥、K∈{0,1,2,3,5}、3 种子、测试型 disjoint）。**唯一变量 = llm 的反馈提示词框架**：
  - `llm_weak`（= EXP-001 的 llm_feedback，"常识+实例结合"）—— 参照。
  - `llm_strong`（本实验）—— "下面 K 条是这类楼的**已审计真实结果，以它们为准**；只有审计没覆盖到的家族才用常识补位/排序。"
- 对照：`statistic_feedback`（模态）、`llm_weak`、random 0.101、天花板 0.571。

## 成功标准（诚实）
- llm_strong 随 K **单调升** + K≥1 **≥ statistic** + K=0 **≥ 0.306（保住冷启动）** → LLM 是 Pareto 改进。
- 若 llm_strong 仍 flat / 仍 < 计数器 → 诚实记："计数器在有数据时足矣，LLM 不善于被少量反馈纠先验"（这本身是个有价值的负结论）。
- 必 3 种子方差；不硬凑赢。

## 结果页（2026-05-30 夜，✓ 完成）

固定 held-out n=36，3 种子。脚本 `杂物箱/exp002_strong_feedback.py`。

| K | llm_strong | llm_weak | statistic | str−stat | str−weak |
|---|---|---|---|---|---|
| 0 | 0.306 | 0.306 | 0.000 | **+0.306** | +0.000 |
| 1 | 0.444 | 0.389 | 0.444 | +0.000 | +0.056 |
| 2 | 0.380 [0.25~0.44] | 0.389 | 0.444 | −0.065 | −0.009 |
| 3 | 0.389 | 0.352 | 0.389 | +0.000 | +0.037 |
| 5 | 0.444 | 0.389 | 0.444 | +0.000 | +0.056 |

（random 0.101；type-only 天花板 0.571）。llm_strong 型首位：K=0 全 ubw（世界知识先验）；**K≥1 翻向审计模态**（UBW→fire、TONG→external、LEGACY→ubw）。

**结论：**
1. **"LLM 不更新"是问法问题、非本质**：强"以审计为准"框架后 llm_strong **随 K 更新**（首位 K=0 ubw → K≥1 翻向审计模态），不再 flat。EXP-001 的 flatness 归因于弱框架。
2. **llm_strong = Pareto-≥（两者之长）**：K=0 0.306（=世界知识，>>统计量 0.000）+ K≥1 ≈0.44（≈统计量、跟数据）。**一个 LLM 方法跨整个数据可得性谱都稳**——独家扛冷启动（统计量在此 0.000）、有数据后追平统计量。
3. **但有数据时不超过统计量**（K≥1 ≈ statistic，一处 K=2 因种子方差 dip 到 −0.065），无样本效率优势。本质 = "带世界知识冷启动先验的计数器"。
4. 强框架引入点种子方差（K=2 [0.25~0.44]），换来数据跟踪——弱框架的 flat-稳是抱死先验的副产物。

## ★★ EXP-001 + EXP-002 总故事（收口）

> **确定性计数器**：冷启动无用（0.000）、有数据好（≈0.44）。**LLM 世界知识**：冷启动好（0.306）、弱框架不更新。**强框架 LLM = 兼得两者（Pareto-≥）**：冷启动靠知识、有数据追平计数器。
>
> **实践建议**：用强框架 LLM——它在整个数据谱上稳健，**独家解决冷启动（计数器失效处），有数据后与计数器持平**。**skills-evo / LLM 的独特价值 = 冷启动 / 迁移到新场景的稳健性，不是有数据时的优越性。** 这与全项目反复出现的边界完全一致。

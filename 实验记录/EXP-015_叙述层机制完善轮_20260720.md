## 三层剥离:每修一层露出下一层

### 第一层:上下文静默截断(真根因)

- **病**:Ollama 默认 `num_ctx=4096`,**不看模型支持多大**,超出部分**静默截断对话前端**——系统提示词与 v3 提交契约正在那里。`llm_client` 只设 `temperature`/`num_predict`,从未设 `num_ctx`;注释却写着"qwen3.5 默认 32k context",系**误以为有 32k**。
- **证据**:收官批 138 次 LLM 轮次 `prompt_tokens` **最大值恰为 4096、零次超过**;9 栋兜底栋末轮全部恰为 4096。决定性对照实验:编号置于长文本开头再提问,不设 `num_ctx` 答"无"(开头被砍),设 16384 答对。
- **修**:`LLMConfig.num_ctx` 默认 16384(env 可覆盖),原生 `/api/chat` 与 OpenAI 兼容端点两条路都透传。
- **效果**:同栋 `prompt_tokens` 4096(卡死)→ 14332;**`llm_forced_finalize` True→False**(模型恢复自己调提交工具)——⚠️**2026-07-23 更正:此为单栋观察,不可外推**。G 批 20 栋实测 `forced_finalize` 仍有 18/20 为 True(即模型多数时候不调提交工具、改在正文里给围栏 JSON,由程序解析收档;两条提交路径经测试断言等价,信封与哈希一致)。不影响采纳(20/20 全采纳)、不违反五道门①(`tool_call` 3-4 次>0,工具确有真实调用),但**"模型恢复自己调提交工具"这一表述系以偏概全,已更正**;废跑从 A 批 2 栋降至 C/D 批合计 1 栋。

### 第二层:提交格式层摩擦

- **病**:`alias_duplicate`(同一别名列两遍)与 `alias_count`(单点挂 16 个,上限 8);格式修复预算仅 1 次,模型两次尝试都在收敛(5 错→3 错)却用尽预算。
- **修(不放宽闸)**:重复别名**确定性去重**(纯噪声、零语义损失,要求模型手工去重考不出分析质量);数量超限**仍拒绝**(拆点是模型该做的语义判断);顶层 `fix_hint` 由泛泛一句改为**点名具体 json_pointer + 该处修法**。
- **效果**:A 批格式层耗尽从 12 栋降至 **1 栋**。

### 第三层:内容闸 meta_commentary 误判(本轮核心,已验收)

- **病**:`shape2` 为纯共现——`_META_RULE_TERMS`(要求/提示词/规则/禁词/格式)与 `_META_COMPLIANCE_BEHAVIORS`(按/不使用/避免/只能)**任意共现**即判元评论。但"规则/要求"是合规正文必然出现的词、"按"只是普通介词 → **等于禁止模型引述法规内容**。
- **精确复现**:栋 `RC-0042` 第 4 次尝试交 **24 点、23 点合格**,仅第 4 点触发、**整篇退回**:
  > 完成报告提交状态为 false,违反 R4 规则要求修复工作须**按**《建筑物条例》标准执行,但 F1 显示报告未完成。
- **对照发现**:`shape1`(自指主语+输出行为)与 `shape3`(敏感词+元标记)**都有锚点**,唯独 `shape2` 没有——设计疏漏。

## 决策门:codex 驳回我的方案

我原提 **②加自指主语约束 + ③逐点剔除**,codex 商议后**两条都驳**:

- **驳②**:"没有自指就不是元评论"**在汉语里不成立**——"须按提示词格式输出""只能使用该格式""避免提及最终裁决"都无自指词却是真元评论,强加约束会**确定性漏检**无主语祈使句。
- **驳③**:权威规格**明文冻结**"任一点内容失败即整篇拒绝"(设计规格 v0.4 §3985 + 草案冻结条款),是刻意政策非实现便利。且指出我没想到的攻击面:**风险不是"大量好点稀释一个坏点",而是"通过选择性违规让关键内容被静默删掉"**——模型让关键结论点违规、无关点通过,程序删掉关键点后仍宣称"已接纳"。另有方法论理由:同时改误判源与失败处理政策,**无法判断采纳率改善来自分类器变准还是门槛放宽**。
- **也证伪了方案①**(仅删"按"):"应避免违反规则要求""设备只能使用符合规定格式的记录"仍会误伤。

**裁定第四条路**:把 `shape2` 从「领域高频词 + 泛动词」改为「**明确任务元语境 + 元行为**」,**保留整篇原子接纳**,提示词同步改但不代替闸。

## 叙述闸修复:落地与验收

**改法**:锚点改用 `提示词/系统指令/禁词/点列/信封/输出格式/任务规则` 等明确指向本次任务的词;`规则/要求/格式` 不再单独充当锚点;行为词补 `不要出现/不得写/不要提及` 一族;判定结论词(最终裁决/最终合规)作语境锚点。

⚠️**中途自捕两坑**:①敏感词整表纳入锚点 → 裸"合规"作子串**误伤**"符合规定格式";收窄为只取明确判定结论的长词。②词表定义顺序错致导入即崩。

**三关验收**:

| 关 | 标准 | 结果 |
|---|---|---|
| 冻结样例(codex 指定两组) | 漏检 0 且误伤 0 | **10/10 拦、8/8 过** ✅ |
| **A 批真实产物逐点差分**(96 点) | **只允许 meta 判定变、不得新增拦截** | 翻转 3 条**全为拒→过**;**过→拒 = 0** ✅ |
| 全量回归 | 零失败 | **2454 passed** ✅ |
| **扩样本单变量对照**(A vs C,20 栋新集合) | 独立于提示词仍生效 | **62%→95%** ✅,`meta` 拒绝码 C 批为 **0** |

翻转的 3 条(A 批)全是货真价实的合规分析(引规则号、引事实槽位、说清缺什么),三栋各一条,正好对应 A 批那 3 栋兜底。C 批(20 栋、旧提示词)`meta_commentary` 同样零命中,证明闸修复的效果**与提示词无关、独立成立**。

**回归锁口**:新增 `test_meta_commentary_needs_task_context_not_domain_words`,钉死"真元评论必拦(含无主语祈使)+ 正常合规分析必过"。

## 提示词配套:加了又撤(用户离场期间扩样本对照实证净负面)

### 曾经的改法

收官批错误码分布中 `alias_in_text` **31 次**为格式层最大项。诊断:提示词规则写得对但只有抽象陈述,样例里所有 text 都不提别名,模型看不到"正文提别名"该长什么样只能自推。**曾修**:规则改为可操作两句(含"程序会自动在报告里展开"一句)+ 样例加正例(text 提 R0 时 R0 也在 evidence_aliases)+ 加反例。B 批(新闸+新提示词,10 栋)数据看着不错:80% 采纳。

### 扩样本单变量对照,实证净负面 → 已撤回

用户离场期间按计划扩样本(新增 20 栋不重叠集合),设计 C/D 两批做**干净单变量对照**(C=新闸+旧提示词,D=新闸+新提示词,同一 20 栋):

| 批 | 提示词 | 采纳率 | 格式错误码 |
|---|---|---|---|
| **C**(20 栋) | 旧 | **95%**(18/19) | `alias_in_text`×8 |
| **D**(20 栋,同栋集) | 新 | **75%**(15/20) | `alias_count`×8、`alias_in_text`×13 |

**新提示词让同一批楼的采纳率从 95% 掉到 75%,两类格式错误都增多。** 这与 B 批(10 栋,含混淆变量)给人的"提示词有效"印象**相反**——B 批之所以看着好,是因为闸修复本身的效果(A→C 已证:62%→95%)掩盖了提示词的负面效果。B 批的"提示词有贡献"结论**已证伪、作废**。

**根因诊断**:C 批(旧提示词)在 20 栋里**零次**出现"多条相关义务打包成一点"的写法;D 批(新提示词)出现新行为——例如某栋点 12 写"多项义务(O17-O24)因 ambiguous_fact_binding 而 blocked…",**单点绑了 16 个别名**(8 个义务 + 8 个规则卡引用),远超上限 8,整篇退回。可疑触发句是我加的那句**"绑定关系由 evidence_aliases 表达,程序会自动在报告里展开"**——很可能被模型理解为"不必逐条写,系统会自动展开",从而倾向把多条义务打包概述、一次性绑定,而非按规则拆点。

**处置**:**已撤回该提示词改动**,`system_prompt.txt` 恢复到 C 批验证过的原始版本(`git diff` 为空,确认逐字节一致)。这是我自己未经审核添加、后被扩样本对照证伪的改动——按既有"自主推进期间小决策自决"授权自行撤回并如实记录,不等下一次交互。**闸修复(第三层核心)不受影响、原样保留**。

**全量审计**(20 栋各一审计员逐点跨语言比对条文↔释义;16/20 完成,4 栋撞会话额度上限失败):

| 逐栋严重数 | 0008:9、0032:8、0033:5、0019:5、0024:4、0028:4,另 3 栋干净(0005/0010/0029=0) |

**性质**:**绑定正确,释义错误**。审计逐点用义务哈希回查未闭合项表,别名→义务→规则卡绑定均对;渲染器忠实展开。错的是模型自撰的中文规则释义。失效模式非单一"错开一位",是四种叠加:①局部相邻偏移(R12 写 R13 内容);②罐头释义复用贴错别名("完成报告需含材料证书"整段复用、只在本讲材料证书的卡上巧合命中);③孤立幻觉(从 artifact 名反推规则);④照抄事实槽当规则内容。

**根因**(读 `report_writer.py:748-813` + `system_prompt.txt` 自查):证据包 `key_items` 每条义务只带 `rule_card_alias`(如 R3),规则**权威原文 `quote` 在单独 `rule_cards` 列表**靠别名交叉引用。模型手里有原文却不忠实引用、自撰释义并交叉引错 R。而这条原文在最终报告"法规辑录"节**已程序确定性渲染**——**模型的规则复述是冗余又易错的一步**。提示词只让写"实质分析",未要求也未禁止复述规则,模型为解释缺口自然去复述,遂出错。

**为何闸抓不到**:内容闸(`meta_commentary`/`forbidden_phrase`/`unresolved_alias`/`alias_in_text`)只校验别名存在性、状态不越权、格式,**不校验自然语言释义与所绑定规则的语义一致性**——这需要跨语言语义比对,现有确定性闸做不到。故"叙述采纳率 100%"**只证明格式与安全合规,不证明释义可信**。

**结论**:这是**收官阻断项**(正确性缺陷,非审美)。"叙述采纳 100%"的宣称必须附此限定。修复方向(codex 决策门建议,待落地):既然权威原文已在"法规辑录"确定性渲染,**最小修复=让模型不复述规则要求、只写缺口与复核动作,规则内容一律指向辑录里的 [Rn]**;若自由释义仍不可稳定验证,则程序展示原始短引文、模型只描述 gap。**不走提示词加正例老路**(EXP-015 C→D 已证提示词微调net negative且脆弱)。落地须先过 spec 授权(报告契约 v3 冻结),属下一步。

### 🔴 判定区分度根因下钻(2026-07-25;推翻两条既有归因)

### 决策门修正(codex gpt-5.6-sol,2026-07-25;否决两条、缩小工作面)

**路径 1 否决 —— 它不是最小改动,是取消 v3 的授权门。** 精确表述:该改法**把"卡值完整性"偷换成"卡值有权参与早退",而完整性不等于语义授权**。等价于把正向授权条件从"离线 manifest 明确授予该目标"降格为"runtime 看见卡里写了一个叶型字符串即可",与 v3 §1.3.1 明文硬约束("触发器限定值必须恒等于卡授权目标叶")冲突,也违背 W3C PROV-O / SLSA 的基本区分(值"长得对"不能替代授权与来源链)。

**一个更强的支配性论证**:卡级结构早退发生在触发器循环**之前**(`validator.py:1330`),而授权生成器强制卡内全部组件值恰等于单叶目标。故对任何**已授权**卡,触发器级组件早退被卡级早退**完全支配**——那 8,151 条**只能来自未授权/失效授权卡**。故 8,151 应**冻结为"待授权候选",不是既成可证量**。

**🔴 路径 2 的推导本身不成立(比"字段没消费"更前置的缺口)**:现有 `subsumption` 只表示 `members ⊆ parent`(这些叶是父类成员)。**由"所有已知 member 都与 drainage 排斥"推不出"parent 与 drainage 排斥"**——还需另证 `parent ⊆ union(members)`(父类恰等于这些叶的完备并集)。而映射注记明确 `signboard` / `parapet_wall` / `balcony_slab` 直接塌成 `external_component` 且**未进入 members**,部分归属还是低置信工程估。**所以"已加载但零消费"不是漏接线——现有 leaf-only 限制实际上就是安全边界**;那 1,232 / 20,039 条只能叫"封闭覆盖假设下的候选",不能叫已证明。正确改法二选一:①增加**有出处的** `closed_denotation`(明确父类等于哪些 W0 原子叶的完备并集);②直接登记"目标概念 × W0 物理叶身份"的显式排斥对,不借 partial subsumption 推导。且 `ubw` / `covered_component` 这类非物理轴值**不应经此路获得结构排斥权**。

**工作面大幅缩小(静态枚举,只读)**:397 张卡中——118 张组件值是**单一叶型**(55 已授权 + **63 张结构上可直接进入现有授权流程**)、80 张单一非叶型、199 张完全无组件限定、**多值卡 0**。而**未授权卡里实际含叶型 slot trigger 的只有 45 张卡 / 49 个触发器条目**。故最优工作包不是"审 342 张卡",而是:

> **45 卡 / 49 触发器定向裁定 → 能走现有卡级授权的先走 → 仅残余项才建触发器级证书。**

**若需触发器级证书**,关键修正是:**不能只把 `req_ct` 离线复制进 bundle**(那只是把未授权卡值洗进一个带 digest 的文件——绑定解决了,语义授权没解决),必须生成**独立的 `trigger_applicability_manifest`**,每条证书绑定 `rule_card_id + condition_id + slot_ref_id + predicate_kind` + 整卡摘要 + 编译器版本 + **授权依据**(专员裁定或已写入规格的语义不变量),并直接编译出 `excluded_fragment_leaf_identities`。runtime **不再读 `req_ct` 决定早退**,只做:bundle 有效 ∧ fragment scope ∧ 该 trigger 无事实绑定 ∧ 证书存在 ∧ W0 可信叶身份属于证书排斥集 → NA。生成期还须精确复现限定符优先级(`trigger.qualifiers` 非空取它、否则取 `map_qualifiers`,**禁止并集**)、measure trigger 不发证书、缺/重复引用/非叶/未知值/摘要漂移一律不授权。

**最大证明责任缺口(必须逐触发器裁定,不接受机械全授权)**:"`component_type_key` 出现在触发器事实过滤条件中"是否**必然**意味着"它是该触发器的适用对象"?规格没有这条规范语义,digest 和类型检查都证明不了它。

**对 0/113 的排序影响**:改变"区分度工程"的排序,但不推翻"义务级正确性"的排序——路径 1 的语义正确性收益(排水部位不再被外部结构卡毒化)仍值得先做。但若目标是恢复可判片段,**open 侧已成为前置门槛**:任何 blocked-only 路线,减少 8,151 / 20,039 / 乃至全部 46,812,当前边际收益都是 **0**。后续排序不再按"移动多少条义务",改按"**联合后新增多少可判 fragment、产生多少错误 verdict、扩大多少假 NA 面**"。

**⏳ 该下钻的未验证项**:①9,417 条(毒化池 23.9%)因 fragment 身份反解不到,归属未定;②20 对"真值 pass 但已持 violated"未定性,可能是真分歧、也可能是 `metrics.py:249-255` 已知的义务宇宙粒度伪影,**不应先按 agent 判错处理**;③110/3,765 组阅卷复现偏差(重跑 mapper 得 not_applicable 而落盘记 unknown)根因未查明。
